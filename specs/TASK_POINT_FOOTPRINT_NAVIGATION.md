# 双格任务点占地与寻路一致性

类别：官方实现修复（R02/R07）。依据：任务书 §4.2 的任务点阻挡移动、§4.6.2 的任务点2占两格；接口 §1.2 的 challengerTaskPoint2/defenderTaskPoint2 地图枚举。横向第二格以现有接口适配约定及 Issue46 已观测 `(16,17),(17,17)` / `(26,17),(27,17)` 为证据，不更改官方原文。

复现：frozen b1765d5、seed1、challenger 原录制 r12/r55，开拓者在 `(16,18)`，购物寻路重复提出 `(17,17)`，末端合法性校验将其过滤，导致任务也被购物占用而停滞。r12–55 连续44轮。

实施：保留原 payload 和 Turn.zones 的锚点表示，在 Turn 内建立公共观测导出的中立占地缓存供 land/blocked 与末端合法性校验共同使用。任务点2只提供单锚点时占锚点及右侧一格；同类型明确列出两格时只采用这两格，不扩第三格。未知中立枚举保持原占格，不推导额外大小。边缘不产生地图外占地。模拟器任务点锚点选择对明确横向两格保持左格，不受输入顺序影响。

不扩大可通行区域，不删除末端过滤，不改夜间建造规则、任务冷却、奖励或角色权限。无官方完整地图新增假设。

Turn 为每轮构造的 frozen 观测对象，仓库生产调用和测试没有原地改写其 zones 字典（本轮按赋值/update/pop/clear 检索）。占地在构造时缓存；原 payload 修改不影响已载入快照，dataclasses.replace(zones=...) 会重算。调用方不得绕过 frozen 约定原地修改内部字典。若同类型有多个不构成明确水平相邻两格的条目，视作异常/含混表示，对每个已报锚点保守保留右侧占地；不以此断言官方存在多个同名任务点。

验收：单锚点、显式两格（两种顺序）、地图边缘、未知类型、原输入不变、真实寻路和末端过滤一致；保留原 r12/r55 脱离 `_demo` 的公开快照及持久 PlannerState，真实 planner 必须发出可执行的移动且落点避开 `(16,17),(17,17)`，不得只 mock 占地 helper。只证明局部修复与本地兼容，不宣称内网 PASS。

局部验证：Python 3.11.10，新文件最终9项通过（0.121秒，exit 0）；相关任务/地图/协调/寻路11组147项通过（160.442秒，exit 0，该进程载入首版7项新用例，随后异常表示保守占地与replace两项另行验证）。`git diff --check` 通过。完整集成回归交由主线程在其他夜间改动完成、代码冻结后统一执行。
