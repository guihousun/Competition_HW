# Issue #49：工人无指令与夜间回防审计

状态：已修复本地策略缺口，等待新的完整回放和真实平台复测。

## 事实分层

Issue #49 的 578 回合录像标注为 `local=true`、`single-team-local`，因此可用于定位策略分配问题，不能作为官方引擎行为认证。

录像确认两类问题：

1. R177–R231，工人 10012 连续 54 个回合没有出现在 `commands`，位置停在 `(10,23)`；这是 planner 没有给它生成目标，不是执行器吞掉了每一回合命令。
2. 夜间只剩炮台攻击，工人在墙外卡住时没有紧急脱困动作。

`commands` 与 `executed` 的一回合延迟、R231 整轮 `executed=[]` 属于本地回放引擎/记录链路待核验项，本次不伪造官方结论。

## 实施

- 白天：当工人完成建墙、升级或交易分支后仍未获得命令，重新进入公开矿点选择，发出采集或朝矿点移动；两个工人的已声明矿点仍通过 `claimed` 分开协调。
- 夜间：连续三个同昼夜回合位置未变且目标仍为回基地的墙外工人，允许拆除一堵非正面保护墙，重新打开回基地路线；正面六堵墙仍受 `frontline.protected_walls` 保护。
- 拆墙动作依据任务书 `remove`：仅工人可用、目标需相邻；任务书没有把 `remove` 限制为白天，因此紧急夜间拆墙不改变官方协议。
