目标是在施工获得完整行动链的同时，不因我方可控的建墙/站位选择，把队友原本仍可完成的已派发行程变成超时或不可达。保护对象可以是墙、基地或武器的升级/维修行程，接口不绑定某种炮或某个天数。

**保护正在执行的承诺，不等于决定新购买总是优先。** 尚未派发的武器升级候选没有路线否决权；是否开始升级、施工、维修仍由当前策略和公开压力决定。本稿不引入“永远武器优先”“永远修墙优先”、固定111/121/132阵容、未来波次、种子分支或私有答案。

只在已知可见状态与明确我方候选动作下给出可行性检查。敌方动作、未知地形、矿点变化、动作失败、延迟或下一轮新威胁都可能使原证明失效，不能承诺实际永远按时完成。

## 3. 最小内部接口

先实现一个纯函数团队约束层，不重写总策略或引入第二套全队规划器。以下是建议结构；均为内部类型，不新增官方请求/响应字段。

```python
TripCommitment(
    owner_id, target_id, item, phase,       # to_shop / delivering / returning
    issued_round, last_observed_round,
    deadline_round,
)

TripCost(
    feasible, remaining_actions, slack,
    target_id, owner_id, reason,
)

ConstructionCandidate(
    owner_id, wall_pos, stand_pos, first_action,
    proposed_walls, remaining_actions,
)

evaluate_trip(turn, payload, commitment, occupancy_overlay) -> TripCost
check_team_route(turn, payload, fixed_commands, commitment, candidate) -> Decision
# Decision: allow / alternative_stand / defer + before/after costs + reason
```

`evaluate_trip` 复用现有购物/送券路径与动作计数，目标固定为传入承诺的 `target_id`，不通过“偷偷换一座更近的炮”使检查变成可行。`construction_trip` 在候选站位/每个施工前缀接受此约束检查；保留自己的取石、建墙、返炮位预算。不得只在墙已建后调用检查。

第一阶段只同时维护一个购物/送券承诺和一个施工归属，适合当前两工人结构。没有活动承诺时走原计划；不增加全图多角色长期搜索。一次规划内缓存同一地图/角色/障碍叠加的路径，有限候选超预算时明确延期，不能跳过检查默认放行。

### 承诺生命周期

1. 计算中的新候选只是 proposal。只有最终协调后真正输出了该角色对应动作，才登记“已派发”，避免被 `reconcile` 删除的命令仍持有所有权。
2. 下一轮读取实际位置、背包和目标等级确认进展。输出 `buy` 不等于券已入包；输出 `use` 不等于升级成功。失败或无回执不自动推进阶段，不依赖模拟器专用回执才能继续。
3. 已派发目标在仍可达、等级/物品适配、费用/截止有效时保持。路线和站位可按当前观测重算。目标消失、已被升级、死亡、换天、回合倒退/跳变、明显新威胁、预算已不足等情况进入显式重评/取消；记录原因，再允许既有策略选择替代目标。
4. “不可行”不能无限锁死工人。先检查能否移走我方阻塞者；仍不可行则取消当前承诺并重新决策。持有的物品继续属于真实背包，不删除、不退款、不当作已经用掉。
5. 新一天、比赛重置清理旧承诺；重复观测幂等。序列化按类型与数量限制校验，preview 使用独立副本。

### 施工归属应有让出边界

原施工 lease 不应仅因“当天曾开始施工”就把该工人排除出所有后续购物选择。正在完成的一段可行施工要保护，但在一个已确认完成的子目标边界重新比较团队候选；未开始的后续十墙计划不是十墙全做完前不可取消的合同。

本阶段不改变新任务价值函数：只解除无条件按天占人，向原候选排序暴露可交接工人及其真实库存/位置/剩余行程成本。已有购物承诺不重新抢人；没有购物承诺时允许原策略在安全边界选择更合适的工人。若换人会中断正在进行的合法关键动作或让施工者无法返防，应拒绝/延期交接并记录理由，而非指定某个角色ID。

## 4. 同轮施工与站位检查

协调顺序：确认旧承诺 → 生成各候选 → 联合检查候选对队友路线的影响 → 最终动作冲突协调 → 仅登记最终派发的意图。

对于每个施工候选，必须同时检查：

- 新墙落点作为新障碍；施工者进行 `build` 时仍占据原站位；有多个施工前缀时，每个前缀分别检查，不能只看最后“大家都回家”的图。
- 候选若需要先移动施工者，以该合法移动后的站位作为影子情景；下一轮仍重新验证，不能本轮同时移动并建墙，也不能借队友本轮将让开的格子输出移动。
- 固定动作的预留落点、当前角色/基地足迹、商店/矿点、双方任务点2的第二格等均为障碍。不能只保护一个目标邻格而忽略途中唯一通道。
- 使用相同时间切片比较“无此施工”的基准和“有此施工”的候选成本：均基于同一轮、同一队友动作、同一剩余截止预算，包含尚需购买、使用及既有返防要求的动作数。不能将r178的20步与r179的19步剩余混算。
- 基准仍可行、候选超预算/不通时，施工候选拒绝；候选仅增加路程但仍在原截止及既有安全余量内，可保留，增加的代价用于同类站位排序。已有安全余量不能被重复扣除或静默放宽。

当冲突来自施工者站位时，优先在同一墙的合法站位中比较：施工自己的预算、队友剩余预算、实际可达性、同轮冲突。可选择一个较远但同时保护两条行程的站位。没有这种站位时，考虑另一面可建墙或先合法让开；仍没有则延期该墙。不得为维持某座炮的路径随意拆墙或瞬移。

真实基地危急/夜间返防可撤销普通日间行程保护，由既有防守仲裁显式接管；这是按观测发生的紧急转换，不通过提前假定未来怪物来绕过约束。保护新建墙或更强火力哪一种更优仍是策略问题，本稿只防止未经评估的自我阻塞。
