# P3/P4 新闻推理与多日宝藏

状态：后续实施 Spec，依赖经审核的 P0b 调用/上下文底座。类别：策略优化 / 官方机制实现修复 / 本地测试工具。

规则依据：R01/R02/R06/R07；任务书 §4.8、§5.1、§5.2，接口 §1.6、§1.7、§2。不改官方原件或数值。

## 共同输入和记忆

只能从 worldNews.officialNews/folkLegends 和本队已收到的公开观测提取证据。按阵营/对局隔离主题上下文，原文哈希和首次观测回合去重。相同消息每天重发不滑动相对日期；如果缺少发布时间且首次观测可能已晚于发布，标记时间不确定，不假定首次看见就是当日发布。

每条约束保留 subject、field、value、来源哈希、原文证据片段、首次观测回合、observed/inferred、适用范围、冲突集合。坐标、数量、时间端点、否定条件不得只存在于自由文本摘要中。引用的哈希/原文片段必须确实存在；模型伪造 evidence ID 则拒绝结论。模型做推断仍标为 inferred，不能因为有引用就改标官方事实。

原始存储、结构化约束、工作上下文分别有工程容量上限。超上限必须记录缺口，保留可用真实 trace 引用，不能声称已存全文却只有摘要。发现冲突保留双方证据；无明确更正关系时不按最后一句覆盖。取消/更正具有独立事件记录。对失效资料允许不放入本次 prompt，但历史解释仍可追溯。禁止无证据把地图种子、隐藏祭坛、未来消息或标准答案写入记忆。

普通模型额度在队伍层共享3次/130轮；只在有新证据、能改变行动时提出请求。保留额度不足时的待办，继续现有经济、防守和合法任务行动；新闻和宝藏请求不冒充自进化请求。

## P3 新闻推理

模型受限输出 effects 数组，每项含 resource、availability、start_day/end_day/resume_day（允许null）、price_direction（up/down/unchanged/unknown）、price_amount（没有原文数值必须null）、evidence。拒绝未知资源、非法日期、区间矛盾和缺乏出处的量化价格。

推理结果仅形成经济建议：选择矿种/出售时机；成交价始终取当前 vendorShopList，既有预算与防守预留不变。公共消息可能不确定时采用保守建议，不直接修改观测、矿量、官方价格或制造新动作。

本地环境单独保存可配置的新闻事件及其影响，不依赖策略生成的解释来设标准答案。手工测试：今天第4天，明天停矿两天→第5/6天停产，第7天恢复；未给涨幅则unknown。覆盖重发、迟到、撤回、互相矛盾、不同资源、额度不足和当前价格与预测相反。明确哪些环境变化是本地题库设定。

## P4 多日宝藏

模型受限输出 constraint_patch，允许 site{x,y}、opens_at/closes_at、items多重集合、prerequisites和unknowns，每个字段有证据引用。不得将只知道区域强行变成精确坐标；未确定绝对回合的“黄昏”仍保留未知，等待有依据的时间转换。

保留每字段候选；只有坐标、时间和物品均充分确定且无冲突时，才交给行动规划。规划通过现有预算预留、背包容量、合法商店、寻路估计、角色互斥进行购买/移动/召唤。只买短缺部分，不因重复消息再次买齐全套。提交后等待公开反馈；不能读私有 opened 来判断成功；若没有充分反馈，记录 attempted/unknown 并有限退避，避免每轮重复耗材。

先修正现有本地召唤机制：当前代码按隐藏祭坛条件直接拒绝并保留所有物品，而且允许多余献祭物品；R07要求合法尝试按实际献祭消耗，即便条件不符而失败，且成功要求物品集合不多不少。动作合法性（身份/距离/实际持有）与能否召唤成功（地点/时间/精确集合）分开验证；未知条件不能被本地拒绝回执泄露。已核对接口文档 §1顶层 lastSummonTreasureResult 及 §2.2：0未探测/非法，1成功，2无宝藏或未开启，3物品集合错误，4宝藏已空；合法动作目标在开拓者周围一格且所献祭物品在背包内，所有合法尝试均耗材。接入这些公开回执，而非只输出本地事件文字。多种错误条件同时发生的结果优先级未明确时单独登记，不冒充官方。已有测试若保护旧行为须更正独立预期并标记旧报告。

手工三天线索：第一天地点，第二天物品，第三天时间。前三次公开观测只含已发布线索；Agent必须跨日保存前两条，第三条后再完成行动。覆盖重复物品数量、缺项、冲突、窗口错过、预算/容量不足、地形变化和两阵营。未来线索改变不得影响此前动作。对已收到长噪声文本插入关键否定/数字，压缩后保真检查，禁止删掉约束却仍召唤。
