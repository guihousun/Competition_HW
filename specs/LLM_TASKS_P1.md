# P1 多轮任务求解与模拟判题

状态：实施设计；P0b 共享路由正在独立实施，待审核接入。类别：官方实现修复 / 策略优化 / 本地测试工具。

依据：DEVELOPMENT_RULES R01/R07/R08；任务书 §五、§5.3、§六，接口 §1.7、§2.1。原始官方文件不修改。

## 必须完成的链路

公开 phaseTask 确认 → 保留原题和输出格式 → 模型选择下一操作 → 路由发出 prompt/executeCmd → 后续观测关联结果 → 解释成功/退出码/截断/错误 → 查询或计算 → 按题目原样格式提交 → 等待反馈 → 纠错或结束。只能使用已收到的公开证据，绝不能读取模拟器答案、未来数据、种子。

模型输出为可校验 JSON 计划，带本地关联 nonce，kind 为 command/answer/need_info/stop；不得直接提供任意角色指令。command 只能交给官方 executeCmd，不能在参赛 HTTP 进程或模拟器宿主 shell 执行。答案字符串不得用 split/join 重写内部换行、JSON、空格和单位。每次提示携带原题格式要求、相关原文、已执行命令及结果、当前错误、剩余回合；不索取隐藏思维链。

使用 P0b 通道和上下文，没有另一个计费器。重复无新证据操作、空值、非法 JSON、错 nonce、无响应、超长值均有有限退避；失败时正常防守仍运行。普通额度用完不阻止有效自进化任务；死亡、离开范围、任务结束后停止其工具操作。

## 首个已定位模拟器缺口

taskworld._advance_once 在任何 pending_answer 后都结算并结束，包括 0% 和部分正确，这使 Agent 无法纠错。修复为：

- 完全正确才立即完成；未完全正确公开 errorCode=2，保留题目和最高通过率，不立即发放金币/分数。
- 后续提交较差答案不覆盖最佳答案；到超时/离开/死亡才按最高通过率结算一次。超时回执 errorCode=1。
- 结算清空题目、任务数减一、冷却30轮；重复处理相同回合幂等。
- 字段级判分是本地 fixture 算法，不冒充所有官方题的评分标准；deadline 临界轮含义的既有差异单独保留。
- 用独立手写两字段标准答案验证 0%→50%→100%、50%→0%→超时、离开/死亡、双方身份、JSON传输和实际 simulator.step 路径。不得仅检查内部 helper。

## 模拟沙盒与题库验收

新增仅测试环境读取的虚拟文件/API fixture；通过明确的只读命令语法解释 cat/ls 和受限参数化查询/计算。不得 eval/exec/subprocess 模型文本；未支持命令返回非零退出码。支持可注入 timeout/truncated/judger_error，并保留官方结果外壳。fixture 的路径、记录数据、正确答案独立于 Agent 存储。

四组端到端问题：未知文档路径探索、参数化数据查询、运算与精度、错误后修正。至少两套不同路径/字段顺序/数据；两个阵营均验证。脚本模型只验证工程控制流，必须与真实模型正确率分开。真实模型同一冻结用例至少3次，失败不得用标准答案替换。

## 交付门槛

对每次发出和收到的操作记录 generation、来源摘要、阶段、回执类型；命令全文/原题需有有界存储和真实 trace 引用。前端展示探索/等待/验证/提交/失败以及额度，不把发出答案等同成功。

完整 unittest、diff check、双侧种子1/90317/90601代表性模拟；与冻结基线对比，报告任务分与基地生存。最终从审核后的源码构建参赛包，Python3.11.10 验证入口，整合固定 codex/sgh。无内网数据不宣称官方 PASS。
