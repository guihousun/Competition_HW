# 新闻与宝藏的原文记忆接入

变更类别：策略优化、Agent 内部架构与 UI 工具。依据 R01/R02/R06/R07，任务书 §4.8、§5.1、§5.2，接口 §1.7、§2。官方原文、每日普通 3 次额度、沙盒权限和召唤结算均不改动。

## 数据流

公开 `worldNews` → 分主题原文档案 → 有界 prompt / inspect → 引用核验与候选草稿 → 完整性和冲突检查 → 既有预算、背包、寻路和角色仲裁。

`inspect` 是内部读取已收到原文的计划，不发 `executeCmd`，不访问本机文件或外网。新闻和宝藏分开保存原文、草稿、检索位置及错误次数；普通调用仍在队伍层与其他消费者共享额度。只有实际发出的 prompt 才更新已发送范围，排队、调试预览和收到 inspect 请求不等于已发送。

实际模型出现的 `inspect+hypothesis/events`、`inspect.draft` 也按中间草稿处理；同一回复中的多个草稿必须完全一致，否则拒绝。请求超出单段上限时只返回 2000 字符，并通过未读位置继续分段；不将归一化当作完成全部读取。提示词的下一未读位置计入本次已附带片段，持久发送记录仍等实际回包确认。

## 记忆与引用

- 每主题最多保留 12 条来源，单条原文 131072 字符、总原文 196608 字符；超过限制记录截断/淘汰，不伪装全文可用。容量为工程选择，不是官方新增限制。
- 模型每次检索最多 2000 字符，工作草稿最多 5000 字符，整条 prompt 最多 12000 字符。每个来源版本最多 8 次实际分析调用，错误回复/超时另计、连续达到 2 次停止该版本重试；每日官方额度不因此增加。
- 来源 SHA 与首次观测回合去重。首个游戏日和实际观察到日界变更可以形成日期基准；后来才首次收到的消息保留未知发布日期。同一来源重发不滑动日期。
- 日期未知的相对新闻保留 `startDay/endDay=null`，不会据此禁止采矿。当前成交价始终读取 `vendorShopList`。
- 宝藏草稿保留 `site/items/window/prerequisite` 候选、原文引用、`assert/exclude` 极性和 `corrected/cancelled` 更正证据。已保留候选不能通过下一次回复省略它来删除。数量的重数保留，物品比较忽略排列次序。
- 候选仍是模型推断；引用检查只证明引文确实出现在实际发送的原文中，不能保证模型的语义推理正确。
- `unknowns` 区分地点、物品、时间、冲突、发布日期、未读原文和前置条件。只有来源已完整发送、地点和物品已核对且唯一缺项是时间，才允许已有策略受控备料。完整召唤还需通过既有行动约束。

## 序列化与页面

WorldAgent 使用 `competition-world-agent/2`；不信任缺少原文和发送范围的旧存档，显式降级。Planner 的 JudgeState 独立恢复，不把旧存档降级解释为刷新普通额度。页面显示原文保留量、已发送量、日期可信度、候选/排除/更正和未知项；原文查看器按任务/新闻/传闻隔离选项。

## 验证与未完成项

独立回归使用手写长传闻：首段给旧用品，中段排除另一个用品，尾段更正为两份指定用品。通过真实 planner/router 和 JSON 往返核对双方、共享额度、跨日继续、未读来源禁止备料、迟到新闻和旧状态降级。脚本回复仅验证工程链路，不算真实模型成功率或官方 PASS。

最终验收仍需要：真实模型的长世界资料重复试验；长传闻在可选模拟器场景中的完整行动与结果验证；新候选全套回归、留出地图/换边及实际参赛包检查。现有公开包继续保持此前版本，不将开发工作树自动标为交付版。

当前实验进展与失败见 [世界记忆验证记录](../reports/world-memory-integration/README.md)。可选长传闻场景已经接入，但红方完整行动回归仍有缺口，不能勾选最终验收。
