# 宝藏动作机制修复（P4基础，不是完整多日Agent）

类别：官方实现修复。依据 R01/R07、接口 §1顶层 lastSummonTreasureResult、§2.2 额外补充说明；任务书 §4.6.3、§5.2。

## 变更

- 0为未探测/非法，1成功，2无宝藏或未到时间，3物品集合错误，4宝藏已空；模拟器实际输出对应的公开字段。
- 非法目标或背包缺少实际献祭数量时不消耗。合法动作无论是否成功均消耗实际献祭的物品；错误/多余/不足的物品集合不能算成功。
- 按 targetPos 判断目标，修复之前忽略动作目标、把角色当前位置送入判定的问题。动作目标必须在开拓者周围一格，隐藏祭坛位置不能用来决定动作是否合法。
- 成功判定使用精确位置、时间窗口与物品多重集合；同轮两侧都满足条件可分别获得奖励，后续不重复奖励。
- 策略的 treasure_notes 只读公开传闻和当前队伍公开回执，不再从模拟器私有 rite 补坐标、物品或“已被打开”。结算不会把隐藏完整条件重新发布成民间传闻。
- 同一公开消息下改动隐藏坐标/物品/开启状态，策略读到的线索不变。此处修复信息泄漏，不以旧本地高分为理由保留捷径。

## 验证与保留差异

独立测试 test_treasure_contract.py 覆盖物品多重集合、实际持有数量、错误目标、两侧公开回执、下一轮清零、隐藏条件不泄漏。旧 test_treasure.py 中“失败都不耗材”的断言已按原文更正，并把原先只检查一个队伍的同轮测试改成真实两个队伍各结算一次。

任务用品列表随地图变化，不能把文档示例六项当作唯一合法枚举；判定实际背包持有数量，不按角色ID前缀识别己方。

多种失败条件同时出现时，当前采用位置/时间→已空→物品错误的本地顺序，官方未给优先级，不能称为已核验。祭坛条件、时间、奖励仍为本地fixture。其他模拟地图/结算差异不因本次修复而自动消失。

这是P4动作与观测底座。跨日线索记忆、成功后的长期行动记忆、模型推理、缺项/冲突处理、预算购买与完整Agent综合验收仍未完成；当前回执在下一回合清零，后续Agent须记住自己已观察到的成功，不能依赖重复回执或私有状态。
