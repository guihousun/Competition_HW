## 变更与规则边界

- **策略优化**：将建造分成有限批次；采购、使用升级券、返回合法墙内炮位作为完整行程。已实际派出的队友行程参与统一预算和同轮建造落点检查；未派出的提案不能抢占承诺。使用成功须由物品消耗和建筑等级变化确认，返回须由实际到达确认。依据 R01/R02/R04 等现行规则，详见 `specs/ISSUE_32_TEAM_TRIP_COORDINATION.md`。
- **性能优化**：仅缓存不可变格点邻接表，不缓存变化中的地图、占用或价格。165 轮响应、决策报告、planner 状态逐字节一致；单次受控顺序回放总决策时间 53.117→26.585 秒，最慢轮 r139 为 2160.894→1137.956 毫秒。后台负载未控制；这是性能样本，不保证平台时延或收益。
- **本地假设修正**：旧模拟器会让机器人反复争抢同一落点，形成不真实的持久停滞。新规划器先预约互不冲突的意向，仍由共同移动结算器统一结算，不增加行动次数。怪物数值、攻击时序和计分不变。NPC 之间是否允许重叠仍是 P0 待确认 V-027，不能把该规划器称为官方 AI。规则范围参见 R02、`specs/SIM_ROBOT_INTENT_PROGRESS.md`、`project_contract.yaml`。
- **诊断工具**：新增限长、去重的 `robot_occupancy` 日志，记录同帧活机器人坐标重叠证据和版本。缺失/非法数据不当作无重叠；不改变 HTTP 动作、不记录完整 LLM 提示词。
