## 行为

- 前墙、两侧前半段优先，之后补后半圈；后方入口和原墙环范围保留，左右基地镜像。
- 火箭—电磁炮—火箭按横跨迎敌方向排列，优先留空格、保留操控和出入口连通；狭窄区域错位，已有塔不拆除重排。
- 交战/观测不足时工人回内侧，未在做题而承担守炮的开拓者也采用内侧站位；修复“邻炮就停在墙外”与补位调度覆盖回防的问题。
- 第1–3夜清场后可继续有界外勤、换位与宝藏准备；第4夜起全员防守（461轮起的夜间，包括清场后），白天正常生产。题目可能因强制回防中断，既有紧急任务仲裁仍生效。
- 持有修复包且相邻前墙 HP≤70%、另一工人已在内侧炮位时，一人使用修复包，之后恢复守炮；不是任意远距离巡墙维修。
- 采购优先武器升级，危急基地仍优先；`worker_shelter` 只在状态变化时记录。更多行为边界见 `docs/FRONT_WALL_INTERIOR.md`。

## 回归过程与剩余边界

开发全量检查发现过：清场准备被过严站位限制打断、守炮开拓者暴露导致错失宝藏、紧急防守与任务接管冲突。均先修复再运行最终全量；没有删除宝藏完整行程或紧急仲裁断言。旧“全塔挤在正面一列”的策略断言按用户间隔布局要求更新，操控/出口连通检查保留；建造绕路测试改为验证合法移动并在30步内实际到位建造。

一个开发期 Windows 源码 checkout 身份检查曾返回 unknown，随后相关整组与最终164项均通过；准确触发原因未证明。WSL 直接读取 Windows worktree 的 Git 路径另有环境问题，最终改用独立原生 Git 克隆；参赛包由内置 manifest 识别，双平台包身份及入口检查均通过。这些开发期检查不混入最终通过记录。

仍需真实平台核对建造区、墙体遮挡几何、拥堵入口、炮位及采购离岗代价；前半圈尚未建齐时不能保证工人免伤。“前三天有怪也只留一人轮换操炮”仅为后续对照方案，尚未默认启用。
