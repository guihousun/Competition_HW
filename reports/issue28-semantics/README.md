新增说明澄清了此前关键错误：oldest_era在该题中要求的是年代最早的**遗产名称**，不是年代标签。实现按当前命名任务文档提取描述，不固化北京/南京/成都答案、接口凭据或历史TOKEN。

## 已实现

- 支持明确提交格式章节中的`<中文占位说明>`模板、JSON字段注释、字段定义；保留字段含义和来源哈希。占位值只用于提取结构，NoneType表示类型尚未确定，不作为应提交的null答案。冲突描述标记为不确定。
- 字段说明进入模型的提交契约。仅在最近工具回执为已核验、完整的HTTP记录集合时，拒绝可证明的“记录名称字段填了era/date/year等比较值”。更晚的失败/缺页/其他工具会使旧查询失去这项拦截依据。
- 仅显式要求实体/记录名称时做这项检查；题目若要朝代名称，允许年代值。不推断缺失数据，不自动决定复杂历史排序，也不把通过结构检查当判题通过。
- 对题文明示运行check并提交token的契约，要求当前实际成功check输出一致；普通非check来源token任务保持原行为。
- 补充[任务方法说明](../../docs/TASK_METHODS_FROM_FEEDBACK.md)，强调逐题指标、分页、当前spec及TOKEN来源。

## 验证

同目录validation.json记录最终源码、测试范围、实包48次双平台/双阵营POST和证据哈希。POST中使用合成模型与API数据：先发年代值，验证未提交；再发当前记录名称，验证按原样提交。另验证工程check→token提交流程。

这是本地流程和协议验证，不是模型真实准确率测试或内网PASS。完整当前源码的Linux全量回归与Windows Python3.11.10针对性测试分别记录；早期候选上的全量结果不冒充最终源码验证。
