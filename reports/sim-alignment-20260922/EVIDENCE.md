## 结论摘要

1. 机器人攻击射程在官方任务书中是 3 格。用户在 2026-09-22 进一步明确：寻敌偏航范围也按 3 格处理，距离大于 3 的角色不能改变机器人原本朝基地/挡路建筑的路径。当前工作树的 `simulator.py` 已将 `ROBOT_DEVIATION_RADIUS` 改成 3，并已更新距离 3/4 的独立回归。
2. 机器人“隔墙不能打到角色、先打路径第一面墙”有用户实战证据，且与任务书“攻击阻挡移动的单位（包括角色/建筑）”一致；当前模拟器已经实现第一面挡墙优先。官方没有给出完整选敌并列规则、路径 tie-break 或建筑受击的精确时序，仍须标为本地实现假设。
3. Issue #46 证明五场 `attack_map` 的首帧地图元素坐标完全一致；当前 `map_layout.py` 已有 observed fixture，但 `scenarios.scenario()` 的函数默认参数仍是 `layouts.SEEDED`，调用路径若不显式传 `map_layout` 仍可能使用随机地图。地图、完整障碍、defender 全部初始角色和机器人精确刷新点尚未完全官方对齐。
4. 自进化任务的高置信实机证据是：任务点 1/2 分别对应 API/工程题，任务执行链为 `acceptTask → executeCmd → submitAnswer`，超时 15 回合，任务奖励通常为 80 分 + 80 金币；每个任务点 3 次机会且消耗后不恢复来自用户规则补充/验证记录。当前工作树新建世界已切换为 `observed-local-v2`（3 次、15 回合、80/80）；旧 world/replay 缺少规则元数据时保留 `legacy-local-v1`，不静默迁移。
5. “任务提交了但没有官方确认”不能直接记为失败；Issue #25/#27/#42–#45 多次记录 `unknown_without_judge_feedback`。模拟器和日志应区分 `submitted`、`official_success_confirmed`、`value_mismatch`、`timeout`、`task_disappeared`，不能把它们合并成一个布尔成功值。
6. Issue #45 的“已修复 CRLF”只证明该包的解题器提前用 `sed` 处理后成功；它没有证明官方任务模板的裸 `./check` 已被平台修复。Issue #38/#43 的 CRLF 是任务沙盒/模板现象，和本地模拟器的规则逻辑分开记录。

## 核心对齐审计

### A. 机器人寻敌和攻击

官方任务书只明确“机器人会攻击阻挡其移动的单位（包括角色/建筑）”以及攻击力/射程；用户实机补充明确了三个策略约束：

- 机器人默认朝基地推进。
- 我方角色距离机器人超过 3 格时，不改变机器人路径。
- 角色被墙隔开时，机器人先攻击直线路径上的第一面墙，不能隔墙伤害角色。

当前代码 `Demo/CoreGeek/src/agent/simulator.py:_plan_robot_actions` 的实际状态：

- 当前工作树常量 `ROBOT_DEVIATION_RADIUS = 3`，距离 3 的角色可成为偏航目标，距离 4 不可成为偏航目标。
- 建筑被排除在近身角色筛选之外；无近身角色时以己方基地为目标。
- `_intervening_wall` 命中路径第一面墙时生成建筑攻击；否则 `_blocking_building` 只处理机器人下一步正前方的建筑。
- 机器人不会攻击矿点、小贩或武器商店。
- `_allocate_robot_moves` 是一格一格的贪心推进和局部占位协调，不是完整 BFS/A*；多个机器人拥挤时可能出现停滞或绕行差异。

需要保留的边界：

- “攻击范围 3”不等于“全图追人”；不能再使用旧的 4 格偏航假设。
- “建筑只在相邻格受击”目前是由下一步挡路模型产生的本地行为；任务书没有给出机器人是否可在 3 格攻击建筑、如何选择多个建筑、多个机器人如何并行结算的完整说明。应加入距离 1/2/3 的独立回归，并把压力结果标为待核对。
- 需要测试机器人在 3 格角色、4 格角色、直线一墙、斜线一墙、墙后角色、多个墙和多个机器人的组合，分别记录 `robotMoves` 与 `robotAttacks`，避免只看基地血量。

### B. 固定刷怪和地图

Issue #12 给出“蓝方基地右侧、约距右边界三分之一处”的方向线索；Issue #19 附件给出前 7 天数量及“高级怪靠基地、每列最多 9 只”的观察；Issue #46 给出五场 `attack_map` 首帧坐标完全一致。证据支持：固定刷新方向/固定地图档应作为本地重模拟输入，而不是每夜四面随机。

当前实现：

- `scenarios.configure_spawns` / `spawn_column_pool` 建立整局复用的固定列阵池，记录占格短缺，不向四面扩散。
- `map_layout.py` 中 `OBSERVED` 记录 Issue #46 的基地、商店、任务点和未解析障碍坐标。
- `map_layout.metadata` 已将数字 mapType 23/24/25、矿点、defender 其余出生位置、机器人精确刷新格标为未确认。
- 但 `scenarios.scenario(..., map_layout=layouts.SEEDED)` 的默认参数仍指向 seeded random；只有调用方显式选择 observed 时才使用固定 attack_map 档。前端/API 默认值必须单独核对，不能只看 `map_layout.DEFAULT`。

Issue #46 的五场证据范围仅覆盖 `attack_map`，不能自动外推到 `attack_map_update_long_context_mission`、其他地图或未来版本。地图固定坐标也不等于建造区域和机器人刷点全部已知。

### C. 自进化任务

高置信实机流程来自 Issue #21/#23/#24/#25/#27/#42/#43/#44/#45：

| 项目 | 证据结论 | 当前模拟器状态 |
|---|---|---|
| 类型 | 类1常见为 `1-unknown-api`，类2常见为 `2-engineering-fix` | 本地 `local_task_cases.py` 仍主要是天气/账目 synthetic fixture |
| 动作链 | `acceptTask → executeCmd → submitAnswer` | 动作字段存在，局部 pipeline 测试存在 |
| 沙盒位置 | 任务文件位于 `/tmp/selfEvolutionTask/1-fixed-step/...`，cwd 可能是 `/` | 本地 fixture 支持 `/tmp` 路径，但不等于官方沙盒复现 |
| 超时 | 实机多次记录 15 回合 | 新建 `observed-local-v2` 使用 15；旧 world 保留旧值 |
| 任务机会 | 每点 3 次；消耗后不恢复 | 新建 `observed-local-v2` 使用 3；30 回合冷却不恢复机会 |
| 奖励 | 80 分 + 80 金的实机记录 | 新建 `observed-local-v2` 使用 80/80；显式 case 可覆盖 |
| 工程题 | 读 spec/check、修文件、获取 TOKEN 后提交 | 本地有工程 pipeline，但不是官方任务模板的完整复制 |
| API 题 | 需要根据实际回执修正鉴权/参数/响应格式 | 本地 synthetic API 不覆盖实机的 Bearer/location 漂移 |
| 判题结果 | `unknown_without_judge_feedback` 与错误码 1/2 必须分开 | 日志模块已记录部分分类，任务结算仍需核对边界 |

任务点的 `30 回合刷新冷却`是官方任务书明确内容；“每点 3 次”来自用户规则补充和配套验证报告，不应与 30 回合冷却混为一谈。一次任务结束后机会数减少，冷却结束只表示剩余机会可再次领取，不会恢复已消耗机会。

## 不能合并的历史结论

- #45 的“CRLF 已修复”只能描述该场解题器使用 `sed` 后的成功，不能覆盖 #43 对裸 `./check` 的复现，也不能证明官方模板已变更。
- #36 早期用交付 SHA 匹配包身份的“新包零出现”结论已被后续评论纠正；包内源码 SHA、交付提交 SHA、包 SHA 必须分别记录。
- #30/#31 的本地与官方积分差异不支持“本地策略一定更差”或“官方一定采用本地任务判定”；它只说明两个判定环境不同。
- #33/#34/#39/#40/#44 的策略建议和分数归因是日志分析，不是官方规则；尤其“空转原因”“任务机会是否过于保守”需回放和代码状态共同验证。
- #12/#19/#46 对固定地图/固定刷怪的证据只覆盖特定地图或首帧样本，不得推广到所有地图。

## 交付前最小验证门

在把本次对齐实现整合到 `codex/sgh` 前，至少应有：

1. 机器人边界回归：角色距离 3/4、隔墙、第一面墙、无墙基地推进、两侧阵营。
2. 机器人拥挤诊断：记录连续停滞轮数、未达成移动目标数、墙/基地伤害和机器人数量，不只看最终分数。
3. observed `attack_map` 默认入口回归：网页新局、debug series、HTTP 入口均显示固定坐标；seeded 随机档只能显式选择。
4. 自进化官方对齐 profile：每点 3 次且不恢复、超时 15、奖励 80/80、任务点 2 双格、30 回合冷却、两类题完整动作链。
5. 日志状态分型：`accepted`、`executeCmd`、`submitAnswer`、`official_success_confirmed`、`unknown_without_judge_feedback`、`value_mismatch`、`timeout`、`task_disappeared`。
6. 所有报告记录源码 SHA、包 SHA、地图档、波次 profile、阵营、种子和假设；没有内网回执时不能写 PASS。
