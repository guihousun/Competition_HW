OpenRouter/DeepSeek API 已接通；模型与版本化验证范围见上述文档。真实任务判题与官方隔离沙盒仍未覆盖。

**规则补充 S03/S04 与 Issue #19：** 固定刷新点已按 Issue12 方向实现为固定列阵池
（精确格子/纵向中心/红方镜像/占格处理仍为本地几何）；默认波次来源改为 Issue19 附件
第 1–7 天实测，第 8–10 天附件为空、本地假设每夜多 5 只小型并标注未观测。旧的 `day×pressure+1`
压力实验仍可用，但须显式选择 `local-pressure`。机器人攻击角色前先命中挡路围墙。
详见 [RULE_SUPPLEMENTS.md](RULE_SUPPLEMENTS.md) 与 [specs/ISSUE_19_MONSTERS.md](../specs/ISSUE_19_MONSTERS.md)。

完整录像、后台录制和复盘操作已更新，见 [REPLAY.md](REPLAY.md)。这次更新只涉及本地调试设施，
不改变下述模拟器规则覆盖；旧报告仍是对应版本的历史证据。

本项目是参赛决策程序，不是官方比赛平台。当前交付的完整链路是：

**带种子的地图生成 → 官方形状的 HTTP 请求 → 同一决策策略 → 指令审计 → 本地结算 → 下一回合 → 终局、记录与复查。**

## 运行

```powershell
python main.py 8080
```

打开 http://localhost:8080/ ，选择地图种子、左右阵营与压力，点击「新建对局」，再点击「播放」。
默认「官方示例」按钮载入的是单个第 85 回合快照；只有「新建对局」包含完整生命周期状态。
操作细节、画面含义、本地接口与验收证据见 [VIEWER.md](VIEWER.md)。

```powershell
python -m unittest discover -s tests -v
python benchmark.py --seeds 1,7,19
python benchmark.py --seeds 101 --pressure 3
```

批量验证实际向本机临时 HTTP 服务提交每一轮观测（5 秒超时），并用返回的指令驱动模拟。
`reports/benchmark-p*.json` 保存统计，`reports/replay-*.json` 保存初始状态、逐回合指令/事件和最终状态。
这些是可审查记录。页面另有本地录像回放：`⏺ 录制` 由服务端用同一个 `step()` 逐回合录制，
可拖时间轴任意回看；回放读取已记录帧，不重新结算，也不代表官方回放。

## 泛化的具体含义

- 地图维持官方 41×32；种子改变基地位置和中立资源分布，左右阵营都运行。
- 策略读取坐标、实际单位 ID、背包、金币和存活情况；不读取种子、波次计划或模拟器私有状态。
- **指令由注册表统一构造**：每种官方动作一个构造器，发送前校验字段名、类型与数量，非法
  指令在本地就被拒绝，不会变成判题器侧异常（R01 的两层口径）。
- **经济按观测价运行**：卖价读 `vendorShopList`（新闻会改变它），商店商品与价格读
  `weaponShopList`，升级合法性由"建筑类型 + 当前等级 + 站位"决定，本地不写死任何价格。
- 炮台位置相对基地计算，保留已有炮台并分散布局；角色按到炮台的距离分配。
- 角色使用八方向 A* 处理动态障碍，矿点刷新后重新寻找资源。
- 白天建造采集、入夜前回防；经济跑腿是**跨天任务**，中立点较远时允许走到第二天，黄昏前
  自动放弃并返程，不会因为做买卖而缺席夜战。
- **围墙留门**：本地球形是一圈武器、外圈围墙，但围墙上固定留出两格大门。此前只有一格
  入口，机器人站进去就把开拓者封死在围墙内，实测多个种子整局接不到任务；留门后
  `_ring_is_sealed` 在整场对局中始终为假（有回归测试）。
- **任务调度**：白天开拓者的默认动作是走向可接取的任务点，站在点上等待时不交出该回合
  （否则防御调度会把它拉回家，形成两点间往返而任务点始终无人）。这些判断只读
  `playerTasks`（`isValid` / `coldDownRounds`），不依赖跨回合记忆，因此无状态的官方 POST
  也能得到同样的决策。
- **跨回合记忆按对局隔离**：planner 记忆（LLM 额度、任务冷却、待回请求）用"回合号回退"
  识别新对局并整体重置。否则上一局最后一次任务的 30 回合冷却会被带进下一局，
  连锁导致那一局完全接不到任务（实测复现并已加回归测试）。
- 压力改变本地波次数量与构成；测试结果只支持这些有限场景，不能证明任意地图/任务都适用。

| 70 白天 + 60 夜晚，1300 回合 | 已实现 | 第 71 回合入夜，第 131 回合黎明 |
| 切比雪夫距离、八方向移动、基地 2×2 | 已实现 | 基地 pos 为左上角；处理敌方存活障碍 |

| 12 个官方动作码与字段契约 | 已实现为可校验的命令构造器（`actions.py`），非官方字段、非法数量、缺字段在发送前被拒 | 覆盖 `move/attack/sell/buy/build/remove/collect/use/drop/acceptTask/submitAnswer/summonTreasure` 的**构造与校验**；任务类动作的**结算**仍未实现 |

## 本地任务夹具（`taskworld.py`）说明

官方任务文本、答案键与奖励数值都不在已发布资料里，因此演示平台自带一个**夹具**来跑通
"接取 → 保持 → 作答 → 结算 → 刷新"这条链路。它明确是本地生成器：

- 任务文本与答案键由种子与任务序号确定，可复现；
- 奖励形状与官方一致（`scoreReward`/`goldReward`/`timeoutRounds`），数值是本地值；
- 新建本地场景按当前观测元数据运行：两个自进化任务点各有 3 次有限机会，默认
  `timeoutRounds=15`、`scoreReward=80`、`goldReward=80`。这组数值来自 Issue
  21/23/24 的公开观测，不晋升为所有官方任务的通用常量；带有显式任务元数据的夹具按
  自身值运行。
- 每次任务结束都会消耗该点 1 次机会；30 回合刷新只恢复可领取状态，不恢复已消耗机会。
  旧任务世界/回放保留其随世界保存的规则元数据，缺少新元数据的旧夹具按旧档读取，不会
  在载入时静默改成当前观测档。
- 通过率按官方口径计算（正确字段数 / 全量字段数），完整通过额外加
  `5 × 标准回合数 / 实际回合数`；
- 官方结构中被严格实现的部分：2 个任务点/队、任务点 2 占两格、结束后 30 回合刷新、
  仅开拓者可在点旁一格接取、离开范围或超时即结束。

因此页面上的任务分数只能用于验证**我们这侧**的链路是否正确，不能当作官方任务能力或成绩。

## 可视化反馈的依据

网页不是示意图，也不重新解释规则：每回合的 `step()` 在结算的同时产出结构化记录
（`actions` 含命中目标与真实伤害、`robotAttacks`、`unitDeaths`、`robotDeaths` 含击杀分、
`spawned`、`skipped`、金币前后值）。

- 移动动画的起点是上一帧已提交坐标、终点是本帧已提交坐标；跨格超过 2 格的位移（复活、
  波次出现、ID 复用）直接吸附，不做滑行动画。
- 开火、命中、伤害数字、爆炸与击杀分只在真实发生时播放；`skipped` 的失败指令在事件流里
  单列，不会显示成正常回合。
- 「下一轮预览」来自根路径 POST 的 `roleCommandMap`，仍未结算，与「已执行」分开显示。
- 画面不做视野遮蔽：机器人全图可见、敌方基地可见都与 R02 一致；夜间光照只是美术，
  不会隐藏任何已绘制的单位。
- 未实现的玩法不会渲染成可用外观；出现未建模的单位类型时按未知类型降级显示并在诊断页签登记。

## 下一步接官方平台

1. 保持 `bash run.sh <port>` 与根路径 POST 不变，只替换观测来源。
2. 对照官方判题器确认建造区域、波次、同回合移动和弹道，保留失败请求作为回归样例。
3. 扩展独立任务求解模块：领取 → 保持任务距离 → 解析描述 → 受限沙盒/LLM交互 → 提交 → 检查反馈；当前尚无官方任务样例，不能承诺已完成该链路。
4. 加入真实不同地图和未见任务的留出集，再评价通用能力与比赛成绩。

因此，本版是**防御生存子集的端到端 Demo**，不是官方规则完整复刻，也不是已证明的任意挑战 Agent。
