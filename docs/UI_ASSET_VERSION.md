# 前端刷新与静态资源版本（本地 UI 工具说明）

变更类别：UI 工具（AGENTS.md 第 8 条）。不涉及 R01–R08 任何规则、协议、结算或策略。
本文件记录一次浏览器观察、当前采用的诊断约定，以及正常刷新要求。

## 1. 观察到的现象（2026-09-13）

- 现象：`http://localhost:8081` 的用户标签页仍在执行旧的 166×73 大铭牌、
  白天地图仍是深色；但同时核对根服务返回的 `renderer.js` / `index.html` 字节，
  已经是紧凑铭牌 + 昼夜底色的新版本。
- 判定：不是服务端发错文件，而是**已经打开的页面不会热替换**。浏览器在文档加载时
  已经取走并执行了旧脚本；之后服务端文件变化，旧标签页仍按旧脚本继续渲染，
  直到用户主动刷新（普通刷新即可，通常不需要强制刷新）。
- 影响范围：仅本地调试页显示。比赛入口 `bash run.sh <port>`、根路径 POST、
  模拟与策略行为均不受影响。

## 2. 当前约定：静态资源版本后缀 + 页脚版本文字

- `web/index.html` 中所有本地 JS/CSS 的资源 URL 统一带同一个查询后缀
  `?v=<版本>`（例如 `/js/renderer.js?v=20260913a`），版本变化时才需要改这一处常量值。
- 页脚新增可见文本 `前端 <版本>`（`#foot-ver`），与资源后缀一致，用于一眼判断
  当前标签页是哪个版本：页脚是旧版本号，说明标签页仍在用旧页面。
- 根服务端的静态处理已按 `urlsplit(self.path).path` 取路径（`agent/server.py`
  的 `_static`），查询串不会参与文件查找，因此**不需要改任何 Python 代码**。
  普通 GET 仍然直接读文件，没有额外缓存层。

## 3. 正常刷新要求（不自动刷新）

- 打开着的页面不会因为服务端文件更新而自动更新；这是预期行为，**不要**加入自动
  刷新或强制重载：那会丢失正在进行的对局、回放位置和控制台状态。
- 需要看到新前端时：在标签页手动刷新（F5 / Ctrl+R），或新开一个标签页。
  若页脚版本号或 `/js/*.js?v=` 后缀与预期不符，说明仍是旧页面。
- 版本后缀是诊断手段，不是功能开关；它不改变脚本加载顺序、ID 或界面结构。

## 4. 覆盖范围与未覆盖项

- 已覆盖：`tests/test_frontend_layout.py::test_asset_urls_share_one_version_suffix`
  断言所有 JS/CSS URL 使用同一个 `?v=` 后缀，且页脚显示同一版本号。
- 未覆盖：本仓库无浏览器自动化，无法在 CI 中验证“旧标签页确实不热替换”这一
  浏览器行为；本文件记录的是人工观察结果，不是自动化证据。
