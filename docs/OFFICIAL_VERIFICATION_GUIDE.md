# 官方核验指南（配合 `project_contract.yaml`）

本文类别：**文档 / 流程工具**。它不修改官方规则、不修改程序行为，也不被运行时代码读取。
用途：把 `project_contract.yaml` 里登记的问题变成公司内网官方接口上可执行、可回填的核验动作。

编制日期：2026-09-14。基线：`Tymonxiong/Competition` 提交
`7e629424c87f3f194d071696d3ee59a8dc2c0a75`，任务书/接口文档 v1.0（2026-09-09）。

## 1. 两个文件怎么用

| 文件 | 角色 | 谁编辑 |
|---|---|---|
| `project_contract.yaml` | 全项目合同与核验台账：官方常量、来源与优先级、本地实现快照哈希、待核验条目 | 取到证据的人可按第 4 节回填；结构性改动交 Codex 审核 |
| `docs/OFFICIAL_VERIFICATION_GUIDE.md` | 怎么核验、怎么回填、怎么反馈 | 同上 |

要点：

- `runtime_loading: false`：**没有任何代码读取该 YAML**，它是给人看的台账，不要把它当配置文件接进程序。
- 每条 `verification_items[]` 都绑定 `source_refs` 与 `implementation_snapshot` 哈希。
  该快照是**工作树快照**：`git_head` 只是本地分支提交，而 `Demo/CoreGeek/` 与 `tests/` 在编制时的基线 HEAD 下
  仍是未跟踪文件，所以 **HEAD 不能代表被描述的模拟器/策略实现**；判断"现状是否已变"必须按
  `implementation_snapshot.files` 的仓库相对路径 + SHA256 逐个比对。
  首次发布同时记录 `git_content_sha256`：它对应 Git 中保存的文件字节，可用 `git show <提交>:<路径>` 取出核验，避免 Windows/Linux 换行转换造成误判。
- 五类 `category` 必须分开写：`ambiguity`（官方没说清）/ `assumption`（本地假设）/
  `source_conflict`（两份官方材料冲突）/ `implementation_gap`（官方明确、本地没做）/
  `noncompliant_approximation`（官方明确、本地近似实现）。已知缺陷即使正在等真实回归，
  也仍然是 `implementation_gap`，不能降级成"待确认"。

## 2. 优先级速查（先做哪几条）

P0/P1 的依据是**官方符合性影响**，不是标签：P0 = 影响胜负/结算/能否参赛，P1 = 影响观测与判分口径。
下表是建议的第一批（7 条），其余条目按 YAML 里的 `priority` 排序。

| 顺序 | 条目 | 一句话问题 | 最小证据 |
|---|---|---|---|
| 1 | V-009 | 官方编译运行环境与沙盒权限边界（OS/Python/依赖、cwd、读写范围、持久化、限额） | 《编译运行环境说明》原文或平台帮助页；一次真实 `executeCmd` 回执 |
| 2 | V-001 | 固定刷新点的确切坐标与批次落位/被占格处理 | 连续两夜同一地图的请求快照（同坐标重复、含被占格处理） |
| 3 | V-005 | 回执的最小必需形状：空 `roleCommandMap`、省略 `prompt`/`executeCmd` 是否合法 | 官方一次"无动作/无任务"回合的完整回执 |
| 4 | V-003 | 蓝/黄建造区的确切几何与锚定 | 带坐标刻度的建造区示意图，或合法/非法建造回放 |
| 5 | V-008 | 终局真实配对轨迹：同回合双毁、提前单毁后是否继续 | 官方两段终局回放（含最终比分） |
| 6 | V-017 | 官方游戏内 LLM 的提供方/模型/token 与上下文上限、prompt↔llmResp 关联 | 一次 `prompt` → 下一轮 `llmResp` 配对样本 |
| 7 | V-002 | 任务点2 两格的朝向/锚点编码（两格本身官方已明确） | 两张不同地图的请求片段（两格坐标差 + `taskPosition`） |

P1 里成本最低的是 V-021 的前半段（S01 是否为"围墙"笔误）和 CF-D02（一级炮 `attackRange` 实际值）：
都只需要官方一句话或一次请求，可并入第 3 步一起问。

## 3. 一次核验怎么做

1. **读条目**：在 YAML 里找到 ID，读 `official.requirement` 与 `local.behavior`，确认要问的是
   `question` 里那一句，而不是顺手扩问。官方已写明的规则（切比雪夫距离、3×3 含对角线、
   10s/5s 两个时限、被毁当天存活系数 0、部分完成不含时间加成）不要在平台上重复确认；
   要确认的是这些规则**没有**覆盖的边界。
2. **造最小场景**：只覆盖该问法的最少回合。例如 CF-D02 只需一次"目标恰好在距离 3/4"的
   `attack` 回执，不需要跑整场。
3. **取三元组**：保留 **请求 → 响应 → 下一回合请求**。下一回合请求里的
   `lastRoundRoleActionResults`、`errors`、坐标变化，才是"官方是否接受了这条指令"的证据。
4. **记录核实结论**：把结果写进条目（见第 4 节），并注明这是**官方平台观测**还是**文档原文**。
5. **冲突不要静默改基线**：两份官方材料不一致（如 `CF-D02` 射程）时，保留双方原文，
   在 YAML 里登记冲突与影响范围，交 Codex 审核决定，不自行选边、不改 `docs/任务书.md`。

## 4. 怎样把一条标成"已确认"

任何人都可以按第 3 节取到证据后直接回填条目；不需要额外授权，但**结论必须可复核**。

1. 填 `confirmation`，必填字段：`value`（官方确认值）、`source`（官方平台/版本文档）、
   `evidence`（回放编号、截图名或原文节号）、`date`、`by`。
2. 把 `status` 改为 `confirmed`。`value` 仍然是**人工证据**，不是自动事实：
   它必须能追溯到 `evidence`，并且与 `local.behavior` 的差异要写清（需要改代码就另开实现任务并引用其编号）。
3. 若只确认了一部分，**不要**改成 `confirmed`；在 `confirmation.partial` 里写清确认了什么、
   还缺什么，`status` 保持 `pending_official`。
4. 官方材料升级（新版本/新补充）时：**先复核条目里的断言与证据是否仍成立**，再更新
   `source_refs` 哈希并把受影响条目改回 `recheck_source`。只重算哈希、不复核断言，等于把旧结论
   套到新版本上；旧回放要标注其版本，不覆盖为"新版本已验证"。
5. 相互冲突的官方材料不因一次核验就删除：保留双方原文与冲突登记，直到官方给出裁定。

## 5. 反馈模板（可复制）

```text
ITEM: V-0xx
PRIORITY/CATEGORY: P0 / noncompliant_approximation
官方平台与版本: <平台名> / <规则或判题器版本> / <日期>
实现版本: 优先填包含该实现文件的提交 SHA；未提交时给出**相关文件的完整 SHA256 列表**
          （不要只写仓库 HEAD——编制基线 HEAD 不覆盖模拟器/策略目录；首次发布后可填写包含这些文件的提交 SHA）
场景: 地图/种子=<...>，阵营=<challenger|defender>，回合=<N>，轮次范围=<...>
请求(脱敏): <该回合官方发来的 JSON 片段，仅保留相关字段>
响应(脱敏): <我方提交的 roleCommandMap / prompt / executeCmd 片段>
下一回合请求(脱敏): <lastRoundRoleActionResults / errors / 坐标变化>
预期: <依据官方哪一节，期望发生什么>
实际: <实际发生什么>
结论: <官方确认值 或 "仍不确定">
证据引用: <回放编号 / 截图文件名 / 官方原文节号>
```

模板使用要求：

- 只贴**判定该问法必需**的字段；不要整包贴请求，不要贴公司原始文件、日志、账号、令牌、内网地址。
- `expected` 必须引用官方出处（章节号或平台提示），不能只写"我认为"。
- 观察到的行为与文档写明的权威不是一回事：**owner 在平台看到的实际行为**属于真实回归证据，
  但仍应在结论里注明"平台行为，等待官方口径确认"；**文档原文**可以直接作为权威引用。
  两者矛盾时不覆盖任何一方，登记冲突。

## 6. 数据安全与边界

- 不写入密钥、令牌、Cookie、账号、内网 URL、公司原始数据；不把官方请求整包复制到仓库。
- 截图只保留与问题相关的最小区域，遮掉无关信息。
- 本地模拟、动作审计、单测通过都不构成官方认证；报告只声明实际达到的层级
  （协议结构 / 单条规则 / 模拟留出集 / 官方平台回放）。
- 本指南与台账都不改变任何官方数值，也不把已知官方规则降级为可调参数。
