# 防御阵容配对实验

类别：策略实验 / 验证工具。依据 R03/R04（任务书 §4.5：三座上限、每座25金币、武器参数），
不改变官方规则。比较三火箭 RRR、三加特林 GGG、三电磁炮 EEE、混合 GER、两火箭一电磁炮 RRE。

预先确定的矩阵：地图 1、7 为开发集，1371 为本轮留出集；每图蓝红两侧、压力 1/3，
每配置 12 场，共 60 场，最多 1300 回合。留出集只是本轮未参与选型的输入，不能代表任意地图。
同组初始状态 SHA-256 必须相同；只改变炮种组合，角色经济/任务/回防算法相同。
后续刷新按当时的空闲格子采样，策略引起的占用变化可能改变出生位置；本实验不是固定敌军轨迹的靶场。

先做 140 轮预检查，并核验实际造出的三座炮。预检查发现旧建造逻辑按动态炮位索引取炮种，
使 GER 实际变成两电磁一火箭。现改为按“目标数量减存活炮台和本轮已计划建造数量”补齐。
独立回归验证混合与两火箭一电磁在左右两侧都能造出目标组合。没有自动更换网页默认的三火箭。

运行：

```powershell
python tools/compare_defences.py --output reports/defence-comparison-20260912
```

每个独立工作进程设置当前阵容，运行结束后恢复；不修改正在运行的网页进程。
实验使用直接本地 step()，不是每轮 HTTP 对战，也不连接付费 LLM。请求/命令会用现有独立审计器
检查，但该审计器不是官方判题器。报告记录请求通道数量，不能把未实际执行的 LLM/沙盒请求算作成功。
逐场结果、聚合、源码哈希和规则假设均保存在输出目录，源文件在实验中改变则拒绝混合版本。

重点比较：1300 轮结束时基地存活局数、基地血量、总分及任务分、击杀数、阵亡、动作失败和审计错误。
本地单队生存不是官方双队胜率；地图上的敌方不构成完整对抗策略。
出生点现已改为固定列阵池（补充 S03），不再四面随机；本页比较报告是旧源码证据，仍按当时
版本阅读。波次数量、建造区、机器人选敌、任务内容等仍含本地假设。混合配置也只测试固定建造
顺序，未穷举炮位排列。
因此结果只能筛选下一步候选，不自动据此宣称官方最优或替换正式阵容。

结果入口：[2026-09-12 测试报告](../reports/defence-comparison-20260912/REPORT.md)。
本轮60场已完成：三加特林、两火箭一电磁炮各12/12场基地存活；三火箭11/12，
三电磁炮10/12，三种混合9/12。两火箭一电磁炮平均本地分比三火箭高7.6分，
但留出地图高压力的平均基地血量为427.5，低于三火箭的1235，尚不支持通用优势。
共发现155次动作失败、3次超预算审计问题。下一步先修复共用协同缺口，保留多个候选，
不据此自动调整正式默认配置。

完整矩阵完成后生成报告：

```powershell
python tools/report_defences.py reports/defence-comparison-20260912
```

可单独复现某一场的动作失败，输出完整失败轮次、指令、角色状态和事件：

```powershell
python tools/diagnose_defence.py --strategy RRR --seed 1 --side defender --pressure 3 --output reports/diagnosis-new-run.json
```

后续扩展顺序：先统一队伍预算预留、协调同轮落点；补齐已确认的固定刷新点后重新建立基线；
再分别测试炮位/墙体布局、升级顺序、角色回防时机。每次比较明确哪些策略因素发生变化，
保持规则参数一致，并重新划分未用于调参的验证地图。旧结果仍保留为旧源码与旧假设下的证据。
