# 完整对局录制与复盘

本次变更类别：**UI工具 / 本地模拟器调试设施**。不修改策略、官方原文、数值或游戏结算。
约束依据：`DEVELOPMENT_RULES.md` R01（接口文档开头、§1–2，保留根路径 POST）、
R02（任务书 §4.1–4.3，坐标与昼夜）、R08（任务书 §六–八，本地终局不是官方双队胜负）。

## 使用

1. 启动 `python main.py 8080`，打开 `http://localhost:8080/`。后端升级后需重启服务。
2. 设置种子、阵营和本地压力。点击「录制到终局」，后台使用原有 `step()` 逐回合结算。
   也可录制前 600 回合。录制上限不等于游戏终局，页面不会把截取的录像当完整比赛结束。
3. 进度卡显示已完成回合、百分比和耗时。「取消录制」在当前回合完成后停止，保留已录片段。
4. 录制完成从**初始帧**打开，点击播放、单步或拖动时间轴复盘。帧 0 是初始状态；
   帧 n 是完成 n 次本地结算后的状态，事件里标明实际结算回合号。
5. 在「对局复盘」筛选失败指令、阵亡、波次、任务/宝藏、昼夜切换，使用前后事件按钮
   或彩色时间轴标记跳转；可以输入帧号精确定位。
6. 「保存完整录像」保存全部已记录状态、事件、已提交指令和下一轮预览指令。
   「打开录像」恢复整个时间轴，回放不会重新请求策略或模拟结算。
   页面加载后，已打开的录像播放不需要后端在线；刷新页面仍需要页面资源。

## 可追溯性与导入

- 新格式 `competition-hw-replay` v1，SHA-256 用于检测文件损坏或修改，不是来源认证。
- 记录种子、阵营、压力、规则基线、录制范围、取消状态，以及录制开始时参赛程序 Python 源码
  和两份官方文档的内容哈希；该哈希不是 Git 提交，也不包含前端文件。
- 接受新格式录像和旧版 `/debug/series` 的完整数据（旧格式无校验和，会提示）。
  旧版「导出记录」只有单帧摘要，不能恢复完整比赛；导入会说明原因。
- 文件上限 128 MB、最多 1300 次结算；缺帧、事件回合不匹配、无效地图和校验失败会拒绝。
  导入失败保留原录像。单个官方请求仍可通过「导入请求 JSON」查看。
- 实时模拟也可保存当前已录片段。新建单队场景记录来源哈希；旧文件未提供的版本信息不补造。

## 后台任务生命周期

| 方法 | 路径 | 行为 |
|---|---|---|
| POST | `/debug/recording/start` | seed/side/pressure/limit，返回 202 和独立任务 ID |
| GET | `/debug/recording?id=…` | running/stopping/done/cancelled/failed、进度与耗时 |
| POST | `/debug/recording/cancel` | 按 id 取消，保留已完成回合 |
| GET | `/debug/recording/result?id=…` | 完成或取消后获取完整录像；运行中返回 409 |

同一服务仅允许一个后台单队录制任务执行；重复启动返回 409，不替换别人的录制。
最多保留三个任务于内存；任务过期/服务器重启后返回 404。旧任务 ID 不会取消新任务。
同一浏览器页刷新后通过 sessionStorage 恢复进度追踪；临时网络错误可点击「重新连接」。
客户端请求等待最多 15 秒，连接失败不假装已取消服务端工作。
完整录像请保存到文件，服务器内存与页面内存不承担持久存档。
原有 `/debug/series` 同步接口继续兼容。

## 边界

录制的是现有**单队本地模拟**。建造区域、波次、任务夹具、部分弹道细节仍是本地假设；
单队提前终止和分数不等于官方双队终局/胜负。此轮未修复现有规则差异，也未接入公司内网平台。
新录制不改变观测权限、动作额度、1300 回合规则或模拟器结算行为。

验证覆盖与源码哈希见 `reports/REPLAY_VALIDATION.md`。旧文档中的过往基准仍是历史证据。
