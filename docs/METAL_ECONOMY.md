# 工人金属经济闭环

变更类别：策略优化（2026-09-13）。规则依据：

- R03：任务书 §4.4 采集需工人在石矿/铁矿/铜矿周围一格内，每轮一个，受背包容量限制；
  §4.5.1 围墙每座耗石头 1；§4.5.2 工人背包 100。
- R06：任务书 §4.4 贩卖需在小贩周围一格内；§4.6.1 收购价随世界新闻变化，必须读当前
  `vendorShopList`，不能锁死样例价格。
- R02：任务书 §4.5.4 切比雪夫距离、八方向每轮一格；白天 70 轮/夜晚 60 轮。
- R01：接口文档 §1、§2，每角色每轮至多一条指令；本地规划需稳定在 5 秒响应内。
- R04：任务书 §4.4 攻击仅黑夜可用，武器需角色操控，因此黄昏前必须回防。

## 问题

`brain._worker_day` 在完成即时交易后有一句 `if not walls_missing: return`。围墙建满后
工人当天到此结束，后面的取铜/取铁分支永远不可达：完成防御的工人只会采石或原地不动，
金属经济从未真正闭环（本地基线可见“挖到 10 铜、卖出 0”的对局）。

## 行为（当前策略）

防御（炮台 + 围墙）完成后，白天经济窗口内（回合索引 12–54）空闲工人按以下顺序行动：

1. **先卖后挖**：背包中“小贩当前收购”的金属总数 ≥ `METAL_BATCH`(10) 时走向小贩；该判断
   在“背包已满”之前，因此装满也不会站在原地。有任务账本时，这条腿仍由既有的
   `_start_errand`/`_errand_mission` 承担。
2. **选矿**：只在小贩清单中**已公布价格且价格 > 0** 的金属中选，价格高的优先；同价按
   铜、铁固定顺序（与字典遍历顺序无关）。价格缺失或为 0 的矿石不会被开采。
3. **开采**：矿必须在 `ORE_MAX_DISTANCE`(8) 内，并同时满足
   - 存在**合法且空闲**的站位（不能站到基地、围墙、机器人或已建炮台上），
   - 从工人当前位置到该站位的**有界 A\* 路线真实存在**，
   - 从小贩到该站位的路线存在（否则挖了也卖不掉），
   - “去矿 + 采够可卖的批量 + 回基地旁”的**路径回合数**不超过当天黄昏交接前的余额。
4. **卖出**：沿用既有小贩逻辑。实际成交批量由原策略阈值决定（`_should_sell` 的
   `ECONOMY_MIN_SURPLUS`：3 件可卖余量，与单价无关），本改动不改交易策略；`METAL_BATCH` 是单次
   行程上限，防止背着整包金属不卖。

保留的既有优先级与限制：

- 造炮 > 建/修墙 > 采石 > 金属；建墙期间不会转入金属开采。
- 石头储备（`WALL_RESERVE`/`STONE_BATCH`）在卖矿时保留；预算预留与同轮移动协调不变。
- **全队同一时间仍只有一条小贩任务**（`errands` 账本 + `break` 未改）。有行程在途时金属
  行程不启动，不绕过该上限，也不会把两个工人同时派出去。
- 当任一工人仍有可采金属时，采购行程让位（避免“站在商店耗尽白天、永远挖不到矿”）。
- 黄昏 `RETURN_BEFORE_NIGHT`、`_is_return_phase` 与夜间战斗优先级不变；夜间维护逻辑
  （`nightwork`）不变。

## 边界与保守性

- **不越权**：全部输入来自公开观测（`mapInfo.zones`、`vendorShopList`、角色背包与位置）。
  未新增 `_demo` 读取；无小贩或小贩不可达时不开始采矿，避免“挖了卖不掉”。
- **不空追矿**：矿不存在、超距、无空闲站位、路线不可达、或该矿已填满一次行程，都不出发。
- **回程预算**：`ORE_MAX_DISTANCE` 以角色为参照，不保证离家近，因此另有路径回合预算。
  回程目标是**基地旁的空闲格**，不是基地自身坐标——基地格是阻塞区，`_cost_to_goal` 永远
  到不了，用它当目标会让所有行程看起来都不可能。时间不够就不出发，比走到一半折返更保守。
- **性能**：`_RouteCost` 只在单次 `_day` 调用内创建，不写入观测/规划器/模块全局，也不跨
  请求或跨回合复用；键包含移动角色 ID，因为 `turn.blocked(role)` 与由谁移动有关。
- **无新增持久状态**：金属行程不依赖跨轮记忆；`_demo.errands` 仍是可选本地账本，官方
  无状态 POST 路径同样能完成“采满 → 卖矿”。

## 未覆盖 / 限制

- 只用本地模拟与单元测试验证，未在官方平台回放，不代表官方胜率或合规认证。
- 回程与去矿用有界 A\* 的路径长度估算；机器人同轮移动、敌方拦截与执行失败（碰撞、落点
  被占）不在保证范围内，冲突仍由既有 `reconcile` 保守处理。
- 机器人现已按固定列阵池刷新（补充 S03）；本页结论来自旧源码版本，波次数量等仍含本地假设。
- 「合理批量」的成交额由既有 `_should_sell` 阈值决定，未调参；新闻价格高时工人会更早卖
  而不是采满 `METAL_BATCH`。
- 结构化验证发现：**预先摆好整圈围墙再放工人**会把工人关在环内（真实对局中围墙由工人
  从外向内建，不会这样）。这是测试夹具的构造问题，不是策略改动；真实种子用例因此先把
  工人放到环外合法空地再竖墙。
- Codex 的成对整局基线显示：候选版在部分对局（seed1 挑战者铜 3 卖 3、seed7 挑战者铜 17
  卖 17、seed7 防守者铁 20 卖 19）出现金属收入，其余对局仍以采石/防御为主，**总收入并非
  普遍更高**；六局基地均 1500、无执行/审计失败。未做新的 loadout 基准。
