# 本地演示与调试平台使用说明

当前观战界面与常用流程见 [VIEWING_GUIDE.md](VIEWING_GUIDE.md)：一键开始、战况解说、角色定位，
以及按需展开的调试面板。下文旧按钮名称和截图保留为历史资料。

2026-09-12 录制与回放更新见 [REPLAY.md](REPLAY.md)：后台进度/取消、完整录像保存与导入、
关键事件跳转和终局回看。下文旧版操作与验收数据保留为历史记录；录制操作以新文档为准。

面向直接使用网页的人。规则依据与差异清单在
[DEVELOPMENT_RULES.md](DEVELOPMENT_RULES.md) 与 [DEMO.md](DEMO.md)，本文件只讲怎么用、
怎么验证、以及画面上的东西各自代表什么。

## 1. 启动

```powershell
python main.py 8080
```

打开 http://localhost:8080/ 。判题入口不变：`bash run.sh <port>`，根路径 POST 返回
`roleCommandMap`。网页与 `/debug/*` 都是本地扩展，删掉它们参赛程序仍能运行。

可选自查：

```powershell
python -m unittest discover -s tests -v     # 13 项：协议、模拟、场景、服务、前端逻辑
python benchmark.py --seeds 1,7,19          # 批量 HTTP 基准，结果写 reports/
```

> 若 8080 已被另一个旧进程占用，页面会是旧版本。用
> `Get-NetTCPConnection -LocalPort 8080 -State Listen` 查占用进程，停掉后重新启动。

## 2. 一条完整链路怎么走

1. **新建对局**：顶部选种子 / 阵营（蓝方=左上基地，红方=右下基地）/ 压力（本地假设），
   点「新建对局」。画面立刻显示初始布局：基地、3 个角色、中立点、矿点、双方任务点。
2. **看懂布局**：鼠标悬停任意单位或中立点 → 浮动说明；点击 → 右下「单位详情」显示真实字段。
3. **开始对局**：`▶ 播放` 按速度档逐回合推进；`⏸ 暂停` 随时停。
4. **单步分析**：`⏭ 单步` 结算一回合（一次 `/debug/step`），`⏮ 退一步` 回看上一帧。
5. **暂停检查**：暂停后可用 `+ / − / 全图 / 跟随基地`、滚轮缩放、拖拽平移放大看细节；
   「下一轮预览」「已执行」「事件流」三个页签分别对应策略意图、真实结果和逐回合日志。
6. **重置重试**：`⟲ 重置` 回到第 1 回合；改种子/阵营/压力后再点「新建对局」即可换场景。
7. **查看结果**：基地被摧毁或到 1300 回合时，画面顶部出现终局横幅，HUD 与「已执行」页签
   保留回合、天数、本地分数、击杀、金币；`导出记录` 可导出本帧的请求/指令/事件。

想一次看完整场：「⏺ 录制 600 回合」或「⏺ 录制到终局」让服务端逐回合录制，然后拖动
时间轴任意回看，速度档调到「极速」即可快速浏览。

## 4. 动画与事件：哪些是真实依据

- **移动**：只在状态已提交后播放，起点是上一帧坐标、终点是本帧坐标，逻辑坐标始终取
  状态值；一步超过 2 格（复活、波次出现、ID 复用）直接吸附，不做滑行。
- **开火 / 命中 / 伤害数字**：来自该回合 `frame.actions[].salvos[].hits`，包括真实伤害值。
- **击毁 / 爆炸 / 击杀分**：来自 `frame.robotDeaths`，分数取任务书表值。
- **受伤**：角色被机器人攻击时按 `frame.robotAttacks` 播放。
- **失败指令**：`frame.skipped` 会在画面上以「指令未执行」浮标显示，并在「已执行」页签单列，
  不会被隐藏成正常回合。

## 5. 开发者面板

| 页签 | 内容 |
|---|---|
| 下一轮预览 | 当前状态下策略要提交的指令（尚未结算），可用开关在画面上隐藏 |
| 已执行 | 本回合真实执行的动作、结果、失败原因、击杀奖励 |
| 事件流 | 逐回合结构化事件，可按类型过滤（移动/采集/建造/开火/机器人/击毁/阵亡/波次/金币/失败） |
| 任务 | `phaseTask` 原文、每个任务点的可领取状态/冷却/超时/奖励、本地任务夹具的结算（通过率、积分、金币、提交答案与参考答案）、判题器通道状态（本日 LLM 额度、待回 prompt/executeCmd、`lastCmdResult`、`llmResp`）、宝藏（民间传闻原文、祭坛位置、献祭物品、时间窗、是否已被开启） |
| 双队 | 本地 1v1 对比：启停控制、进度、双方积分与基地血量、最近事件、本地结果（含"不是官方成绩"的说明） |
| 单位详情 | 选中单位的真实字段、射程、冷却、背包 |
| 请求 / 响应 | 可直接编辑并「应用到画面」或「只跑策略」；响应来自根路径 POST |
| 规则边界 | 官方明确 / 非合规近似 / 本地假设 / 实现缺口 四类分列 |
| 诊断 | 帧率、单帧渲染耗时、特效计数与丢弃数、未建模类型、未覆盖动作、失败记录 |

画面上不同箭头含义不同，这是刻意区分的：

- **黄色虚线箭头 + 编号圆环**：预览（下一轮将要提交的 `roleCommandMap`），不代表执行成功。
- **青色实线箭头**：本回合**已执行**的移动。

## 6. 本地 HTTP 扩展

| 方法 | 路径 | 用途 |
|---|---|---|
| GET | `/debug/stats` | 官方常量与等级表（射程、血量、机器人数值），供前端不写死 |
| GET | `/debug/rules` | 差异清单（官方/近似/假设/缺口） |
| GET | `/debug/scenario?seed=&side=&pressure=` | 生成带种子的初始场景（不推进） |
| POST | `/debug/step` | 本地结算一回合，返回 `state` + `frame`（结构化事件）+ 下一轮 `roleCommandMap` |
| POST | `/debug/series` | 逐回合录制整场，返回 `initial` / `frames` / `states` / `final`（回放数据源） |
| POST | `/debug/screenshot` | 验收辅助：把页面 canvas 存到 `reports/screenshots/`（仅接受 PNG data URL） |
| GET | `/`、`/css/*`、`/js/*` | 本地页面（只从 `web/` 目录读取，拒绝越界路径） |
| GET | `/sample` | 官方示例请求（`docs/request.txt`，原样） |
| POST | `/`（根路径） | **官方兼容入口**，请求失败也返回 `{"roleCommandMap":{}}` |

`POST /` 是唯一对判题器有意义的入口，其余都是本地功能。`_demo` 私有状态在进入策略前由
`scenarios.observation()` 剥离，录制数据也会去掉模拟器内部账本后才发给前端。

## 7. 规则边界与差异（画面里也常驻显示）

- 压力档、本地分数、测试通过率都**不是**官方难度或官方成绩。
- **视野**：已按 任务书 §4.3 过滤。己方单位共享视距 4；敌方基地与围墙全局可见；
  机器人全局可见；其余敌方单位只在视野内出现。`observation()` 是唯一出口，
  策略与本地模拟都只看得到合法信息（`vision.py`，含 `contact_report` 供界面显示
  "看得见几个、隐藏几个"）。
- **同回合移动**：按 §4.2 以"同一轮内腾出的格子可进入"结算：换位、整条链式前进都成立；
  同一格被两个角色争抢时都不移动；形成闭环（A→B→C→A）时无人移动。此前的保守近似
  直接拒绝目标格被占的移动，实测每局数百次"指令未执行"，修复后多数配置为 0。
- **寻路保证**：`next_step` 返回"某条最短路线的第一步"，并在多条等价最短路线中优先选能
  明显缩短距离的一步。A* 只保证最优代价，返回哪条等价路线取决于扩展顺序，实测会让开拓者
  看起来在原地左右挪动；现在同一棋盘上结果稳定且单调前进（`tests/test_pathfinding.py`
  用独立的最短路检查器验证，而不是硬写坐标）。
  排查时发现一个真实缺陷：用于比较候选步的代价探针沿用了默认搜索上限，长路线上对每个候选
  都报"不可达"，使比较全部失效；现已传入调用方允许的预算（下限为地图格数）。该修复不改变
  得分，但让选择真正生效。
- **任务刷新是"按任务点"而不是"按队伍"**（任务书 §五）：30 回合刷新属于结束任务的那个点，
  不封锁另一个可接取的点。此前策略把冷却当成全队状态并写进 planner 记忆，实测每完成一个
  任务就白白放弃 30 回合的另一个任务点，而且**只有保留记忆的路径会这样**——无状态的判题
  请求反而更接近规则。现在改为只看判据 `isValid` 与 `coldDownRounds`（按点），
  全局冷却不再阻止接取。实测（种子 1/7/19/3/23 双方，压力 1）：总任务结算 108 → 129，
  十个配置 `audit_errors` 全为空，总分 2588 → 2637。
  代价：开拓者在任务循环里待得更久，宝藏在部分种子上会错过时间窗（见下）。
- **任务用品的价格**（任务书 §4.6.3 末表）：六种任务用品（AcientTablet / StarSand /
  FlameBreath / FrostPotion / ThornAmulet / IronWhistle）**每种 15 金币**，属于武器商店商品，
  只可用于召唤宝藏，使用后消失。此前本地商店目录与价格表都漏了这六项，等于这一整类商品
  在本地不存在；现已补进 `SHOP_PRICES`、本地 `weaponShopList` 夹具与协议测试。
- **传闻的发布通道**：祭坛线索按 §4.8 走 `worldNews.folkLegends`（民间传闻），
  策略用 `treasure.notes_from_news` 解析。此前线索只放在 `_demo` 里，而官方请求会剥掉
  所有 `_` 前缀字段，所以**无状态 POST 上策略永远看不到这条线索**——把线索放错通道，
  等于整个宝藏机制对判题路径不存在。现在已验证：从 `observation()` 出来的请求里
  能解析出 site / items / 时间窗。
- **召唤宝藏**（任务书 §4.6「仅开拓者可用，在周围一格内献祭任务用品，召唤并开启祭坛宝藏」、
  §5.2）：动作已**原子**实现——成功则消耗献祭的任务用品、加积分与金币、并把宝藏标记为已开启；
  失败（物品不足、不在有效回合、不在祭坛一格内、非开拓者）**什么都不改**并给出原因。
  一张地图只有一个宝藏：同一回合内双方都满足条件都可获得奖励（§5.2 明文），
  之后的回合再开启没有奖励。祭坛位置、献祭物品与时间窗在原文里是"需要玩家根据民间传闻推断"，
  因此本地用**夹具**生成并通过 `treasure_notes` 发布，传闻文本自带"本地夹具"字样；
  奖励数值也是本地值，不是官方分数。
  **策略侧已打通**：开拓者会**购买任务用品 → 走到祭坛 → 召唤并开启宝藏**，整条行程只依赖
  已发布的传闻、自己的背包与金币，因此在无状态 POST 上同样成立。实测五个种子全部开启成功
  （开启回合 92–220，各买 2 件），得分随之上升：种子 1 2185→2485、7 2551→2845、
  19 2631→2931、3 2440→2846、23 2384→2684；任务结算数不变（16–20 次），`audit_errors` 仍为空。
  这条路上修掉了三处"指令被顶掉"的缺陷：`_day` 末尾的炮位调度、`plan_for_state` 里
  **第二遍**的宝物/任务行走、以及任务管线对开拓者的抢占；现在只要宝物行程发出了指令，
  当天其余调度都让位。行程的启动条件也改成"这趟基本是顺路"（窗口已开，或离窗口开启的
  空闲回合足够走完），否则宁可把白天用在任务点上——曾经无条件优先宝物，实测反而低
  150–260 分。
  **同一机制的第四条缺陷（本回合）**：`_treasureRound` 是"本回合宝物占用开拓者"的**回合内**
  标记，却被写进了调试接口返回的状态，浏览器下一回合把它原样送回，于是此后每一回合都
  认为宝物仍占用开拓者，任务行走全程被压住。现已从 `_viewer_state` 与 `step_payload` 两侧
  剥掉，并登记在 `HW.viewModel.roundScopedKeys` 里；浏览器验证：`_treasureRound` 不再泄漏。
  **仍未解决**：无。本回合已定位并修复根因——**调试页每回合都在跑一个"失忆"策略**：  `_viewer_state` 把存活的 planner 对象换成了摘要（随后又被 `_json_safe` 变成类型名占位符），
  浏览器下一回合把状态发回来时，`PlannerState` 无法从字符串重建，于是每回合都新建一个空
  planner。任务周期、冷却与 LLM 额度因此只在判题路径上保留，网页"单步"跑的其实是另一套
  策略——这也是"宝物在基准里能开、在网页里不开"的真正原因。
  修法：planner 增加 `dump()/load()`（可 JSON 往返、容忍残缺输入），`_json_safe` 对带
  `dump()` 的对象取真实数据而不是占位符，`step()` 用 `PlannerState.load` 重建。
  浏览器验证（种子 19）：第 40 回合背包买到 FlameBreath+FrostPotion，第 92 回合开启宝藏，
  面板显示"已被开启：challenger（本地奖励 +300 分 / +150 金币）"，
  与判题路径的开启回合完全一致。证据：`reports/screenshots/13-treasure-opened.png`。
  **按点刷新带来的新取舍**：任务循环变长后，部分种子（如种子 1，窗口 184–224）开拓者
  仍在任务循环里，赶不到祭坛。已加入一条**窄条件**的优先规则（只在"已买得起"或"窗口开着
  且来得及"时让宝物占用开拓者），并对种子 19 做了端到端回归；种子 1 不再断言开启，
  因为它取决于调度而不是机制。测试改为断言"传闻必须出现在请求里，且至少一个种子能走完
  购买→前往→召唤 的完整行程"。
  机器人被建筑挡住时攻击**那栋建筑**，而不是挑最近的单位。因此围墙是"拖延型护盾"而不是
  绝对屏障：被打穿的缺口会真正打开（被摧毁的建筑会从地图格上移除，0 血单位不再占格），
  后续机器人可以走进去继续逼近基地。此前围墙永远不会掉血，基地在整局中固定 1500 血；
  现在压力 3 下基地会掉到 690–1325，得分略降（例如种子 1：2305 → 2185），
  换来的是防守真正有压力、有取舍。
- **机器人攻击建筑**（任务书 §4.7.3：「机器人会攻击阻挡其移动的单位（包括角色/建筑）」）：
- **已实现并可在画面看到**：移动、采集、建造、拆除围墙、武器攻击（含加特林 90° 锥形与
  逐发弹道、电磁炮能量穿透）、小贩卖矿、商店购买、升级券升级建筑、修墙包/生命药剂、
  眩晕法宝、范围炸弹、机器人召唤令、任务领取与答案提交。价格全部来自观测，升级合法性由
  建筑类型与当前等级决定；失败指令在事件流单列，非法锥形在开火前就被拒绝。
- **接口层已实现**：`prompt` / `executeCmd` / `lastCmdResult` 的构造、解析与每日额度记账
  （任务期间不限额且不计数）；沙盒超时与判题器异常单独统计，不计入队伍异常。
- **本地夹具**：任务文本与答案键由 `taskworld.py` 生成，用于离线跑通任务链路；它不是官方
  判题器，任务分不能当作官方成绩。
- 未实现：召唤宝藏（献祭与祭坛）、官方胜负结算、官方任务文本与答案。
  未实现的功能不会在界面上做成可用外观。
- **本地双队对局（已接入界面：开发面板「双队」页）**：同一套策略引擎分别驱动两支队伍——
  双方在同一回合快照上取指令（无先手优势）、各自独立的 planner 记忆、各自独立的模拟簿记与
  判题发布字段（`phaseTask`/`playerTasks`/`lastCmdResult`）、各自的本地任务夹具、各自的
  夜战波次与分数线；结束条件是基地被摧毁或到达回合上限。整场约 100 秒，因此走后台任务：
  `GET /debug/twomatch` 取状态、`/debug/twomatch/start|stop` 启停，界面每秒轮询并显示
  双方积分、基地血量、进度与最近事件。结果标注 `local`，界面同时写明"结算顺序与异常上限
  未复现，不能当作官方成绩"。
  实测两侧分数不再被对方覆盖（同一配置下后手方与单队基准一致：2047 / 2450）。
  **仍待解决**：先手方在双队棋盘上完成的任务少于后手方（8–15 次 vs 14–20 次）。已定位原因：
  地图上任务点距基地 20+ 格，一次"往返 + 30 回合刷新"约 110 回合，1300 回合最多约 11 次，
  先手方实测 8 次已接近该上限，属于调度上限而非状态错误。曾尝试"夜间留在外面等刷新"
  （放宽与收窄两版），实测都会降低双方得分（先手 1009 → 728 → 550），已整个回退，
  并在 `docs/VIEWER.md` 记录为已验证的负面结果，避免以后重复尝试。
- 本地假设：建造区域几何（一圈武器两圈墙，外圈固定留两格大门）、波次数量与出生采样、
  机器人选敌与移动顺序、复活落点、矿点刷新位置、经济跑腿与任务跑腿的出发时机、
  任务文本与答案键（本地夹具）、弹道"在路径上"的半格判据。
- 非合规近似：同回合多单位移动按顺序结算，不是官方同时结算。

细节与证据见 [DEMO.md](DEMO.md) 的规则覆盖表与 `DEVELOPMENT_RULES.md` 的差异清单。
