# 从反馈提炼任务方法

来源：Issue #27、#28。这里记录可复用方法；官方定义以当前任务原文和规则基线为准。
Issue28列出了六个任务模板，开头“五个完成”与列表数量不一致，未附本批完整判题序列；不能据此登记六项官方通过。

## 查询与聚合

先读取当前任务的提交字段和中文说明，再读API文档。记录每个字段的类型、筛选条件、排序依据、需要返回的属性和单位。
例如题文若要求“年代最早的遗产名称”，需要用年代判断先后，并返回那条记录的名称；字段名本身可能容易误解。
不要把排序用的年代标签直接当名称。某城要求世界遗产数量，并不能推出下一城仍要求相同保护级别；逐题核对。

鉴权、参数和分页按当前文档及真实错误回执调整。一次401随后成功200属于恢复过程；HTTP200也可能带业务错误。
拿到一页10条、分页总数12条时，仍需收集其余记录并去重。字段形状与页数一致不代表聚合答案一定正确。
本地契约检查能拒绝部分可证明的字段混淆，但不会编造缺失记录、判题答案或替模型决定所有历史排序。

## 配置修复

进入题目指定工作区，读取当前spec，核对路径、行号、端口、应用名、目录和权限。只修改当前spec要求的项目，保留无关行。
确认当前check成功后，按题目格式提交实际返回的TOKEN。旧对局的校验值、任务书里的占位值和历史城市答案都不能直接复用。
明确CRLF故障可使用兼容check工具；它不修改check原件，不把此前修改链再执行一次。

## 回馈与复测

保留当前题文中的字段说明、必要的数据完整性证据、实际答案、错误字段、check退出码及任务结算观测。
无需每轮重复整张地图；同一错误应附最小闭环。每批记录包内源码SHA。公司复测仍用codex/sgh根目录CoreGeek.tar.gz。
缺少成功回执、无错误码或出现总分增长均不能单独证明该题全对；部分通过可能在任务结束时结算。
