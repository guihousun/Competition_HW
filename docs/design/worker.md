# 角色运行逻辑全景

> **现状梳理**：三个角色（工人 / 开拓者 / 夜里全员操炮）在 `plan()` 里每回合怎么决策。
> **代码是唯一权威**（`src/coregeek/game/`：胶水 = `planner.py`、白天 = `day.py`、夜里 =
> `night.py`、任务线 = `task.py`、共用底座 = `game/core.py`，通用判定在 `game/utils.py`）；
> 本文只讲"现在在跑什么"，
> 不重抄推导 —— 为什么这样设计看 `strategy.md`，逐条实测悬置看 `code-task.md` 文末悬置表。
> ⚠️ **状态机的权威在 `strategy.md` §1**（状态 / 闸门 / 转移）。本文是同一件事的"优先级阶梯"
> 切法，那里是"状态 + 转移"列表切法 —— **改判据顺序时两处都要改**，以代码为准。

## 0. 总入口 `plan(turn)`：一回合的骨架

每角色每回合**恰好一个动作**（§4.4）；`plan` 返回 `{角色id: 指令}`，唯一例外 `attack` 的 key
是**武器 id**（操控者在 `controllerId` 里）。**两段式**：下面这条判据链是第一段 `_intents`（按昼夜分派给 `_day_intents` / `_night_intents`）
（逐角色出"初步行为"——能直接干的当场落指令，走路的只交 `(角色, 目标)` 意图）；第二段
`_walk_out` 按同一顺序批量解走路意图（BFS 落一格、记落子账与路径预留账，后解的让开先落的）。
判定顺序（先命中先发）：

```
对每个角色（按 payload 顺序）：
① 开拓者 且 phaseTask 非空 ⇒ 钉死在任务点上（昼夜无关，永远最先；夜里一个工人都没有时例外，见 §3.1）
② 第 0 级 收工门 `day.BACK_TO_POST`：**只有这一夜的炮手走它**，且
   `回岗步数 + POST_MARGIN(3) ≥ 白天剩余` ⇒ 回那个共用的操作位（步数实时算）
②′ `night.hold_the_wall`：**这一夜的修墙工**（`night.repairer`）同样到点先回待命位
   （正面墙后方那一列，`core._wall_post`）—— 天黑才发现人还在盒外就来不及了
③ 白天·开拓者：有任务点就去接（`task.take_task`）；全空 ⇒ 跑"买券 → 立刻用"的差事，
   都没得干 ⇒ 去最该等的地方站着（`day.wait_errand`）
④ 白天·工人：走 `day.DAY_CHAIN` 那几级 —— 建武器（1）→ 建墙（2）→ 攒修墙包（2.5，第 3 天起）
   → 挖矿买券（3）
⑤ 夜里 ⇒ 基地残血升级（券链里已无基地券 ⇒ 暂时进不去）→ **持包的那个工人**守着正面列修墙
   （第 4 夜起，`night.repair_wall`）→ **其余炮手之外**的工人出门采矿
   → 炮手一个人走到那个共用操作位开火（`night.defend`）；**清场了整条换挡**走白天那两条线
   （工人 `day.sell_or_mine`、开拓者回 ③ 那一支 `planner._pioneer_errand`）
```

**无任务模式**（`turn.tasks_exhausted` = 两个任务点都 `coldDownRounds == 0` 且 `isValid is False`）：
白天工人只干"矿 → 金币"（`day.sell_or_mine`：攒够一趟就背去卖，够本门 = 货值 ≥ 2 × 到小贩的步数；
否则接着挖），**买卖券全归开拓者**。⚠️ **夜里两套模式已经合成一条**（第 130 步：三座全是火箭、
一个角色操全，与有没有任务无关）—— 旧口径的 `planner._no_task_night` 整段删了。判据每回合现算，
又出现可接的点就自然退出。

**回合内黑板**（`_day_intents` 现算、**不跨回合** —— 跨回合标志位卡住会静默关掉整条线；
第 93 步起下面除了 `claimed` / `assigned` / `paths` / `segments` 之外全装在 `_Ctx` 里，
**一个回合只有一个 `_Ctx`**：循环外构造一次、循环里所有角色共用，挪进角色循环黑板就散了）：

| 账本 | 内容 | 谁写谁读 |
|---|---|---|
| `claimed` | 本回合已认领的**落脚格**（两人冲同一格双双停住，§4.5.4） | 所有 `move` |
| `sites` | 已认领的**建造格**（武器与墙共用；别走到建造格上） | 建造线 |
| `taken` | 已认领的**武器**（组内任一座被认领 = 整组被认领；收工闸门也用它认领那个操作位） | 操炮线 |
| `demolish_taken` | 已认领的**待拆 L1 弱墙格**（两个工人不拆同一面） | `day._demolish` |
| `segments` / `ore_taken` / `budget` | **环缺口按在场工人数切段**（A 前段 B 后段沿环推进）、**矿格认领**（B 就近换一座）、**金币预留**（认领即预扣，下一座才不超支） | 砌墙/采矿线 |
| `paths` | **路径预留**（第二段：后处理的工人整条让开先处理的路） | `_walk_out` |

公共机制：

- **两个距离口径**（`grid` / `path` 的 docstring）：`Pos.dist`（切比雪夫）**选点**——挑最近的矿/小贩/炮位；
  `steps_between`（BFS 绕障）**回合预算**——所有"来不来得及"的账，`-1`（不可达）⇒ 这趟不去。
  ⚠️ **`0` = 已经贴着目标**（"还要走几步才贴上"）⇒"我贴着小贩/商店了"是 `== 0`，写成 `<= 1`
  就是离两格就发指令 = **非法指令**（`day._sell_cargo` / `day._walk_to_shop` / `day._walk_to_use` 那三处）。
- **两套地形口径别混**：全部**估算**走 `_passable(turn)` = `map.blocked` **剔掉我方角色**
  （"自己人算路过"）；`_Queue.step` / `_walk_out` 那边**必须把同事当硬障碍**（撞上是执行失败）。
  估算里不剔才是重病：环砌满后盒内只剩一格宽的走廊，同事停在走廊上 ⇒ 每座矿都算出 -1 ⇒
  整段放弃、**工人一整天一条指令都不发**。
- **`_Queue.step` 是所有走路的公共出口**（provider 型意图除外）；`avoid` 是**软**的（绕不开退回
  硬障碍，绝不原地卡死）；**动身成功才预留路径**（`_reserve_path`）。
- **`_emit`**：动作在 Action 构造函数里过权限闸门，越权只丢这一条并告警，不连坐同回合其他角色。
- **移动决策完全无状态**，每回合从 payload 重推；跨回合状态只有 `AGENT` 单实例上的几处
  （SOP 流程表 / 任务内会话 / 新闻指纹）、`_fired`（火箭冷却本地账）、
  `core._collected`（本地采矿账）、`core` 的**10 天矿价表**（第 149 步：新闻钉住的未来天）
  与 `cmd_explore` 的探查状态 —— 逐条住址见 `CLAUDE.md`。

## 1. 工人决策

### 1.1 白天（`turn.is_day`）

**0、收工门 `day.BACK_TO_POST`（第 0 级，链之前）**

- 0.0、**只有这一夜的炮手走它**（`role.id != _night_gunner(turn)` 直接 `False`，`utils._night_gunner`）：
  工人白天在矿边干到天黑、不回炮位（他们夜里接着挖）。
- 0.1、`回岗步数 + POST_MARGIN(3) ≥ 白天剩余` ⇒ **回那个操作位**。步数是**实时 BFS**
  （`_steps_to_post`，与挑岗位同一个口径 —— 回岗要走多久就得多早动身），也不问环砌完没有，
  **券也不参与判据**（手里握着券照样按步数走）。目标与夜里 `night.defend` 同一个
  （`_post_spots`：多座组 = 共用的操作位、要站上去；单座组 = 炮旁）。
- 0.1′、**手里的武器券优先于开火**（第 168 步，用户口径「优先升级武器再操作攻击」）：
  贴着可升的那座 ⇒ `use`（`day.use_voucher_here` 逐个链上步骤找贴手的）；只差 ≤3 步 ⇒
  `day.walk_to_upgrade` 朝它走一步，**这一回合不开火**；再远就不追。
- 0.2、已经在岗（步数 0）⇒ **先用券**（`day.use_voucher_here`：手里的武器券 / 墙券、目标贴着就 `use`；
  夜里那条链也调它 —— 第 161 步），
  用不上就待命（什么都不发 = 合法空指令）。
- ⚠️ **这一支只发 `move`**，绝不可复用 `night.defend` —— 那会发 `attack`，而 `attack` 仅黑夜
  ⇒ 白天发就是**非法指令**（红线）。守门：`DayEndGateTest.test_a_day_round_never_fires`。
- ⚠️ 判据与夜里 `night.defend` **同源**（`utils._night_gunner` 一处说了算）：只改一处会出现
  "白天送它进岗位、夜里又没人认领"或"白天没人回岗、夜里第一回合炮位空着"。

**1、建武器（第 1 级）—— 完备之前永远停在这一级**

- 1.1、**完备** = `day.slots(turn)` 产出不了名额（份额 = `len(角色) − len(武器)`，落点必须是空的）。
  完备 ⇒ 到 2。
- 1.2、不完备：
  - **1.2.1、钱够建满**（`can_build_all`：回合开始时的 `turn.gold ≥ 25 × 缺数`）⇒ `day.assign_sites`
    把这批落点分给两个工人（枚举划分，取"最后一个建完的回合最早"的那份），各自认领、预扣金币、
    走过去或就地 `build`。
  - **1.2.2、钱不够**（且地图上有小贩、有价可卖）⇒ **两个工人一起挖最贵的矿**（`core._priciest_ore`）；
    当**团队金币 + 两人背包里矿的价目总值 ≥ 缺口**时，各自把货背去小贩那儿卖掉，钱到账后下一回合
    由 1.2.1 接着建。没小贩 ⇒ 凑不出钱，落回第 2 级。

**2、建墙（第 2 级）—— 武器齐了才轮得到，只看 L1**

- 2.1、**不完备**有两种：**缺口**（那一格没墙）、**L1 弱墙**（`day._weak_l1`：`level == 1` 且
  `core.needs_repair` = `0 <= health < core.wall_repair_hp(turn)`（第 1–4 天 200、第 5 天起每天 +50）⇒ 直接拆了重砌：1 块石头换满血，
  比 20 金的升级券便宜）。这个阈值与**夜里的修复线共用一处**（`core.needs_repair`）。
  L2/L3 的损伤**不阻塞**这一级（升级券顺带回满血，夜里还有 `night.repair_wall` 用修复包）。
  `need = 本段缺口数 + 该拆的弱墙数`，`need == 0` ⇒ 到 2.5。
- 2.2、石头不够（`role.stone < need`）⇒ 挑一趟**最省回合**的采石（`day._mine_stone`：比较各座石矿的
  `去 + 回` BFS 步数），采够了回工地；**一座能用的石矿都没有 ⇒ 拿手里那点石头先砌**（能做多少做多少）。
- 2.3、石头够 ⇒ **先补缺口、后拆弱墙**：缺口是夜里机器人进来的门，弱墙好歹还挡着（拆完砌不回来
  就是白开一个洞，所以没石头不拆）。砌墙沿用三条边角规则（贴着就 `build`、站在目标格先挪开、
  环上只剩最后一格就从盒外砌）。**采量不留存货**（旧口径的 `STONE_RESERVE` 删了）。

**2.5、攒修墙包（第 2.5 级）—— 第 3 天起，只由名册里最后一个工人跑**

- 2.5.1、修墙包（`WallFixer`，10 金）是**夜里**那条修复线要用的消耗品 ⇒ 白天先把存量补到 3 张
  （`day.RepairStock` → `day.repair_errand`）。**只由名册里最后一个工人跑**：包不能转手（谁买谁用），
  夜里背着包的那个工人就是修墙工，两个人各跑一趟等于白花一倍回合。
- 2.5.2、**顺路优先**：已经贴在商店旁 ⇒ 当场买（额外走路 0）；一张都没有时才肯专程跑一趟，且要求
  `2 × 到店步数 + 1 <= 白天剩余`。买不起（价目查不到 / 钱不够）⇒ 返回 `False`，让第 3 级接着挖矿。
- 2.5.3、⚠️ 券的差事要**先给「修墙那两个开销」留出预算**（`day._wall_reserve` = 还缺的包 +
  **一张**墙券）：开拓者在名册里排在工人前面、买券又是"尽可能多买"，不先留一手那点钱会被
  一次吃光（第 143/156 步）。

**3、挖矿买券（第 3 级）—— 武器与环都完备之后**

- 3.1、挖**实际单价最高**的矿（`core._priciest_ore`：`单价 × 剩余 / (剩余 + 去 + 回)`，剩余数来自
  本地账 `core._collected`）；动身前先看顺路卖矿 `_detour_sell`（贴着小贩就当场 `sell`）；贴着矿就 `core._collect`（它记账）。
  单价走 `ahead=0` = **当天实测价**（第 149 步：白天采的货当天就可能卖掉，不看预报）；
  今天是停工日的矿种整个不进候选（`core._mineable`）。
- 3.2、券按 `VOUCHER_CHAIN` 取**第一个还有东西可升**的步骤（第 146 步起**只有武器三步**：
  非角火箭 2 级 → 同两座 3 级 → 角上火箭 2 级；它是目标清单，不跳级去买更便宜的券）。
  ⚠️ **墙券不在这条链里**（`core.WALL_CHAIN` 四步：中间三格→2 → 边上三格→2 → 中间三格→3
  → 边上三格→3）：它归修墙工那条差事（见 §2.5）。
  步骤里挑哪一格由 `day._step_targets` 定：**血少的在前**（升级当修），同血取坐标序，
  **血量未知（-1）排最后**。⚠️ 同一张券名在链上出现两次 ⇒ 手里那张券打谁要**从步骤里取**
  （`_targets_for`），不能只看券名。
- 3.3、手里的券 ⇒ **立刻走到目标用掉**（买完就用，攒几张就一张一张用）；买得起 ⇒ **按需要买够**
  （张数 = `min(还升得动的目标数 − 全队手里已有的 − 本回合已预扣的, 金币 ÷ 券价)` ⇒ 一条
  `buy num=N`），预扣券价 × N 后朝商店走；现钱 + 背包货值够 ⇒ 先去卖；背包里售价最高的那种
  攒过 `BAG_SELL_AT`(15) 件 ⇒ 先去卖；其余 ⇒ 接着挖。全升满了 ⇒ 链尾：继续挖矿。
- ⚠️ **第 3 级的前提是武器建满**（`weapon_gap` 为真就整条不跑）；**差事走不通时一律落回挖矿**，
  绝不干等。

### 1.2 黑夜（`not turn.is_day`）

**1、基地升级 `night.upgrade_station`**（任何角色，持券即可）

- 1.1、包里持有基地升级券、且基地血量 < 满血 1/4（`STATION_MAX_HP` 1500/3000/4500）⇒ 贴到基地
  旁边 `use`（升级 + 回满血一次到位）。**当回合放弃开火** —— 只在基地真残血时才值得。
  ⚠️ 第 130 步起**券链里没有基地券** ⇒ 这条实际进不去（代码留着，改了链就复活）。

**1.5、修墙 `night.repair_wall`（第 4 夜起，第 142 步）**

- 1.5.1、谁去：`night.repairer` —— **非炮手的工人里手里真有修复包**的那个（包多的优先、并列按 id）。
  **一个包都没有 ⇒ 不派**（那个工人照旧走下面的 2 出门挖矿）。
- 1.5.2、干什么：正面列（`core.front_wall_cells`）里血 < `core.wall_repair_hp(turn)` **且够得着**
  （有活机器人切比雪夫 ≤ `ROBOT_RANGE`(3)）的那一格，取血最少的 ⇒ 贴着一格内出手：**手里有
  打得上的墙券先打券**（`night._front_voucher`：升级顺带回满血，比包值），没有券才用 `WallFixer`；
  没有要修的 ⇒ 守在**正面墙靠基地那一列**的待命位（`core._wall_post`：零步够着 3 格，
  两个角格要 1–3 步）；待命位也走不到 ⇒ 出门挖矿，不原地干等。
- 1.5.3、⚠️ **被打穿的墙它救不了**（血 0 的那格在 `model._walls` 就丢了、夜里又不能 `build`）
  ⇒ 那是白天 `_ring` 的缺口账。只发 `move` / `use`。

**2、炮手之外、且我是工人、且没被派去修墙 ⇒ `night.mine_ore`（第 119 步，独立的一条线）**

- 2.1、去采**实际单价最高**的那座矿（与白天第 3 级同一个 `core._priciest_ore`：`单价 × 剩余 /
  (剩余 + 去 + 回)`，剩余数来自本地账 `core._collected`；贴身了就 `core._collect`），囤到第二天
  由白天那条线卖掉。**不卖、不买、不回炮位**；只问"走得到吗"（BFS -1 剔掉）。
  ⚠️ **第 163–166 步起不再"连时间预算都不算"**（用户报"夜里在采矿、一到白天就转去修墙"）：
  ① **挑矿带预算**（`night.mine_budget` = 本段剩余回合 − `POST_MARGIN`）—— 能整块采完的矿优先，
  连"走到 + 采一块"都塞不进的矿直接不选；② **最后 `回基地步数 + POST_MARGIN` 回合改走回程**
  （`night.walk_home`：朝基地走、到家待命，不再折返回矿）—— 天亮那趟回程因此落在夜里，
  白天那 70 个回合（砌墙的硬截止）全留给正事；③ **路上脚边有矿就顺手采一块**
  （`core._on_the_way_ore`：一趟 1 次、吃 `POST_MARGIN` 的余量、不认领矿格；缺石时优先采石；
  停工的矿不顺手采）。
  ⚠️ 单价走 **`ahead=1`**（第 149 步：今夜采的货**明天**才卖 ⇒ 按**明天**的期望价挑，
  那是它与白天那条**唯一的差别**）；可采性照旧只看**今天**（`core._mineable`）。
  ⚠️ 回程那一项在挑矿里仍只是个**分母**（第 119 步那个"回不来 ⇒ 一座矿都不可行 ⇒ 整夜空转"的
  冻结不会重现）—— 回程由 `walk_home` 兜底，不塞进筛选。
- 2.2、⚠️ **机器人还活着时按 `night._safe` 挑矿**（第 130 步，用户口径"保证安全"）：
  `_passable` **再加上每个机器人周围切比雪夫 ≤ `DANGER`(2) 的格子、以及它朝基地推进的那条走廊**
  （第 170 步：往前 `LANE_AHEAD`(8) 格 × 每格让开 `LANE_HALF`(1) 格）⇒ 矿被机器人占着、或正在它
  要经过的路上就换下一座；**脚边已经不安全就先撤一格**（`night.flee`：站在走廊上 / 机器人在
  2 格内 ⇒ 原地 + 8 邻格里挑"不在走廊上、离机器人最远"的一格，没有更安全的就待命）；
  迈步那一步把它们当**软避让**（绕不开照走，绝不为躲机器人原地卡死）。
- ⚠️ **为什么与白天那条分成两条**：两条都走 `core._priciest_ore`（同一个排序），差别只有两处 ——
  白天那条动身前会看一眼**顺路卖矿**、挖到的货是拿去凑券钱的，夜里这条**不卖不买**；
  单价一个按**今天**（`ahead=0`）、一个按**明天**（`ahead=1`，货要到第二天才卖）。
- ⚠️ 夜里 `build` / `remove` / `sell` / `buy` 一律不发 ⇒ 这一支只可能出现 `collect` / `move`。

**3、炮手 ⇒ `night.defend`**，见 §4。⚠️ **这一夜只有一个人操炮**（`utils._night_gunner`：开拓者
没被任务钉死就是它，否则名册第一个工人）—— 三座火箭共用一个操作位，一个人站上去轮转就够。
判据与白天收工闸门**同源**（§1 第 1 项）。

**换挡：清场了 ⇒ 整夜走白天那两条线**（`night.is_cleared` = 没有还会打我方的活机器人，第 85 步）：
工人 `day.sell_or_mine`、开拓者走白天 ③ 那一支（`planner._pioneer_errand`：接任务 / 买券 / 等刷新；
⚠️ 它会发 `acceptTask`，而"夜里能不能接任务是赌的"见 `code-task.md` 表 #73）。⚠️ 判据不是"场上全空"：机器人**全图可见**
（L95）⇒ 对方那一波也在 `turn.robots` 里、我们从不打它（`_fire` 同样过 `_foe_robots`）⇒ 照全空判
的话对方机器人活多久，工人就在炮位上钉多久。

## 2. 其他总纲

### 2.1 建墙逻辑

- **U 形，背面整列空出来当通道**：**正面列 6 格 + 上下两行各 4 格 = 14 格**，背面那 6 格全空
  （`wall_cells` 与 `door_cells` 同源，方向判据在 `grid._front_back`，**只此一处**）；
  第 3 天起（`_sealed_back`：`round_no > 2 × ROUNDS_PER_DAY`）补**背面两个角格** = 16 格，
  通道从 6 格收到 4 格。补角格**没有新机制**：`_ring` 按 `sealed` 取候选、已砌的 14 格被
  `blocked` 滤掉 ⇒ 只剩那两格。
- **`wall_cells` 的顺序 = 正面列（迎着机器人）→ 下行 →〔背面两角〕→ 上行** ⇒ 回合不够时自然
  优先砌面向敌人的方向，零新机制（`_ring` 保序、`day.WallLine` 取本段第一格）。
- **`_ring` 的例外**：候选墙格要排除 `blocked`，但**我方角色站的那一格除外** —— 否则"谁站在
  待砌的墙格上"会让那格从候选里消失，另一个工人的目标跟着后移、等人一挪窝又变回来 ⇒ 两人在
  两格之间对着改目标转到天黑，一格都砌不上。
- **`_walled` 只把"站在后方通道那几格"的自己人算障碍**（与 `_ring` 故意相反）：那圈墙里没有
  任何建筑 ⇒ 能堵门的只有单位，"自己人站在格子上"只在门口有意义；环内站着的是**过路的**。

### 2.2 武器逻辑

- **三座、种类与落点绑死**：`WEAPONS_BY_SITE = ("rocket", "rocket", "rocket")`（第 130 步，用户口径），
  下标与 `weapon_sites()` 一一对应 —— 前两个是**非角上**那两座、第三个是**角上**那座（券链的五步
  按这个分家）；落点**全在正面列**。三座共用一个操作位 ⇒ **一个角色站上去就能操满 3 座**
  （火箭 3 回合冷却 ⇒ 在炮之间轮转）。
- 落点由**己方 station 的 `pos` 推导**，禁止绝对坐标（换边后基地会挪）；基地 2×2 的展开以
  `grid.base_cells` 为准。
- 份额 = `len(roles)`，上限取**保守的全局 ≤3**（原文自相矛盾，取"武器只有建三个才有意义"）。

### 2.3 兜底

- **任何一级都发不出指令 ⇒ 空指令** `{"roleCommandMap":{}}`，合法、不计异常。
- **时间预算一律走 BFS**（`steps_between`），`-1`（不可达）一律当"这趟不去"，**不为估算去改
  `step_toward` 的契约**。

## 3. 开拓者（Pioneer）

### 3.1 被任务钉死（最高优先，昼夜无关）

`phaseTask` 非空 ⇒ 每回合只做一件事：`task.answer_task` 把 `AGENT.take_answer()` 取走的那份答卷
（= 本回合 `submitAnswer` 工具调用的 `answer` 参数，取走即清）用 `actions.SubmitAnswer` 交上去
（**每回合都交** —— 判题器取"通过率最高"的那份，重交零成本；空答案不发）。**一步都不挪**：
离开任务点周围一格（切比雪夫 ≤1）任务立即作废 ⇒ 它连夜里都不回炮位。

**例外：夜里一个工人都没有 ⇒ 弃任务回炮位**（用户口径"生存第一"）。判据 `_short_handed` =
**夜里且名册里一个工人都没有** —— 没人能顶炮位，那个被钉住的人就是唯一的火力。**白天恒假**
（白天不能开火、回炮位只发 `move`）⇒ 这一支与本判据都不带跨回合状态，工人白天复活后自愈。
代价是任务当场作废（"离开任务点一格"），这是用户明确要的取舍：任务积分换一门火力。

### 3.2 白天接任务 `_take_task`

贴着最近一个**能接**的任务点（切比雪夫 ≤1）就 `acceptTask`；否则朝它走一步（`step_toward` 天然
停在贴着的一格 —— 任务点挡路，"走过去"与"停在接取位"是同一件事）。判据来源是
`teamOur.playerTasks`（只含我方两个点）。⚠️ **不走去冷却中的点蹲守**（那是 `wait_errand` 的活，
见下）。

### 3.3 真空闲（任务点全空）—— 白天，以及**夜里清场之后**（两支共用 `planner._pioneer_errand`）

跑"买券 → 立刻用"的差事（`day.voucher_errand`，与工人那条**各自独立跑**）。⚠️ 规则限制：
`collect` 仅工人、**没有转移物品的指令** ⇒ 开拓者背包里通常没矿，"攒钱"那一半它跑不起来
（`_mine_for_voucher` 对非工人直接返回 False），能做的只有"买"和"用"。
⚠️ **差事也没得干 ⇒ 去最该等的地方站着**（第 130 步，`day.wait_errand`）：冷却中的任务点里
**刷新最快**的那个 → 一个都没有就去武器商店（并列取坐标序）；到了就待命。

### 3.4 夜里（没被钉死时）

跟所有人一样走夜里分支（§4）：基地残血持券先升级（券链里已无基地券 ⇒ 暂时进不去），否则看
**炮手**那条判据 —— 它没被任务钉死 ⇒ 它就是这一夜的炮手（工人顶上只因它被钉死）。

## 4. 夜里共同：操炮防守（`night.defend` / `night._fire`）

`night.defend` **只被喂一个角色**：`utils._night_gunner` 指定的那一个（开拓者没被任务钉死就是它，
否则名册第一个工人）—— 其余工人整夜在盒外挖矿（§1.2 的 2）。三座全是火箭、共用一个操作位，
一个人站上去按冷却轮转就够。

认领最近**未被本回合别人认领**的一组武器（`_weapon_groups`：三座火箭并成一组；组按
`weapon_sites` 的下标分，不按种类猜），**先开火、打不了才挪岗**：

- **贴着组内某座** ⇒ 认领整组、开火。就绪的先挑（含本地开火账），就绪的并列按 `round_no`
  轮转，都冷却 ⇒ 一发不发。**只贴一座也打** —— 另一座就绪而这座在冷却时别白丢一回合。
  ⚠️ 这一支**排在岗位判据之前**（第 77 步）：岗位格被占 / 走不到都不是"这一组不用管"，
  旧顺序让"贴着炮但岗位格被占"的角色跟着整组一发不打（用户报的死锁）。
- **整组的岗位都站着、又都打不了** ⇒ **原地待命，不换组**（每回合重挑会让角色在炮位之间来回走）。
- **只贴着一部分 / 压根没贴着** ⇒ 朝岗位挪一格（走不到就换下一组）。
- **主岗位一个都站不上**（共用操作位被机器人踩死 / 后方通道那三个门格被堵）⇒ 退到 `_near_spots`
  指的格子（贴着组内**任意一座**），只守得了一座也照打 —— 退路**排在主岗位全试完之后**。
- `round_no` 缺失（-1）⇒ 一发不发：缺失被 `is_day` 判成夜里，对"白天不许建造"安全、对"白天
  开火非法"就是反的。

⚠️ **岗位 = `_post_spots`**：多座组 = 同时贴着组内所有座的**空地**（要踩上去 ⇒ `path.step_onto`；
`step_toward` 的契约是"贴着即到"、停不进这种格子，会原地卡死）、单座组 = 那座炮本身。
**自己人一律不算障碍**（`model._entries` 把我方角色写进网格 ⇒ 不放行的话，站在岗位上的操作者
看不见自己的岗位、整组被跳过 —— "敌人进了射程不打"的根因）；**别人站着的那格要让开**
（换一组，否则一个走不进去、一个干等着）。

`_fire`（方针：**打死所有机器人**，按**最大伤害落点**）：

- **冷却中不打**：payload 的 `cooldown` 优先；火箭字段缺失（-1）时查**本地开火账** `_fired`
  （跨回合观测状态：发出 `attack` 那回合记武器 id，之后 `ROCKET_COOLDOWN`(3) 回合不选它，
  期满自动过期 —— 打冷却炮是指令执行失败、白丢一回合火力）。加特林/电磁恒 0，不查本地账。
- **只打打我方的机器人**（`_foe_robots`）：`target_team` 为空或 `== our_team` ⇒ 打；明确打对方
  ⇒ 跳过（打它们既浪费火力、又帮对方减轻基地压力）。`our_team` 缺失 ⇒ 不过滤、全部照打（安全降级）。
- **逐发/逐枚挑目标**（`night._volley` 一处分派三条线）：评分 = Σ `min(伤害, 剩余血) × 权重`，
  权重 = `TIER_VALUE`（小/中/大/BOSS = 4/3/2/1，用户口径"优先攻击最低级的机器人"；`kind` 缺失当最低级）
  × **贴墙加成**（`WALL_THREAT_NEAR` ×1.5 / `WALL_THREAT_HURT` ×2：啃的是一格残墙）
  ⇒ 并列取近的、再按坐标序。⚠️ 4/3/2/1 与 1.5/2 都是拍的（`code-task.md` #97/#98）。
  - **火箭 `_rocket_volley`**：候选 = 机器人格及其 8 邻格、落点须在射程内（**溅射可以够到射程外的
    机器人** —— 射程只管落点）；每枚挑总分最高的落点、扣血再挑下一枚。**指哪打哪、不被弹道阻挡**；
    越界格不进候选（越界落点 = 指令非法，红线不让赌）。
  - **加特林 `_gatling_volley`**：落点在机器人身上，命中的是**弹道上最近的那台**（`_first_on_line`）。
    多目标必须落在**同一 90° 锥形**内（任务书 L250，越界**整次攻击非法**）⇒ 自查按 ≤45° 卡
    （`_in_cone`），加不进新目标就用第一格补齐。
  - **电磁 `_railgun_volley`**：单目标，按**沿弹道穿透**总和挑那一格（`_pierce`：共线的按距离排队、
    各吃 `min(剩余能量, 血)`）。
- **等级放的是发数/枚数**（`GATLING_SHOT`(10) / `ROCKET_CENTER`(20) / `ROCKET_SPLASH`(10) 都是
  每发的 L1 值）：`targetPos` 的**份数 = 等级**（电磁恒 1 —— 接口文档 L218，发错是指令非法）；
  **电磁的等级翻的是能量**。旧的"多发同点"（"最小合法化"）已作废。
- ⚠️ **没有跨炮的伤害记账**（第 130 步删了 `assigned`）：一个炮手一回合只发得出一座 ⇒
  "同回合两座挤同一个将死者"这回事不存在。
- 机器人 `health` 缺失按"还活着"算（打空处只是执行失败、不计异常；"一律不打"会让整晚哑火）。

## 6. 实测锚点与已知薄弱处

  （悬置 #21 就地写明）。

  门格 `(8,23)/(8,24)/(8,25)` —— 队友/机器人停在那几格上时 BFS 判不可达 ⇒ 这一步不走（收工门
