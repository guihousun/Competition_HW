# 角色运行逻辑全景

> **现状梳理**：三个角色（工人 / 开拓者 / 夜里全员操炮）在 `plan()` 里每回合怎么决策。
> **代码是唯一权威**（`src/coregeek/game/planner.py`，下称 planner；白天工人链在
> `game/states.py`，通用判定在 `game/utils.py`）；本文只讲"现在在跑什么"，
> 不重抄推导 —— 为什么这样设计看 `strategy.md`，逐条实测悬置看 `code-task.md` 文末悬置表。
> ⚠️ **状态机的权威在 `strategy.md` §1**（状态 / 闸门 / 转移）。本文是同一件事的"优先级阶梯"
> 切法，那里是"状态 + 转移"列表切法 —— **改判据顺序时两处都要改**，以代码为准。

## 0. 总入口 `plan(turn)`：一回合的骨架

每角色每回合**恰好一个动作**（§4.4）；`plan` 返回 `{角色id: 指令}`，唯一例外 `attack` 的 key
是**武器 id**（操控者在 `controllerId` 里）。**两段式**：下面这条判据链是第一段 `_intents`
（逐角色出"初步行为"——能直接干的当场落指令，走路的只交 `(角色, 目标)` 意图）；第二段
`_walk_out` 按同一顺序批量解走路意图（BFS 落一格、记落子账与路径预留账，后解的让开先落的）。
判定顺序（先命中先发）：

```
对每个角色（按 payload 顺序）：
① 开拓者 且 phaseTask 非空 ⇒ 钉死在任务点上（昼夜无关，永远最先；夜里人手不够例外，见 §3.1）
② 白天 且 在 leaving 里（砌满墙会被关住）⇒ 先迈出盒子一步
③ 白天 且 有人被关 ⇒ 工人去拆一格放人（_rescue）
④ 夜里 ⇒ 基地残血升级 → 怪清完工人跑经济兜底 → 其余角色认领一组武器、站上岗位开火（_defend；
   开拓者是**补位炮手**：工人够操满所有组时它一组都不认领）
⑤ 白天 且 环已砌完 且 回岗位来不及 ⇒ 收工，只发 move（BackToPost；开拓者同上，不让位）
⑥ 白天·开拓者：有任务点去接（_take_task）；全空则跑腿买券 → 卖矿兜底
⑦ 白天·工人：建武器 → 筹资 → 安全闸门 → 砌墙 → 修墙 → 经济兜底
   （= `DAY_CHAIN` 那一组状态类，从上往下第一个 run 返回 True 的说了算；详见 §1）
```

**回合内黑板**（`_intents` 现算、**不跨回合** —— 跨回合标志位卡住会静默关掉整条线；
第 93 步起下面除了 `claimed` / `assigned` / `paths` / `segments` 之外全装在 `_Ctx` 里，
**一个回合只有一个 `_Ctx`**：循环外构造一次、循环里所有角色共用，挪进角色循环黑板就散了）：

| 账本 | 内容 | 谁写谁读 |
|---|---|---|
| `claimed` | 本回合已认领的**落脚格**（两人冲同一格双双停住，§4.5.4） | 所有 `move` |
| `sites` | 已认领的**建造格**（武器与墙共用；别走到建造格上） | 建造线 |
| `taken` | 已认领的**武器**（夜里一人**一组**：组内任一座被认领 = 整组被认领；收工闸门也用它认领岗位） | 操炮线 |
| `assigned` | 每台机器人**已被许掉的伤害**（先开火的记账，后开的按剩余血挑目标） | `_fire` |
| `repair_taken` | 已认领的**待修墙格**（两个修墙工人不挤同一面） | `RepairWalls.run` |
| `segments` / `ore_taken` / `budget` | **环缺口按在场工人数切段**（A 前段 B 后段沿环推进）、**矿格认领**（B 就近换一座）、**金币预留**（认领即预扣，下一座才不超支） | 砌墙/采矿线 |
| `paths` | **路径预留**（第二段：后处理的工人整条让开先处理的路） | `_walk_out` |

公共机制：

- **两个距离口径**（`grid` docstring）：`Pos.dist`（切比雪夫）**选点**——挑最近的矿/小贩/炮位；
  `steps_between`（BFS 绕障）**回合预算**——所有"来不来得及"的账，`-1`（不可达）⇒ 这趟不去。
  ⚠️ **`0` = 已经贴着目标**（"还要走几步才贴上"）⇒"我贴着小贩/商店了"是 `== 0`，写成 `<= 1`
  就是离两格就发指令 = **非法指令**（`_sell_ore` / `RepairWalls.run` / `_upgrade_line` 三处）。
- **两套地形口径别混**：全部**估算**走 `_passable(turn)` = `map.blocked` **剔掉我方角色**
  （"自己人算路过"）；`_Queue.step` / `_walk_out` 那边**必须把同事当硬障碍**（撞上是执行失败）。
  估算里不剔才是重病：环砌满后盒内只剩一格宽的走廊，同事停在走廊上 ⇒ 每座矿都算出 -1 ⇒
  整段放弃、**工人一整天一条指令都不发**。
- **`_Queue.step` 是所有走路的公共出口**（provider 型意图除外）；`avoid` 是**软**的（绕不开退回
  硬障碍，绝不原地卡死）；**动身成功才预留路径**（`_reserve_path`）。
- **`_emit`**：动作在 Action 构造函数里过权限闸门，越权只丢这一条并告警，不连坐同回合其他角色。
- **移动决策完全无状态**，每回合从 payload 重推；跨回合状态只有 `AGENT` 单实例上的几处
  （SOP 流程表 / 任务内会话 / 价格期望）与 `_fired`（火箭冷却本地账），都在任务线或操炮线。

## 1. 工人决策

### 1.1 白天（`turn.is_day`）

**0、前置闸门（排在一切差事之前）**

- **0.1、我自己会被关住**（`_trapped`：假设墙砌满 `_walled` 后 `step_outside` 出不去）且现在
  静态障碍下迈得出去 ⇒ 只发一条 `move` 迈出防御盒子一格，本回合结束。迈不出去（已被关死，
  比如门让机器人堵满）⇒ 不占这一支，落到 0.2。
- **0.2、有人被关在盒子里**（`_rescue`）⇒ 工人去拆一格放人。`remove` **唯一**的调用点。
  五道门全过才动手：**环已砌满**（`_ring` 非空即退）／本回合还没拆过（`q.claimed`）／
  手里有石头／`day_rounds_left > HOLE_MIN_LEFT`(30) ／真有人 `_stuck_inside`。
  候选格 = **`turn.walls` 里真有墙的格**中"开了真能让某个被困的人迈出去、且离我最近"的那一格
  （并列取坐标序）；贴着就 `remove`，隔着就朝它挪一格。
  ⚠️ 只认 `turn.walls`：`wall_cells` 是几何，没砌的那一格被机器人踩着照样挡路，照它拆 = 白丢
  一回合。⚠️ `_stuck_inside` 里**自己人一律不算障碍**（同事站在通道格只是路过，算成障碍会白拆）。

**1、收工闸门 `BackToPost`（环砌完才生效；挂在工人链之前，不在 `DAY_CHAIN` 里）**

- 1.1、环没砌完（`_ring` 非空）⇒ 跳过，继续干活（**补墙优先于收工**）。
- 1.2、环砌完了 ⇒ 算到"我那一组岗位"的 BFS 步数（`_steps_to_post`；多座组的岗位是空地、要站
  上去 ⇒ 结果 +1）：
  - 1.2.1、步数 **≥ 白天剩余 − `POST_MARGIN`(3)** ⇒ 认领那一组、只发 `move` 回岗位，本回合结束。
    已在岗（步数 0）⇒ 在岗待命（什么都不发 = 合法空指令）。
  - 1.2.2、还有富裕回合 ⇒ 照常干活。
- ⚠️ **这一支只发 `move`，绝不调 `_defend`** —— 那会发 `attack`，而 `attack` 仅黑夜 ⇒ 白天发就是
  非法指令（红线）。守门：`DayEndGateTest.test_a_day_round_never_fires`。
- 目标是"**岗位**"而不是"最近炮位"是有意的：天黑时人已经站在共用操作位上，夜里第一回合就能
  交替开火。
- ⚠️ **开拓者不走这一支**（`_pioneer_mans_guns` 为假 ⇒ 直接 `False`）：工人够操满所有组时，炮位
  全留给工人。判据与夜里 `_defend` **同源** —— 只拦一处的话，白天把它送进岗位（火箭对只有一格
  岗位）、夜里它又不认领，那格被占着、整组没人操。

**2、建武器 `BuildWeapons` / 筹资 `RaiseForWeapons`（最高优先级：无论哪一天，武器没了先建）**

- 2.1、判定武器是否完备：`_slots` 产出名额 = `len(角色) − len(场上武器)`，落点取自
  `weapon_sites`、**必须是空格**（建在已有武器上会把它覆盖成 level1，25 金币打水漂还降级）、
  必须白天、基地在。
  - 2.1.1、没名额 ⇒ 到 3。
  - 2.1.2、有名额：
    - **2.1.2.1、钱够**（本轮可用金币 `budget` ≥ 25）⇒ 认领落点（**预扣 25 金**、登记 `sites`），
      贴着落点（切比雪夫 ≤1）直接 `build`；否则只发一条 `move` 走过去。
    - **2.1.2.2、钱不够 + 筹资可行**（`_can_fund`：地图上有小贩、且价目里有一种矿收购价 > 0）
      ⇒ **整条墙线让位**（含修墙）：先卖背包里的货（石头只留 `STONE_KEEP_RAISING`(1) 块），
      卖不动就去采性价比最高的矿（`_mine_spare_ore`），凑够 25 金币回来建。
    - **2.1.2.3、钱不够 + 筹资不可行** ⇒ 落回墙线（地图上没有更值得干的事）。

**3、安全待命（`BuildWalls.run` 头一句）**

- 3.1、我分到了墙格、且 `leaving` 非空（砌满墙会关住人）⇒ **待命**（返回 True 而一条指令都不发，
  也不去筹资 —— "安全：别跑远，下回合缺口还在"）。第 93 步起这道闸在 `BuildWalls` 里，
  建墙函数不再接 `gated` 参数。

**4、砌墙 `BuildWalls`（黑板切段；返回 bool）**

- 4.1、没分到墙格（环砌完了 / 段空）⇒ 到 5（修墙）。
- 4.2、挑矿：**只认石矿、取最近的一座**（铁/铜砌不了墙），排掉本回合别人认领的矿格。
- 4.3、算这一趟该采几块（`_stones_to_mine`，按回合预算现算）：

  `走到矿 + 采 k 块 + 从矿回工地 + 手里 s 块的"挪+砌"(2s−1) ≤ 白天剩余 − TIME_MARGIN(5)`

  解出 k（每多采一块净花 `ROUNDS_PER_STONE`(3) 回合），再与「**本段还差几格墙 + `STONE_RESERVE`(3)**
  − 手里石头」取小。多出来那 3 块是**砌完墙后的存货**（夜里被打掉一格，第二天手里有货立刻补上）。
  距离一律 BFS 真实步数，`-1` ⇒ 一块都不采。
- 4.4、想采（`want > 0`）且挑到了矿 ⇒ 登记矿格认领；贴着矿就 `collect`，否则走过去
  （动身成功后整条路进预留账）。⚠️ **认领只发生在 `want > 0` 之后** —— 石头已够的工人不占矿格。
- 4.5、手里有石头（≥ `WALL_COST`(1)）：
  - **4.5.1、环上只剩最后一格**（`len(_ring) == 1`）⇒ 要站到**防御盒子外面**的邻格再砌
    （`_outside_spots`；已经在盒外就直接砌，在盒内先往外走一步）。盒外一个能站的邻格都没有
    （被占/出图）⇒ 退回盒内就近砌；有格子却走不到 ⇒ 这回合不砌，交给别的差事。
    走到盒外那一步**不避让 `target`** —— 缺口本身就是出盒子的近路（穿过它 2 步、绕后方通道整圈 12 步）。
    ⚠️ 这一支**排在 4.5.2 之前**，反过来会原地打转（守门 `LastCellFromOutsideTest`）。
  - 4.5.2、**自己正站在目标格上** ⇒ 这一回合只挪开一格（`_aside_cell`）、不砌。人站在墙上时那格
    在网格里只剩 `worker`（单位铺在最后，墙被盖掉）⇒ 看不出砌过没有，而 `_ring` 的"自己人算路过"
    又把它复活成候选 ⇒ 每回合对脚下同一格 `build`、石头白花。
  - 4.5.3、贴着目标（切比雪夫 ≤1）⇒ `build`。
  - 4.5.4、否则朝目标走（认领 `sites` 发生在**动身之前** —— 等砌完再登记的话，另一个工人会在同一
    回合也奔着它去）。
- 4.6、返回 `False`（没石头 / 采不到 / 没分到格）⇒ 到 5。⚠️ `_emit` 是 `cmds[id]=…` **后写覆盖先写**
  ⇒ `False` 路径上不许已发过指令 —— 这个不变量就是返回值契约存在的理由。

**5、修墙 `RepairWalls`（"升级当修"，白天专属；**环砌满了才轮到它**，第 84 步）**

- 5.1、判据：**弱墙 = 已砌、血量 < 满血 1/5**（`health×5 < WALL_MAX_HP[level]`，满血
  L1 1000 / L2 1500 / L3 2000）。⚠️ 已毁的墙（血 0）**不在这一支** —— 那是一格缺口，归 4 管重建。
- 5.2、有弱墙 ⇒ 取**等级最低**的一面（券最便宜、每金币换到的血最多），同等级取最近的；别人
  已认领的跳过。
- 5.3、用哪件东西（`_wall_item`，按**目标等级**查）：**L1/L2 用围墙升级券**
  （`WallUpgradeVoucher1/2`，样例 20/30 金 —— 升级同时回满血 + 上限抬一档），**L3 到顶才用
  `WallFixer`**（10 金）修复包。
- 5.4、包里没券 ⇒ 走到武器商店 `buy`（商店走不到 / 价目里没有 / 钱不够 / 今天来不及 ⇒
  **待命，不换另一面**）；包里持券 ⇒ 走到那面墙旁边 `use`（目标 = 墙坐标）。
  ⚠️ `remove` 不再出现在这条线上：修墙**不拆墙**（旧 L1"拆掉重建"支就是"工人在乱挖墙"的来源）。

**6、经济线兜底 `ECONOMY_CHAIN`（`SellCargo` → `UpgradeWeapons` → `MineSpareOre`，一件不行才下一件；`_economy` 就是这条链的驱动器，夜里那支走同一条）**

- 6.1、**卖矿 `_sell_ore`**：挑收购价最高的一种背到小贩一次卖光。四道门：
  ① 有可卖的货（`_best_load`，**石头留 `keep` 块**：默认 `STONE_RESERVE`(3)，筹资那两条路
  `STONE_KEEP_RAISING`(1)）；② 有小贩且走得到（BFS `-1` 剔除）；③ 够本 —— **货值 ≥ 2×步数**
  （"1 金币 ≈ 1 回合"是拍的、唯一旋钮；**已贴着小贩就跳过**，这趟路早付过了）；④ 回得来 ——
  `去 + 回 ≤ Turn.rounds_left − TIME_MARGIN`。
- 6.2、**武器有缺 ⇒ 跳过 6.3**，直接 6.4（用户口径："武器 ok 才升级"）。
- 6.3、**升级券线 `_upgrade_line`**：优先链 `UPGRADE_CHAIN` = 火箭→2 > 火箭→2 > 加特林→2 >
  火箭→3 > 火箭→3 > 加特林→3（群体打击口径）。跑腿者 = **持券的人**（券在谁包里谁用 —— 没有
  转移物品的指令）> 真空闲的开拓者（任务点全空）> 名册上第一个工人。持券 ⇒ 走到目标武器 `use`
  （终点即炮位，用完正好站岗、不留回程）；没券 ⇒ 走到商店 `buy`（整趟来得及才出发）；
  **钱不够但"现钱 + 背包里最好那一堆"够 ⇒ 先去卖矿**（`_sell_ore(urgent=True)`，跳过门③）。
- 6.4、**采闲矿 `_mine_spare_ore`**：**先筛可行**（走得动 + 回得来，回程参照 = 最近的武器位）
  **再按性价比挑** `价 × AGENT.price_hint(新闻修正) ÷ (到矿 + 采 + 回)` —— 近的贱矿可能跑赢远的
  贵矿；价 ≤ 0（小贩不收）的矿不为它多走一步。路上**顺路交易**：`_detour_buy`
  （`_shopping_list`：弱墙要的那张围墙券 > 升级链下一张券，绕 ≤ `DETOUR_MAX`(2) 格）、
  `_detour_sell`（有货可卖时绕小贩）。
- 6.5、一件都不成立 ⇒ **什么都不发（合法空指令）**。

### 1.2 黑夜（`not turn.is_day`）

**1、基地升级 `_upgrade_station`**（任何角色，持券即可）

- 1.1、包里持有基地升级券、且基地血量 < 满血 1/4（`STATION_MAX_HP` 1500/3000/4500）⇒ 贴到基地
  旁边 `use`（升级 + 回满血一次到位）。**当回合放弃开火** —— 只在基地真残血时才值得。

**2、没有还在打我方的活机器人 + 我是工人 ⇒ `_economy`**

- 2.1、**与白天 6 逐字同一个函数**：卖矿 → 券 → 采闲矿，一条能发就发。
- 2.2、判据是 `_alive(_foe_robots(turn))`（血 ≠ 0 **且** `targetTeam` 不是明确指向对面）：
  一夜一波（任务书 L352）但机器人**全图可见**（L95）⇒ 对方那一波也在 `turn.robots` 里，而
  我们从不打它 ⇒ 第 85 步之前照"场上全空"判，那台机器人整夜钉住工人、这条线永远进不去。
- ⚠️ 夜里 `build` / `remove` 非法 ⇒ 这一支只可能出现 `collect` / `sell` / `buy` / `use` / `move`。
  走多远由 `Turn.rounds_left`（这一段还剩多少回合）与 6.1 的四道门、6.4 的可行性筛选各自兜着，
  **不留额外的紧半径**。

**3、其余 ⇒ `_defend`**，见 §4。⚠️ **开拓者是补位炮手**（`_pioneer_mans_guns`：工人数 <
武器组数才为真）：工人够操满所有组 ⇒ 它一组都不认领、这一级什么都不发。工人夜里除操炮没别的活，
它却是任务线的主力，抢一组只是把一个工人挤成闲置。判据与白天收工闸门**同源**（§1 第 1 项）。

## 2. 其他总纲

### 2.1 建墙逻辑

- **U 形，背面整列空出来当通道**：**正面列 6 格 + 上下两行各 4 格 = 14 格**，背面那 6 格全空
  （`wall_cells` 与 `door_cells` 同源，方向判据在 `grid._front_back`，**只此一处**）；
  第 3 天起（`_sealed_back`：`round_no > 2 × ROUNDS_PER_DAY`）补**背面两个角格** = 16 格，
  通道从 6 格收到 4 格。补角格**没有新机制**：`_ring` 按 `sealed` 取候选、已砌的 14 格被
  `blocked` 滤掉 ⇒ 只剩那两格。
- **`wall_cells` 的顺序 = 正面列（迎着机器人）→ 下行 →〔背面两角〕→ 上行** ⇒ 回合不够时自然
  优先砌面向敌人的方向，零新机制（`_ring` 保序、`BuildWalls.run` 取段首格）。
- **`_ring` 的例外**：候选墙格要排除 `blocked`，但**我方角色站的那一格除外** —— 否则"谁站在
  待砌的墙格上"会让那格从候选里消失，另一个工人的目标跟着后移、等人一挪窝又变回来 ⇒ 两人在
  两格之间对着改目标转到天黑，一格都砌不上。
- **`_walled` 只把"站在后方通道那几格"的自己人算障碍**（与 `_ring` 故意相反）：那圈墙里没有
  任何建筑 ⇒ 能堵门的只有单位，"自己人站在格子上"只在门口有意义；环内站着的是**过路的**。

### 2.2 武器逻辑

- **三座、种类与落点绑死**：`WEAPONS_BY_SITE = ("rocket", "rocket", "gatling")`，下标与
  `weapon_sites()` 一一对应；落点**全在正面列**。两座火箭**相邻** ⇒ 一个角色站在内侧那格
  （共用的操作位）就能同时贴两座、按 3 回合冷却交替开火 ⇒ **2 个角色即可操满 3 座**。
- 落点由**己方 station 的 `pos` 推导**，禁止绝对坐标（换边后基地会挪）；基地 2×2 的展开以
  `grid.base_cells` 为准。
- 份额 = `len(roles)`，上限取**保守的全局 ≤3**（原文自相矛盾，取"武器只有建三个才有意义"）。

### 2.3 兜底

- **任何一级都发不出指令 ⇒ 空指令** `{"roleCommandMap":{}}`，合法、不计异常。
- **时间预算一律走 BFS**（`steps_between`），`-1`（不可达）一律当"这趟不去"，**不为估算去改
  `step_toward` 的契约**。

## 3. 开拓者（Pioneer）

### 3.1 被任务钉死（最高优先，昼夜无关）

`phaseTask` 非空 ⇒ 每回合只做一件事：`_answer_task` 把 `answer_of(llmResp)` 的答案
`submitAnswer` 交上去（**每回合都交** —— 判题器取"通过率最高"的那份，重交零成本；空答案 /
工具回复不发）。**一步都不挪**：离开任务点周围一格（切比雪夫 ≤1）任务立即作废 ⇒ 它连夜里都
不回炮位。被堵在盒里时自己出不来（走不到 0.1），只能靠工人 `_rescue`。

**例外：夜里人手不够就弃任务回炮位**（用户口径"生存第一"）。判据 `_short_handed` = **没被任务
钉住的角色数 < 武器组数**（一人只能操一组，少一个就有一组整夜空着）—— 工人阵亡（只可能在夜里）
把 3 人变成 2 人、阵形两组炮 ⇒ 那个被钉住的人就是唯一的机动火力。**白天恒假**（白天不能开火、
回炮位只发 `move`）⇒ 这一支与本判据都不带跨回合状态，工人白天复活后自愈。代价是任务当场作废
（"离开任务点一格"），这是用户明确要的取舍：任务积分换一门火力。

### 3.2 白天接任务 `_take_task`

贴着最近一个**能接**的任务点（切比雪夫 ≤1）就 `acceptTask`；否则朝它走一步（`step_toward` 天然
停在贴着的一格 —— 任务点挡路，"走过去"与"停在接取位"是同一件事）。**不走去冷却中的点蹲守**
（全在冷却 ⇒ 待命，空指令合法）。判据来源是 `teamOur.playerTasks`（只含我方两个点）。

### 3.3 真空闲（任务点全空）的白天

领"买券 → 用券"差事（`_upgrade_line`，**武器有缺时不跑**）；它没差事没货时 `_sell_ore` 兜底
（接住从任务/宝藏拿到可卖物的情形）。⚠️ 规则限制：`collect` 仅工人、**没有转移物品的指令**
⇒ 开拓者背包里通常没矿，这条兜底结构在、多数时候跑不起来。

### 3.4 夜里（没被钉死时）

跟所有人一样走夜里分支（§4）：基地残血持券先升级，否则看**补位炮手**那条判据 —— 工人够操满所有
组时它一颗炮位都不占（见 §4），不够（工人阵亡）才认领一组、站上岗位开火 / 待命。

## 4. 夜里共同：操炮防守（`_defend` / `_fire`）

`_defend`：**开拓者先过一道门** —— `_pioneer_mans_guns` 为假（工人数 ≥ 武器组数）⇒ 它直接返回、
一个组都不认领。工人夜里除操炮没别的活，开拓者却是任务线的主力，而 payload 里它常排在最前，
不拦就会先挑走最近的组、把一个工人挤成闲置（火力一分不多）。工人阵亡（只可能在夜里）后
人手不够，它下一回合自然补位 —— 判据是每回合现算的，不带跨回合状态。
⚠️ **唯一例外**（第 77 步）：它**已经站在**某组的操作位上（`_stands_on_a_post`）⇒ 认领那一组 ——
那一格被它占着、工人站不上去，它再不打就是整组白丢一夜。

然后认领最近**未被本回合别人认领**的一组武器（`_weapon_groups`：2 火箭一组、加特林单独
一组；组按 `weapon_sites` 的下标分，不按种类猜），**先开火、打不了才挪岗**：

- **贴着组内某座** ⇒ 认领整组、开火。就绪的先挑（含本地开火账），就绪的并列按 `round_no`
  轮转，都冷却 ⇒ 一发不发。**只贴一座也打** —— 另一座就绪而这座在冷却时别白丢一回合。
  ⚠️ 这一支**排在岗位判据之前**（第 77 步）：岗位格被占 / 走不到都不是"这一组不用管"，
  旧顺序让"贴着炮但岗位格被占"的角色跟着整组一发不打（用户报的死锁）。
- **整组的岗位都站着、又都打不了** ⇒ **原地待命，不换组**（每回合重挑会让角色在炮位之间来回走）。
- **只贴着一部分 / 压根没贴着** ⇒ 朝岗位挪一格（走不到就换下一组）。
- **主岗位一个都站不上**（共用操作位被机器人踩死 / 那条一格宽的走廊被堵）⇒ 退到 `_near_spots`
  指的格子（贴着组内**任意一座**），只守得了一座也照打 —— 退路**排在主岗位全试完之后**，
  不然工人会把同事站着的那一组抢过来。
- `round_no` 缺失（-1）⇒ 一发不发：缺失被 `is_day` 判成夜里，对"白天不许建造"安全、对"白天
  开火非法"就是反的。

⚠️ **岗位 = `_post_spots`**：多座组 = 同时贴着组内所有座的**空地**（要踩上去 ⇒ `grid.step_onto`；
`step_toward` 的契约是"贴着即到"、停不进这种格子，会原地卡死）、单座组 = 那座炮本身。
**自己人一律不算障碍**（`model._entries` 把我方角色写进网格 ⇒ 不放行的话，站在岗位上的操作者
看不见自己的岗位、整组被跳过 —— "敌人进了射程不打"的根因）；**别人站着的那格要让开**
（换一组，否则一个走不进去、一个干等着）。

`_fire`（方针：**打死所有机器人**，按**最大伤害落点**）：

- **冷却中不打**：payload 的 `cooldown` 优先；火箭字段缺失（-1）时查**本地开火账** `_fired`
  （跨回合观测状态：发出 `attack` 那回合记武器 id，之后 `ROCKET_COOLDOWN`(3) 回合不选它，
  期满自动过期 —— 打冷却炮是指令执行失败、白丢一回合火力）。加特林/电磁恒 0，不查本地账。
- **只打打我方的机器人**（`_foe_robots`）：`target_team` 为空或 `== our_team` ⇒ 打；明确打对方
  ⇒ 跳过（打它们既浪费火力、又帮对方减轻基地压力）。`our_team` 缺失 ⇒ 不过滤、全部照打（安全降级）。
- **火箭 `_rocket_site`**：候选 = 机器人格及其 8 邻格、落点须在射程内（**溅射可以够到射程外的
  机器人** —— 射程只管落点），评分 = Σ min(中心 / 溅射, 剩余血)，并列取坐标序。**指哪打哪、
  不被弹道阻挡**；越界格不进候选（越界落点 = 指令非法，红线不让赌）。
- **加特林/电磁 `_beam_site`**：打**有效伤害**最高的机器人（`min(伤害, 剩余血)`；并列打近的）。
  终点必在弹道 ⇒ 必命中；加特林实际命中"弹道最近"那台，估计只用来挑目标，错了只是次优。
- **伤害与份数按等级走**（`_beam_damage` / `_rocket_damage`）：加特林/电磁每级 +10，火箭按枚数
  叠加（中心 20×级 / 溅射 10×级）；`targetPos` 的**份数 = 等级**（电磁恒 1 —— 接口文档 L218，
  发错是指令非法），多出来的目标位**重复同一个最优落点**（用户口径的"最小合法化"）。
- **`assigned` 记账**：同回合先开的炮把估计伤害记上，后开的按剩余血算 ⇒ 不挤将死的目标。
- 机器人 `health` 缺失按"还活着"算（打空处只是执行失败、不计异常；"一律不打"会让整晚哑火）。

## 5. 常量与旋钮（全在 planner 顶部，改行为先改这里）

| 常量 | 值 | 管什么 |
|---|---|---|
| `TIME_MARGIN` | 5 | 所有回合预算的真余量（BFS 化之后不再是补丁） |
| `POST_MARGIN` | 3 | 收工闸门的缓冲：`回岗步数 ≥ 白天剩余 − POST_MARGIN` 就动身（拍的） |
| `ROUNDS_PER_STONE` | 3 | 采 1 + 挪 1 + 砌 1 |
| `STONE_RESERVE` | 3 | 砌完墙手里多留的石头（夜里补墙用）；只抬高 `_stones_to_mine` 的上限 |
| `STONE_KEEP_RAISING` | 1 | 筹资路上（建武器 / 买券）卖石头只留 1 块 |
| `HOLE_MIN_LEFT` | 30 | 拆墙放人的时间门（剩不到 30 个白天回合就不拆） |
| `DETOUR_MAX` | 2 | 顺路买卖的绕路上限 |
| `WALL_MAX_HP` / `STATION_MAX_HP` | 1000/1500/2000、1500/3000/4500 | 修墙的 **1/5 血**判据 / 基地残血判据（墙 L2/L3 是推断） |
| `WEAPON_COST` / `WALL_COST` | 25 / 1 | 建一座武器 / 砌一格墙 |

| `UPGRADE_CHAIN` | 6 步链 | 升级优先序（群体打击口径：火箭优先） |
| `WEAPONS_BY_SITE` | `("rocket", "rocket", "gatling")` | 落点配种类（与 `weapon_sites` 下标一一对应）。两火箭相邻 ⇒ 共用一个操作位 |

## 6. 实测锚点与已知薄弱处

- **首日收官**（`DayOneFinishTest`，两座石矿可行地图、70 回合逐回合结算）：环 **R41** 收官
  14/14、三座武器 **R39-R44** 建满、金 75→0、环砌完前工人零闲置、同格不重砌。前提是**真实地图
  至少 2 座石矿** —— 只有 1 座则环物理砌不完（悬置 #32，首场日志先数）。
- **`_short_handed` 的分母是"武器组数"**：武器没建齐时组数按场上已建的算 ⇒ 天然不报警；但也
  意味着**只有一座炮时一个人就够**，那条"弃任务"永远不触发（设计如此）。
- **两道人手门同一个数**：`_pioneer_mans_guns`（第 74 步）= "工人数 < 武器组数"，`_short_handed`
  （第 65 步）= 它**再加一道白天恒假**。问的是两件事（认不认领炮位 / 弃不弃任务），但名册里只有
  工人与开拓者两种角色 ⇒ "工人数"就是"没被钉住的角色数"，第 74 步已把计数收进前者、后者只是
  `not is_day and _pioneer_mans_guns(turn)`。改分母只需改一处。
- **`targetPos` 的份数 = 等级这条规则没有实证报文**（按接口文档 L218 实现；悬置 #23 的判据已换成
  "真机上会不会要求多格互不相同"）。
- **加特林弹道是否被墙挡没有明写**（只明说火箭不被挡）—— 若被挡，武器打不出盒子，防守阵形整个
  要重想（悬置 #21）。
- **双火箭的共用操作位 `(11,25)` 是个"口袋"**（唯一通路 = `x=9` 那条一格宽的走廊）：队友停在
  走廊上时 BFS 判不可达 ⇒ 这一步不走，这一夜它就不挪窝；白天收工会把人送进口袋、第二天早上要
  多走 6 步出来（悬置 #34，**未实测**）。
- **"最后一格墙从盒外砌"在当前几何下防不了封死**（14/16 格里没有一格落在敞开的背面列上 ⇒
  站在盒内砌完仍出得来），收益要等几何/门宽变化才兑现（悬置 #40）。
- 其余逐条见 `code-task.md` 文末悬置表（#26 门被堵、#27 `-1` 分支、#31 压缩闸门、
  #42 升级链优先序、#43/#44 升级当修等）。
