## 0. 一页纸结论

1. **这是"双人各自打塔防 + 比分数"的 PvE 竞速。** 角色无攻击能力、**所有建筑均不可被攻击**（✅），**我们唯一能伤害对手的方式是"机器人召唤令"**——双方火力互相够不着。**因此半场大概率不是被"打死"结束，而是由比分决定胜负。**
2. **任务分（score₁）是绝对主战场，且"快"比"对"更值钱**：`score₁ = 奖励 + 5 × 标准回合 / (完成回合 − 接取回合)`。⚠️ **v0.4 纠错**：题面（`phaseTask`）最早在**接取的下一个回合**才可见，所以 LLM 路径下界是 **2 回合**（std=30 时 75 分）；**只有命中本地技能库/规则解才能做到 1 回合**（150 分）。→ **技能库的命中率直接决定任务分上限**，是最大增量收益来源（详见 §5.2）。
3. **防御是固定 36 格盒子**（✅③）：基地 2×2 居中、外一圈 12 格武器环、再外一圈 **20 格围墙环（单层、不可加厚）**。**防御上限由这 20 面墙的"存活 + 修复"决定。**
4. **夜间不可建墙**（build 仅白天可用）→ **墙一旦被拆，整夜都是缺口，无法重建**。因此夜间第一优先级是"**预防性修复**"：在墙被打爆之前回血，而不是爆了再补。
5. **防御经济学**：1 石 ≈ 1000 点阻挡（最划算）；`WallFixer` 10 金回满；**已受损的墙优先用升级券（20 金）= 回满 + 上限 +500**，比 10 金修复更值。**石头不要卖。**
6. **武器没升级前几乎无用**（L1 加特林 10 伤/回合，打死小机器人要 4 回合）。目标：**第 3 天前 2 座 L3 武器**（约 500 金）。
7. **开拓者是"全时任务机"**，不参与采矿、不做火力主手；任务点离盒子 8~10 格且离开即作废。**夜间默认只有 2 个动作可用**（每角色每回合 1 个动作，✅⑥）。
8. 红线：**异常 ≥5 次直接出局**；**绝不能成为"先丢基地"的一方**（半场判负 = 3 分，单项最大得失）。

## 1. 规则解构：事实 → 战略含义

| # | 事实 | 战略含义 |
|---|---|---|
| 1 ✅ | 角色无攻击能力；武器须由**周围 1 格内的角色**操控；**一角色同时只能操控 1 座武器**；**每角色每回合仅 1 个动作** | 最大同时火力 = 角色数；**操控武器即消耗该角色当回合动作**（不能边打边修边吃药）。夜间动作经济是本局最稀缺资源（见 §6.5） |
| 2 ✅ | 武器全局上限 3 座；新建覆盖旧武器且**等级重置 L1** | 武器槽稀缺；**绝不用新建覆盖已升级武器** |
| 3 ✅ | **攻击不可作用于任何建筑**（围墙、基地均已确认） | ❌ 全图狙击、拆对手墙的路线全部作废；**唯一进攻手段 = 机器人召唤令**（§9.2）。**推论：半场几乎不可能靠"打死对手"结束，胜负将主要落在比分上 → 任务线的权重进一步上升** |
| 4 ✅ | 我方弹道**不被自己的围墙阻挡** | 围墙可以放心闭合，无需留射孔；武器/围墙布局解耦 |
| 5 ✅ | 基地 2×2；外一圈 **4×4 武器区**；再外一圈 **6×6 围墙区，恰 20 格**；基地位置**固定** | 防御是**固定 36 格盒子**：4 基地 + 12 武器格 + **20 围墙格（单层环，不可加厚、无余量、无备用格）** |
| 6 ✅ | 机器人**出生于固定区域**，寻路基地，**不可绕过围墙**，会攻打围墙 | 攻击面固定在盒子正面 → **所有来敌挤在同一段墙上**：AoE 收益拉满、修复点集中、背面永远安全（可当门） |
| 7 ✅ | 攻击仅黑夜可用；伤害回合末结算；顺序 = 武器攻击 > 机器人移动 | **本轮打死的机器人不会移动/攻击** → 集火击杀 = 同时减免伤害 |
| 8 ✅ | 机器人夜间首回合全体出现、天亮首回合全体清除 | 不需要全歼，只需**让基地活过这一夜**；残血伤害天亮清零 → **集火 > 平摊** |
| 9 ✅ | **build 仅白天可用** | **夜间无法重建被拆的墙** → 必须预防性修复（§6.4） |
| 10 ✅ | 基地 1500/3000/4500；**建筑升级后回满血** | 基地升级券 = 一次性大回血（最多 +1500/+3000），**必须预留 100/150 金** |
| 11 ✅ | 围墙 1000/1500/2000，1 石建造；WallFixer 10 金回满 | 最高性价比坦克；**石头留作墙，不要卖**（1 金机会成本换 1000 血） |
| 12 ✅ | 矿石：石 1 / 铁 3 / 铜 5；单矿 10 次采空后随机刷新；工人 1 矿/回合 | 收入 ≈ 1 矿/回合/工人；"就近采满 + 批量卖"是唯一提效手段 |
| 13 ✅ | 矿区不会刷在可建造区内 | 采集与回防之间有固定往返成本 → 日间必须按回合预算排程 |
| 14 ✅ | 小贩、武器商店位置固定，买卖需在周围 1 格内 | "卖 + 买 + 回基地升级"必须合并成一次出行 |
| 15 ✅ | 视野 4 格；**敌方基地/围墙、机器人全局可见** | 可全程读取对手基地血量与围墙布局；**由对手方机器人血量逐回合差反推其防御 DPS**（§9.1） |
| 16 ✅ | 每队每日 3 次 LLM 配额，**任务期间不限次**；**回复在下回合初必到** | LLM 是可用的"1 回合延迟神谕"；**绝不在请求线程里等 LLM** |
| 17 ✅ | `executeCmd` 每回合 1 条、≤15 秒、结果下回合返回；沙盒无外网 | 任务求解 = 1 命令/回合的慢速闭环；**首解慢、复解快 → 技能库** |
| 18 ✅ | 异常仅三类：超时 / 格式错误 / 指令字段缺失或动作码非法 | 白天 attack、移动碰撞、攻击落空**都只算"执行失败"，不计异常**；**部分提交错误也仅报 errorCode 2，不累计异常** → 试错成本极低 |
| 19 ✅ | `summonTreasure` **只要动作合法就消耗**献祭物品 | 不能试错，必须情报确定后再动手 |
| 20 ✅ | 宝藏**半场重置** | **第一半场推断出的地点/物品/时间，第二半场直接复用**——最强的跨半场优势（§5.3） |
| 21 ✅ | 半场判定：基地先被摧毁者判负；否则比积分 | 半场目标 = "不先死 + 分高"；**3 分权重 >> 比分差** |
| 22 ✅ | 建筑被拆后地格变可通行 | 墙破即开门；但夜间不可重建 → 破口整夜有效 |

## 2. 目标函数

```
总积分 = score₁(任务) + score₂(击杀) + score₃(生存)
score₁ = 任务奖励 + 5 × 标准回合 / (实际完成回合 − 接取回合)     // 完全正确
score₁ = 任务奖励 × 通过率                                      // 部分完成（无时间项）
score₂ = Σ(机器人积分)          // 小1 中2 大4 BOSS10
score₃ = Σ_{day=1..10} 10 × day × 存活系数                       // 满额 550
```

| 收益项 | 量级 | 结论 |
|---|---|---|
| 自进化任务（**接取后 1~3 回合交付**） | **100–200 分 + 30–60 金** | 主战场 |
| 自进化任务（20 回合交付） | 50–60 分 | 时间项几乎归零 |
| 生存 1 天 | 10–100 分（递增） | 是门槛不是选项；基地死 = 半场判负 |
| 一夜击杀 10 只 | ≈20–30 分 | 顺路打即可，**绝不为此牺牲基地或任务** |
| 宝藏（长上下文类，每半场一次） | 未知，估 ≥300 分 | 全图唯一，先开者得 |

**优先级：P0 任务吞吐 > P1 防御充足性（基地不死）> P2 经济效率 > P3 击杀/骚扰。**

```
        ┌─────────────────────────────────────────────────────┐
        │ 红线 A：异常 < 5 次   │ 红线 B：绝不先丢基地          │
        └─────────────────────────────────────────────────────┘
  白天（70 回合）                          夜晚（60 回合）
  ┌───────────────┐ ┌────────────────┐    ┌──────────────────────────┐
  │ 任务线(开拓者) │ │ 经济线(双工人) │    │ 防御线：控武器 / 预防性修复│
  │ 接取→求解→交付 │ │ 采石→建墙       │    │        / 应急道具         │
  │ 宝藏推断/采购  │ │ 采矿→卖→买→升级│    │ 动作预算：每角色仅 1 个动作│
  └───────────────┘ └────────────────┘    └──────────────────────────┘
```

| 角色 | 白天 | 夜晚 |
|---|---|---|
| 开拓者 10011 | 驻守任务点跑任务；冷却期做宝藏采购/情报 | 优先回盒子（第 3 个动作：第 3 座武器 / 修墙 / 道具）；若任务点实测安全则可留在外过夜 ❓ |

| 工人 B 10012 | 同上（不同矿点、不同批次） | 操控副武器；必要时转修复/道具 |

## 4. 经济线

### 4.1 回合预算（一切以回合计价）

| 行为 | 成本 | 备注 |
|---|---|---|
| 移动 1 格（含对角） | 1 回合 | 切比雪夫，**永远走对角** |
| 采集 1 矿 | 1 回合 → 1 矿 | 单矿总量 10，采空刷新 |
| 批量贩卖 / 批量购买 | 各 1 回合 | 攒够再走，**绝不零散交易** |
| 建造 1 面墙 / 1 座武器 | 1 回合，**仅白天** | 目标须在自身 1 格内 |
| 使用 1 张券 / 道具 | 1 回合 | 须站在目标建筑 1 格内 |

**推论**：移动是纯开销 → ①采满 10 次再走；②买卖合并出行；③两工人**不抢同一座矿**（分开各采 10 次，移动成本减半）。

### 4.2 收入估算（⚠️ 待实盘校准）

单工人 ≈ 10 矿 / (6 移动 + 10 采集) ≈ 0.62 矿/回合 → 双工人 ≈1.25 矿/回合；均价按铁铜混合 ≈3 金 → **≈3.8 金/回合 → 白天 70 回合 ≈260 金**；加任务金币（30×通过率，日 4–8 个）→ **合计约 350–500 金/天**。

### 4.3 采购优先级（金币按此顺序花）

| 序 | 项目 | 价 | 理由 |
|---|---|---|---|
| 1 | `WeaponUpgradeVoucher1/2` | 100/150 | 长线 DPS，跨夜复利 |
| 2 | `WallUpgradeVoucher1/2`（打到**正面受损墙**上） | 20/30 | 回满 + 上限提升，优于纯修复 |
| 3 | `WallFixer` | 10 | 战损墙回满，应急 |
| 4 | `StationUpgradeVoucher1/2` | 100/150 | **预留在手**，基地挨打时当大回血 |
| 5 | `Medicine` | 10 | 保命，常备 1–2 |
| 6 | `DizzyWeapon` / `Bomb` | 100 | 应急：BOSS 集群 / 小中集群 |
| 7 | 任务用品（献祭） | 15×n | 仅在宝藏条件确定时买 |
| 8 | 机器人召唤令 | 20–200 | 仅"破局窗口"（§9.2） |
| — | 不建议 | — | 卖石头、早期买召唤令、买不确定的献祭品 |

**现金储备规则：常备 ≥150 金**（= 1 张基地升级券 + 修墙），除非当场能确定今夜无威胁。

### 4.4 物价情报（推理类任务）

官方消息预告矿区停工/供需变化 → 小贩回收价波动。执行规则：
1. 每天第 1 回合解析 `worldNews.officialNews` → 结构化事件 `{矿种, 影响窗口, 方向, 是否停产}`（规则优先，LLM 兜底，省配额）。
2. 涨价预期 → **屯矿不卖**（工人 100 格背包就是仓库）；跌价预期 → 当天清仓。
3. 价格窗口打开当天，一次性批量卖空（1 回合）。
4. 停产窗口 → 提前改采其他矿种。

**石头账本（v0.4 新增）**：笼统的"石矿优先"不够，因为**每面墙被拆后重建仍需 1 石，20 面 = 20 石**，这是一笔必须显式管理的负债。

```
stone_target = 当前缺口面数 + 缓冲（默认 3）
```

采集优先级由 `stone_target` 驱动，而不是无条件优先石矿：
- `背包石量 < stone_target` → 石矿优先（墙不等人，且白天不补，夜里补不了）
- 石量已够 → 转采铁/铜换金币（金币买升级券的复利更高）
- ⚠️ 石头**只用于建墙，绝不卖**（卖石头 = 把防御工事换成金币，是本末倒置）

## 5. 任务线（score₁ 主战场）

### 5.1 三种任务

| 类型 | 获取 | 执行者 | 关键动作 |
|---|---|---|---|
| 自进化类（任务点，2 个） | 开拓者站任务点 1 格内 `acceptTask` | 开拓者 | `executeCmd` 探测 + `submitAnswer` |
| 推理类（官方消息） | 新闻被动 | 全员经济动作 | 卖矿套利（§4.4） |
| 长上下文类（民间传闻） | 新闻被动 | 开拓者 | 推断后 `summonTreasure` |

### 5.2 自进化类：把"实际回合"压到 2–3

> ⚠️ **本节在 v0.3 被大幅修正**（时序错误 + 提交策略）。依据见 `code-design.md` §9。

**生命周期**：`acceptTask(回合 R)` → 任务点冷却 30 回合。**任务结束只有 4 种行为**（✅任务书 §五）：

1. 任务被完成
2. 从领取起计数超过 `timeoutRounds`
3. **离开己方任务点周围一格内**
4. 领取任务的开拓者死亡

> **注意"提交答案"不在其中** —— 这是下面提交策略的依据。

**关键杠杆是"完成回合"**：`5 × std / (完成 − 接取)`。

#### ❌ v0.2 的时序错误

`phaseTask` 的定义是"**当前已领取**任务的原文描述"。在回合 R **发** `acceptTask` 时，R 回合的请求里 `phaseTask` 必然还是空 —— 题面最早在 **R+1** 才可见。因此 v0.2 写的"实际回合 = 1（LLM 路径）"**在时序上不可能成立**。修正后：

```
LLM 路径（下界 = 2）：
  回合 R   : acceptTask（+ 一条与题目无关的通用环境探测 executeCmd 合法）
  回合 R+1 : 读到 phaseTask（首次拿到题面）→ 发 prompt
  回合 R+2 : 读到 llmResp → submitAnswer        → 实际 = 2，std=30 时时间项 = 75 分

技能库路径（唯一能做到 1）：
  回合 R+1 : 读到 phaseTask → 本地技能库/规则直接命中 → submitAnswer
            → 实际 = 1，std=30 时时间项 = 150 分

需沙盒取证的任务族：
  回合 R+1 : 发 executeCmd（heredoc 打包多个探测）
  回合 R+2 : 读 lastCmdResult → 充分则交付（实际 = 2），否则再发一条 → R+3 交付（实际 = 3）
```

> **结论：技能库不是"优化项"，而是唯一能吃到满时间项的路径。**
> 阶段目标应从"交付回合 ≤3"改为"**技能库命中率**"。

#### 提交策略（v0.3 修正）

两条事实：

- 部分完成分 = `奖励 × 通过率`，**没有时间项** → 低置信度答案"早交"与"晚交"**分数完全等价**
- 接口文档：超时后"以**之前提交过的通过率最高的答案**计算积分与金币"——"之前提交过的"是复数且**取最高**，说明多次提交都被保留、判题器始终按历史最佳结算

> **推论（高置信，待首局实测确认）：部分提交不终止任务，重复提交是弱优势策略** —— 单调不减，最坏情况等于不交。

因此取代 v0.2 的"保底提交 at `deadline − 2`"：

- **每回合只要有答案就提交当前最佳答案**
- 正确的理由是"**零机会成本的迭代**"，而不是"保底"
- 唯一需要克制的是别让"提交"挤掉更值钱的动作（开拓者每回合只有 1 个动作）

#### 通过率反解（零成本的监督信号）

`submitAnswer` 只回 `errorCode 2`（对/错），**不给通过率**。但每回合的 `teamOur.totalScore` 与 `goldNum` 逐回合做差即可反解：

```
Δgold  (提交回合 → 下回合) = goldReward × 通过率
Δscore (提交回合 → 下回合) = scoreReward × 通过率            （部分完成）
                          = scoreReward + 5×std/Δrounds     （完全正确）
```

→ 两条独立方程，**同时解出"是否完全正确"与"通过率"**，写回技能库当**有监督标签**。这比"猜答案格式对不对"高一个量级，且完全免费。
（同时它也能直接判掉 §11 的实验 6：提交后 `phaseTask` 仍非空 → 不终止任务。）

**执行纪律：**
1. **先查技能库**：按任务族指纹（题型 + 参数模式）命中则直接生成答案，**不走沙盒** —— 拿满时间项的唯一路径。
2. **LLM 与沙盒并行**：`prompt` 与 `executeCmd` 可同回合下发，两者下回合初同时到齐。
3. **提交**：见上，每回合交当前最佳答案。
4. **技能库落盘持久化**（按题型指纹索引），跨对局复用 → 第二场开局即带全套 SOP。
5. **两个任务点交替**：A 点交付后立即转 B 点；两者都在冷却时才做宝藏/回防。
6. 任务点总数有上限 ❓，且结束后需 **30 回合**刷新 ✅ → 用尽后开拓者转为**专职修墙手 + 第 3 座武器操作员**。
7. ⚠️ **开拓者必须驻留**：任务期间"离开任务点周围一格"即结束任务。任何移动前必须校验"移动后仍与任务点相邻"。
   注意**任务点 2 占两格**（✅样例 `zones` 里 `challengerTaskPoint2` 出现两次）→ 相邻判定必须取**两格并集**。站 `(15,16)` 时到 `(17,17)` 距离 2、到 `(16,17)` 才是 1；只记一格会误判为"已离开"而直接废掉任务。

**沙盒命令编排**：`python3 - <<'EOF' … EOF` 一次打包多个探测，15 秒内榨干信息；输出务必精简（>64KB 截断）；严格解析 `[exitCode:N]` / `[TIMEOUT]` / `[JUDGER_ERROR]` 前缀（**只在开头匹配**）。
⚠️ **不要假设沙盒文件跨回合持久** —— "把探索脚本写进去留存复用"是 v0.2 的乐观假设。设计上必须在"无持久化"假设下也能 2 回合解完，持久化只当加速项。第一条命令永远是**廉价通用探测**（shell 方言、python 版本、可用标准库），结论缓存整场。

### 5.3 长上下文类：宝藏（每半场一次，**跨半场复用**）

**情报模型**：每日 `folkLegends` 追加一条（DAY1…DAYN），需推断三要素：**地点 / 开启时间 / 献祭物品集合**（物品须**不多不少**，错一件 = 结果码 3 且物品照样消耗）。

**执行规则：**
1. 维护"情报台账"：按天累积原文 + 结构化假设（候选地点集合 / 候选物品集合 / 候选时间窗口）。

3. **只在置信度高时出手**：物品 15 金/件，失败一次白扔 45–90 金。
4. 提交前三项自检：targetPos 在开拓者周围 1 格内 ✓、`item` 与背包**完全一致** ✓、时间窗口匹配 ✓。
5. ✅ **宝藏半场重置 → 第一半场推断出的地点/物品/时间，第二半场开局直接照搬执行**。这是最强的跨半场优势，**务必在第一半场把三要素完整记录下来**（含推断依据与最终验证结果）。
6. 第一半场若发现对手先开 → 记录对手的开启回合与地点，反推其推断路径。

## 6. 防御线（v0.2 全面重写）

### 6.1 固定盒子几何（✅）

设基地左上角坐标为 `(bx, by)`（接口规定 pos = 左上角；y 轴向上）：

```
基地   : x∈[bx  ,bx+1], y∈[by-1,by  ]            → 4 格
武器环 : 4×4 的外圈 (x∈[bx-1,bx+2], y∈[by-2,by+1] 去掉基地) → 12 格
围墙环 : 6×6 的外圈 (x∈[bx-2,bx+3], y∈[by-3,by+2] 去掉 4×4) → 恰 20 格（✅已确认：围墙区仅此 20 格，无备用格）
```

示意图（D=基地 W=武器格 ▓=围墙格）：

```
      ▓ ▓ ▓ ▓ ▓ ▓
      ▓ W W W W ▓
      ▓ W ▓ ▓ W ▓        ← D 为基地 2×2，占据内圈中心
      ▓ W ▓ ▓ W ▓
      ▓ W W W W ▓
      ▓ ▓ ▓ ▓ ▓ ▓
```

**推论：**
- **武器环上任意一格，到整个围墙环的距离 ≤5（切比雪夫）**，到环外 1 格的来敌 ≤6 → **L3 加特林（射程 7）即可覆盖整个环及其外围**；L3 电磁（射程 10）富余。**摆放位置只需偏向正面**，不必追求覆盖死角。
- **围墙恰好 20 格、单层、无纵深可言** → 防御强弱 = `正面那 5~6 面墙的存活 + 修复能力`。
- 角色可站立的自由格 = 武器环 12 格 − 已建武器（≤3）= **≥9 格**，容纳 3 个角色，且每格都能同时够到武器（操控）与围墙（建造/修复）。
- 示例局观测：挑战者基地 (10,24)、守卫者基地 (30,10)（❓ 固定位置待最终确认；样本中守卫者围墙 (28,7) 正好落在 (30,10) 推导的 6×6 角点上，交叉印证了该几何）。

### 6.3 围墙施工与"门"

**建墙顺序（正面优先）：**
```
① 正面 5~6 面（朝向机器人出生区）——第一优先，第 1 天就要有
② 两侧各 4~5 面
③ 背面 5~6 面 —— 最后，且优先留作"门"
```

**门的设计（背面）：** 机器人不可绕墙（✅⑥）→ 背面不会被攻击，**留 1 格背面墙不建，作为工人进出通道**。

> ⚠️ **v0.3 修正：`build` 仅白天可用，所以"夜间封门"根本执行不了。**
> v0.2 写的"当夜波次威胁 > 吸收能力 × 0.8 时封门"是个**不可执行的决策** —— 夜间既不能建也不能封。封门本质上是**白天的决策**。

两个可执行方案，**推荐方案 B**：

| 方案 | 做法 | 代价 |
|---|---|---|
| A. 白天末尾决策 | 在白天最后若干回合（`within 64~70`）根据当夜预估威胁决定是否补上门口那格 | 判断不准就整夜敞口；且白天末尾工人往往在远处采矿，赶不回来 |
| **B. 常闭 + `remove` 开门（推荐）** | 门墙**始终存在**；白天首个出勤的工人 `remove` 开洞，收工回环后由最后回环的工人补建 | 每个白天多花 2 个工人动作（一开一闭）+ 2 石 |

选 B 的理由：夜间**零敞口风险**，而"敞口整夜"的代价远大于 2 个工人动作；且 `remove` 没有白天限制，夜里也能应急开洞。

- ❓ **待验证**：背面留洞时机器人是否会从背面进入（若会，则必须常闭 → 直接选 B 且不留洞）。

**修复优先级（夜间不可重建，✅⑨）：**
```
每回合先评估：正面是否有墙"预计本回合会被打爆"（墙血 ≤ 该墙当回合承受伤害）
  ├─ 是 → 该侧角色本回合动作改为 WallFixer 修复（> 输出）
  └─ 否 → 全员输出
```
- **绝不能让墙见底**：夜间墙一破就是整夜缺口，机器人直接进环打基地与角色。
- 受损墙优先用**升级券**（20/30 金 = 回满 + 上限 +500/+500），比 10 金纯修复更值；`WallFixer` 留给已 L2/L3 的墙或紧急回血。

### 6.4 夜间火力分配算法（纯代码，每回合）

```
每个已上人的武器：
    enemies = 切比雪夫距离 ≤ 射程的机器人
    if 无目标: 该角色转 修复/道具/待机
    for r in enemies:
        killable = (r.hp <= 单发伤害(weapon, r))        // 本轮可击杀
        threat   = r.dps × 距离权重(r, 基地)             // 越近越危险
        value    = threat + (killable ? 击杀奖励 + 积分权重 : 0)
    选最高分目标；并列时优先"可击杀"，再按 BOSS>大>中>小
```

**要点：**
- **集火**：未击杀的伤害天亮清零 → 宁可 3 发子弹打同一只残血。
- **加特林 90° 锥形**：全部目标相对加特林夹角 ≤90°，否则**整次攻击非法**；安全兜底 = 3 个落点填同一坐标（夹角 0° 恒合法）。
- ⚠️ **落点数组长度**：**电磁狙击炮恒为 1**（只能攻击一个目标）；**加特林/火箭 = 当前等级**（L3 传 3 个，不足用重复坐标补齐）。v0.3 曾误写成"一律等于等级数"。
- **attack 的 key 是武器 id**，`controllerId` 才是操控角色（demo 已验证）；且**仅夜晚可发**。
- **火箭**：同时评估"3 发叠同一格（60 中心伤害）"与"3 发分散到相邻格（覆盖 3×3+，每邻 10 溅射）"，取期望总伤最高者；**密集小中群选分散，单体高血选叠加**。
- **电磁**：总伤恒定 → 优先"本轮能被 30 打死"的残血；无残血打 BOSS/大型（避免能量浪费在低血目标）。

### 6.5 夜间动作预算（每角色每回合 1 个动作，✅）

```
可用动作 = 已上人的武器数（默认 2，开拓者回盒时 3）
每一动作用于：操控武器 / WallFixer 修复 / 道具 / （开拓者：仅此三类）
```

**分配原则：**
1. **保住墙 > 输出**（墙破即失守；输出少一轮不致命）。
2. 修复需求超过 1 个动作/回合时 → 说明墙的等级不够，**次日白天立即给正面墙上升级券**（提升上限 = 减少修复频次）。
3. 应急道具优先级：

| 场景 | 道具 | 效果 |
|---|---|---|
| ≥3 只小/中挤在正面 | `Bomb` | 3×3 各 100 伤，直接清场 |
| BOSS/大型贴墙且墙将破 | `DizzyWeapon` | 3×3 眩晕 5 回合（少挨 5 回合 + 多打 5 回合） |
| 角色血量 < 60 | `Medicine` | 10 金回满，不要省 |
| 基地血量 < 40% 且仍在挨打 | `StationUpgradeVoucher` | 回满 + 上限提升（一次性，最强保命） |

### 6.6 防御充足性判据（决定是否召回开拓者）

```
今夜威胁量 ≈ Σ(机器人DPS) × 预计存活回合
我方吸收量 ≈ Σ(正面墙体当前血量 + 可修复量) + 基地当前血量 + 我方预计击杀总量
若 威胁 > 吸收量 × 0.8 → 触发预案：
   ① 召回开拓者（放弃当前任务）→ 第 3 个动作：第 3 座武器 / 修墙
   ② Bomb / DizzyWeapon
   ③ 基地升级券回血
早触发优于晚触发：基地归零没有第二次机会，任务明天还能再做。
```

**节拍红线：**
- `within ≥ 52` 后停止一切采集/采购，无条件回防（夜间盒外角色 200~220 血，被 BOSS 摸 5~6 次就死）。
- 角色阵亡 → 次日 `within 20` 才在基地复活 → **宁可少采 10 矿，不能让工人死在夜里**。
- 开拓者：有未完成任务时不得离开任务点；无任务时才回盒。

### 8.1 动作 ROI 排序表（v0.4 新增）

窗口期最贵的资源是**工人动作**，不是金币 —— 每个角色每回合只有 1 个动作。没有统一的排序函数，每个模块都会觉得自己的动作最优先。冲突时按此排序（数值为机会成本，越高越优先）：

| 优先级 | 动作 | 机会成本 | 理由 |
|:--:|---|---|---|
| 1 | 修"本回合将被击穿"的墙 | ∞ | 破口整夜有效且夜间不可重建 |
| 2 | 操控武器输出（夜间） | 高 | 不输出 = 白挨打，且机器人会累积 |
| 3 | 补门 / 建墙收尾（白天末尾） | 高 | 决定当夜是否有敞口 |
| 4 | 采集（喂 `stone_target`） | 中 | 防御的原材料，断供则修复停摆 |
| 5 | 一次成行的"卖 + 买" | 中 | 摊销移动成本，攒够再走 |
| 6 | 使用升级券 | 中 | 长线 DPS / 墙上限复利 |
| 7 | 移动 | 负 | 纯开销，能合并就合并 |
| 8 | 采集（超出 `stone_target` 的部分） | 低 | 金币收益，可延后 |

> **红线优先级（硬规则）**：当"保住红线 A（不产生异常）"与"拿任务分"冲突时（例如沙盒命令可能超时），**一律红线 A 优先**。这条要写成 planner 里的一行硬规则，不靠各模块自觉。

**阶段目标：**

| 天 | 防御 | 经济 | 任务 |
|---|---|---|---|
| 1 | 正面墙 6 面 + 2 座武器（-50 金）；完成 §7.1 锚定校验 | 摸清矿→金实际速率与波次强度 | 摸清题型族，跑通 accept→submit 全链路（**下界 2 回合**） |
| 2 | 主武器 L2；正面墙上券 | 完成首次"卖+买"合并出行 | 技能库落盘第 1 条；通过率反解跑通 |
| 3 | **主武器 L3**；围墙合围 | 现金储备 ≥150 | 技能库 ≥2 条；宝藏情报 ≥2 天 |
| 4–5 | 副武器 L3；正面墙 L2/L3 | 按物价窗口套利 | **技能库命中率 ≥50%**（v0.2 的"交付回合 ≤3"已被 §5.2 修正：未命中技能库时下界就是 2–3，该指标无法再压缩） |
| 6–8 | 基地升 L2（当回血用）+ 第 3 座武器（开拓者有空时） | 献祭物品预算就位 | 宝藏抢开窗口 |
| 9–10 | 全线维修保命 | 清库存 | 任务点可能耗尽 → 转修墙/防御 |

## 9. 对手博弈

**核心推论（✅ 所有建筑均不可被攻击）：** 双方都只能靠机器人波浪伤害对手，而机器人波浪又能被围墙环 + 修复挡住 → **半场大概率不会以"基地被摧毁"结束，而是落到比分比较上**。三个直接后果：

1. **任务线的相对权重进一步上升**——比分定胜负时，`score₁` 就是唯一的胜负手。
2. **召唤令从"进攻手段"退化为"对手临界时的补刀工具"**，触发条件必须严格（§9.2）。
3. **我方防御的真正对手不是对手的火力，而是对手的召唤令**。所以防御预算要给"某一夜突然多出 1~2 只 BOSS"留冗余：正面墙等级与修复金币储备不能卡在"刚好够用"。

### 9.1 情报通道（免费、全程可用）

> ✅ **实测修正**：接口文档说 `RobotRole` 有 `targetTeam` 字段，但 **`docs/request.txt` 样例里不存在**。
> 因此"按 `targetTeam` 筛出打对手的机器人"这条通道**不可用**（除非实盘中该字段确实出现，那就当白捡）。
> 替代方案：用**对手围墙 / 对手基地血量的逐回合差值**反推对手防御 DPS —— 这两项全局可见、**必定存在**，可靠性更高。

| 通道 | 可读信息 | 用途 |
|---|---|---|
| 对手基地（全局可见） | 血量、等级 | 判断对手承压程度 |
| 对手围墙（全局可见） | 位置、血量、等级 | **数出其围墙面数**：若正面墙不足/等级全 L1 → 对手防御薄弱 → 召唤令窗口 |
| 全部机器人（全局可见） | 位置、血量 | ⚠️ **`targetTeam` 不可用**（见下），改用"对手围墙 / 对手基地血量的逐回合差值"反推对手防御 DPS；再对照其基地血量曲线 → 判断"还能撑几个回合" |
| **我方波次的数量突变** | 与自测波次曲线拟合值比对 | **超出拟合曲线的额外机器人 = 对手使用了召唤令**（我们看不到对手的购买/使用动作，这是唯一信号）→ 据此判断对手的金币去向与针对意图，并据此上调我方正面的防御冗余 |

### 9.2 唯一的进攻手段：机器人召唤令

建筑不可攻击（✅③）→ **要让对手基地先倒，只能靠"叠加它自己的夜袭波次"**。召唤令叠加在对手下个夜晚的基础波次上，每天上限 10 张。

| 型号 | 价 | 血/伤 | 说明 |
|---|---|---|---|
| 小 | 20 | 40 / 5 | 便宜，凑数 |
| 中 | 30 | 60 / 10 | — |
| 大 | 100 | 500 / 20 | 性价比拐点 |
| BOSS | 200 | 800 / 40 | 破墙主力 |

**成本量级提醒**：对手一个完整围墙环 = 20×1000 = **20000 血**。纯靠召唤令砸穿极贵（10 张 BOSS = 2000 金 = 8 次武器升级）。所以：

```
破局触发条件（三者同时满足才出手）：
  ① 对手基地血量 < 800，或
     对手正面围墙出现缺口/多面残血（可从全局可见的围墙血量读出）
  ② 今夜对手波次威胁 > 我们估算的对手吸收能力 × 0.8
  ③ 我方现金 > 我方防御与升级所需 + 300 金余量
出手量：1~2 张 BOSS（200~400 金），赌一次半场直接拿下
否则：不买召唤令（同金币投我方武器升级的长期收益更高）
```

**理由**：半场胜负只有"先丢基地"和"比分"两条路，而 **3 分的半场权重远大于比分差**；但召唤令是纯赌博，只有"对手已在临界点"时才是正期望。

### 9.3 不要做的事

- ❌ 用全图火箭去打**对手的**波次刷击杀分（一夜 ≈25 分，却可能帮对手守住基地，把 3 分半场送出去）。
- ❌ 靠近对手可建造区（其武器够得着我们，角色只有 200~220 血）。
- ❌ 用角色去卡对手的建造格（收益极低，且暴露在被其武器打击的范围内）。

## 10. 鲁棒性工程约束（红线 A）

| 约束 | 要求 |
|---|---|
| 响应时延 | 收到请求后 **<5 秒**必须返回；**绝不在请求线程内调用 LLM / 沙盒 / 网络** |
| 默认指令 | 每角色每回合都有绝对合法的兜底指令（`move` 到安全格 / `collect` 最近矿）；构造失败时返回**空指令集合**而非异常 |
| JSON 合法性 | 严格按接口拼装；⚠️ **`targetPos` 长度：电磁狙击炮恒为 1，加特林/火箭 = 当前等级**（v0.3 曾误写成"一律 = 等级数"）；`num`/`item`/`controllerId` 等字段齐全（字段缺失 = 异常）；**顶层三字段永远齐备**（`roleCommandMap`/`prompt`/`executeCmd`，无内容发 `""`） |
| 指令合法性 | `attack` 的 key 是**武器 id**，`controllerId` 才是操控角色；**仅夜晚可发 attack**；校验器必须是**全函数（永不抛异常）**，且对组装完成的最终报文**再校验一次**，失败条目逐条剔除并记日志 |
| 异步状态机 | `prompt→llmResp`（固定 1 回合）、`executeCmd→lastCmdResult` 均为跨回合异步，用状态机登记待回填任务 |
| 结果回读 | 每回合读 `lastRoundRoleActionResults` 修正世界模型；失败动作不重试同参数，探测类失败写入负知识库 |
| 错误监控 | `errorCode 5`（LLM 超限）→ 暂停 prompt；`errorCode 2`（答案错误）→ 更新技能库继续迭代 |
| 日志复盘 | 每回合落盘完整 request/response + 决策理由（赛后重建"对手在干什么"、校准波次曲线） |
| 降级链路 | 由**观测驱动**而非"算不出来才降级"：`NORMAL → CONSERVATIVE → MINIMAL → EMPTY`。触发条件 = 首次见到 `errorCode 4` / 校验器剔除了条目 / 响应逼近 deadline。`EMPTY`（三字段全空）永远不会造成异常，是最强兜底 |
| 落盘解耦 | 日志的压缩+加密+`fsync` **必须在请求线程之外**（后台队列 + 单 writer 线程），否则是 5 秒闸门最大的现实威胁 |
