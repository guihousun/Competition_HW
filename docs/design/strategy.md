# 《未来战争》v1.0 对局策略

> 版本：v0.1（草案）  日期：2026-09-13
> 依据：`docs/任务书.md`、`docs/接口文档.md`、`docs/request.txt`、`docs/response.txt`
>
> 标记约定：
> **✅** 由规则/接口原文可直接推出的结论；**⚠️** 需要实盘验证的推断；**❗** 高价值、必须优先验证的未知项。

## 0. 一页纸结论

1. **本局本质是"双人各自打塔防 + 比分数"的 PvE 竞速，不是 PvP。** 角色无攻击能力、只能在自己基地旁的可建造区建武器，双方主力火力互相够不着（除非火箭 L3 全图射程❗）。因此**胜负主要由自身的执行质量决定，而不是压制对手**。
2. **任务分（score₁）是绝对主战场，且"快"比"对"更值钱。** `score₁ = 奖励 + 5 × 标准回合 / 实际回合`，一个 std=30 的任务 2 回合交付得 125 分、20 回合交付只 57.5 分。**自进化类任务的技能库（SOP 复用）是本局最大的可增量收益来源。**
3. **生存分（score₃）是硬门槛而非增量**：满额仅 550 分，但基地先被摧毁 = **直接判负半场**（3 分，单项最大得失）。所以白天一切经济活动都要给"今夜基地不死"让路。
4. **击杀分（score₂）是可以忽略的量级**（一整夜约 20–30 分），只在"顺手/保命"时打，绝不为刷分牺牲基地或任务。
5. **防御的经济学核心是"金币 → 吸收伤害"的兑换率**：围墙 1 石≈1000 血（最划算）、修复包 10 金回满、眩晕/炸弹是应急按钮、武器升级券是长线投资。**石头不要卖，留作围墙**（1 金机会成本换 1000 点阻挡）。
6. **武器在没有升级前几乎无用**（L1 加特林 10 伤/回合，打死一只小机器人要 4 回合）。**目标是在第 3 天前做出 2 座 L3 武器**（约 500 金），这是防御线的第一优先级。
7. **开拓者是"全时任务机"，不是火力手**。任务点离基地约 10–15 格，且领取后离开即任务作废；因此夜间默认只有 2 名工人操作 2 座武器，第 3 座武器仅在开拓者当日任务冷却空窗时才建。
8. **一条红线贯穿全局：异常次数 ≥5 = 直接出局。** 所有策略都必须服从"每回合 5 秒内返回合法 JSON、绝不阻塞在 LLM/沙盒上"。

## 1. 规则解构：事实 → 战略含义

| # | 规则事实（✅） | 战略含义 |
|---|---|---|
| 1 | 角色无攻击能力；武器须由**站在其周围 1 格内的角色**操控，且**一个角色同时只能操控 1 座武器** | 最大同时火力 = 角色数。开拓者做任务时，**火力上限实际是 2 座武器**——这是全盘最强约束，决定了防御必须靠"墙 + 修复 + 基地回血"扛，而不是靠 DPS 堆死 |
| 2 | 武器全局上限 3 座，新建覆盖旧武器且等级重置为 L1 | 武器槽是稀缺资源；**不要用新建覆盖已升级的武器**；类型搭配一旦定下很难改 |
| 3 | 攻击仅黑夜可用；伤害回合末统一结算；结算顺序 = 武器攻击 > 机器人移动 | **当回合击杀的机器人不会移动/攻击**→优先"本轮能打死的目标"，等于同时减免伤害 |
| 4 | 机器人黑夜首回合全体出现、天亮首回合全体清除 | 机器人不需要"全歼"，只需要**让基地活过这一夜**；未打死的残血伤害全部浪费，所以**集火击杀 > 平均输出** |
| 5 | 基地 1500/3000/4500；**建筑升级后回满血** | 基地升级券 = 一次性大回血（最多 +1500/+3000）。**这是最便宜的"基地保命"按钮，必须预留金币**（100/150） |
| 6 | 围墙 1000/1500/2000，1 石建造，WallFixer 10 金回满 | **围墙是全游戏最高性价比的坦克**；修复优先级高于一切输出投资 |
| 7 | 矿石：石 1 / 铁 3 / 铜 5；单矿 10 次采空后随机刷新；工人采集 1 个/回合 | 收入 ≈ 1 矿/回合/工人；**"就近取矿 + 批量卖"是唯一拉高收入的手段**；石头的钱不能卖（要造墙），除非富余 |
| 8 | 矿区不会生成在可建造区域内 | 矿点必在远处，**采集与回防之间存在稳定的往返成本**，日间计划必须按"回合预算"排程 |
| 9 | 小贩、武器商店为全局中立单位，位置固定；买卖均需在周围 1 格内 | 一次"卖+买+回基地升级"是一条**三位一体采购链**，必须合并成一次出行（省 30+ 回合） |
| 10 | 视野 4 格；**敌方基地与围墙全局可见**，机器人全局可见 | 我们可**全程读取敌方基地血量/等级 + 围墙布局**；并可**通过敌方机器人血量逐回合变化反推敌方防御 DPS**——这是最关键的博弈情报通道（见 §9） |
| 11 | 敌方武器/角色不可见（除非进入我方 4 格视野） | 无法直接侦察敌方火力，只能间接推断 |
| 12 | 每队每日 3 次 LLM 配额，**自进化任务期间不限次且不计数** | 编队内不要自建 LLM 调用；`prompt/llmResp` 是唯一 LLM 通道，且**必须异步**（本回合发、下回合收） |
| 13 | `executeCmd` 每回合 1 条、≤15 秒、结果下回合返回；沙盒无外网 | 任务求解是"1 命令/回合"的慢速闭环；**必须写成状态机，不能阻塞**；首解慢、复解快 → 技能库是核心资产 |
| 14 | 异常仅三类：超时（连接 10s / 响应 5s）、响应格式错误、指令字段缺失或动作码非法 | **白天用 attack、移动碰撞、攻击落空都只算"指令执行失败"，不计异常**。这给了我们安全的探测/试错空间（可用来探测可建造区❗） |
| 15 | `summonTreasure` 只要合法就消耗献祭物品（无论是否开启成功） | **不能试错**，必须靠情报确定物品集合再动手 |
| 16 | 半场判定：基地先被摧毁者判负；否则比积分；同回合摧毁则比积分 | 半场目标 = "不先死 + 分高"。**赢半场 3 分，比分差重要得多** |

## 2. 目标函数：到底什么值得抢

```
总积分 = score₁(任务) + score₂(击杀) + score₃(生存)
score₁ = 任务奖励 + 5 × 标准回合数 / (实际完成回合 − 接取回合)
score₂ = Σ(机器人积分)     // 小1 中2 大4 BOSS10
score₃ = Σ_{day=1..10} 10 × day × 存活系数    // 满额 550
```

单回合价值量级对比（估算）：

| 收益项 | 量级 | 说明 |
|---|---|---|
| 1 个自进化任务（快速交付） | **100–200 分 + 30–60 金** | std 越大越快越值钱；两个任务点交替接取 |
| 1 个自进化任务（慢速交付） | 50–60 分 | 时间项几乎归零，等于只剩基础分 |
| 生存 1 天 | 10–100 分（递增） | 是"关卡门槛"而非可选项，基地死 = 半场判负 |
| 一夜击杀 10 只机器人 | ≈ 20–30 分 | 与任务差 5–10 倍，**顺路打即可** |
| 宝藏（长上下文类） | **"大量积分与金币"**（未知，估 ≥300 分） | 全图唯一，先开者得，与对手竞速 |

**结论：**
- **优先级 P0：任务流水线吞吐**（含宝藏推断）→ 决定半场积分胜负。
- **优先级 P1：防御充足性**（基地不死）→ 决定半场不判负。
- **优先级 P2：经济效率**（矿→金→升级）→ 支撑 P0/P1。
- **优先级 P3：击杀/骚扰** → 边际收益极低，只在顺手时做。

## 3. 核心战略：三线并行 + 两条红线

```
             ┌──────────────────────────────────────────────┐
             │  红线 A：异常次数 < 5（否则不再被调度）        │
             │  红线 B：绝不能成为"先丢基地"的一方            │
             └──────────────────────────────────────────────┘
   白天 (70 回合/天)                          夜晚 (60 回合/天)
   ┌──────────────┐  ┌──────────────┐        ┌────────────────────┐
   │ 任务线(开拓者)│  │ 经济线(工人) │        │ 防御线(全员)        │
   │ 接取→求解→交付│  │ 采矿→卖→采购 │        │ 站位→控武器→修复    │
   │ 兼顾宝藏推断  │  │ →建造/升级   │        │ →应急道具→保命      │
   └──────────────┘  └──────────────┘        └────────────────────┘
          ↑ 技能库/LLM                              ↑ 火力分配算法
```

**分工定式（默认态）：**

| 角色 | 白天 | 夜晚 | 备注 |
|---|---|---|---|
| 开拓者 10011 | 全时驻守任务点，接取→沙盒求解→提交；空闲时做宝藏推断/采购献祭品 | 任务冷却空窗时才回基地控第 3 座武器；否则靠近基地墙内待机 | **不参与采矿**（背包 40 格且任务金币已足够） |
| 工人 A 10010 | 采矿（就近不同矿）→ 批量卖 → 采购升级券/材料 → 回基地施工 | 操控主火力武器（L3 火箭/电磁） | 兼任围墙修复工 |
| 工人 B 10012 | 同上，与 A 分工不同矿点、不同采购批次 | 操控副火力武器 | 兼任应急道具手（炸弹/眩晕） |

## 4. 经济线

### 4.1 回合预算（一切以"回合"计价）

| 行为 | 回合成本 | 说明 |
|---|---|---|
| 移动 1 格（含对角） | 1 回合 | 切比雪夫移动，**对角不额外收费**，永远走对角 |
| 采集 1 矿 | 1 回合 → 1 矿 | 单矿总量 10，采空即刷新 |
| 批量贩卖 n 矿 | 1 回合 | 支持批量，**必须攒够再卖** |
| 批量购买 | 1 回合 | 同上 |
| 建造 1 面墙 / 1 座武器 | 1 回合 | 建造仅白天、工人、且目标在自身 1 格内 |
| 使用 1 张升级券 | 1 回合 | 需站在目标建筑 1 格内 |

**结论：单次行动的固定成本是 1 回合，而移动是纯开销。** 所以：
- 采集必须"到矿即采满 10 次"再走（把移动摊薄到 10 矿）；
- 卖/买必须合并成一次出行；
- 两个工人**不要抢同一座矿**（10 次采空后两人一起长途转移；分开各采 10 次可把移动成本减半）。

### 4.2 收入估算（⚠️ 需实盘校准）

设工人平均走 6 格到矿、每矿采 10 次：
- 单工人产出率 ≈ 10 / 16 ≈ 0.62 矿/回合 → 双工人 ≈ 1.25 矿/回合
- 均价按铁/铜混合 ≈ 3 金 → **≈ 3.8 金/回合 → 一个白天（70 回合）≈ 260 金**
- 加上任务金币（30×通过率，每日 4–8 个）→ **合计约 350–500 金/天**

### 4.3 采购优先级（金币按此顺序花）

| 优先级 | 项目 | 价格 | 理由 |
|---|---|---|---|
| 1 | `WeaponUpgradeVoucher1/2` | 100/150 | 长线 DPS，跨夜复利 |
| 2 | `WallFixer` / 围墙升级券 | 10 / 20 / 30 | 最便宜的"吸收伤害" |
| 3 | `StationUpgradeVoucher1/2` | 100/150 | **预留在手**，基地挨打时当作大回血 |
| 4 | `Medicine` | 10 | 工人/开拓者保命，常备 1–2 个 |
| 5 | `DizzyWeapon` / `Bomb` | 100 | 应急：BOSS 集群 / 小中集群 |
| 6 | 任务用品（献祭） | 15 × n | 仅在宝藏条件确定时购买 |
| 7 | 机器人召唤令 | 20–200 | 仅在"破局窗口"使用（见 §9.3） |
| — | 不建议 | — | 早期买召唤令、买无用的献祭品、卖石头 |

**现金储备规则：始终保留 ≥150 金**（= 基地升级券 1 张 + 修墙若干），除非当场就能确定今夜无威胁。

### 4.4 物价情报（推理类任务）

官方消息会预告矿区停工/供需变化 → 小贩回收价波动（例：铁矿停工 2 天 → 铁价上涨）。

**执行规则：**
1. 每天第 1 回合解析 `worldNews.officialNews`，产出结构化事件：`{矿种, 影响窗口[起始天,结束天], 方向(涨/跌), 是否停产}`。
2. **涨价预期 → 屯矿不卖**（背包就是仓库，工人 100 格足够）；停产预期 → 提前改采其他矿种。
3. **跌价预期 → 当天清仓**。
4. 价格窗口打开当天，把所有库存一次性批量卖出（1 回合卖空）。

> 解析优先用规则+关键词，LLM 仅作兜底（每日 3 次配额要省着用）。

## 5. 任务线（score₁ 主战场）

### 5.1 三种任务的执行模型

| 类型 | 获取 | 谁执行 | 关键动作 |
|---|---|---|---|
| 自进化类（任务点） | 开拓者站任务点 1 格内 `acceptTask` | 开拓者 | `executeCmd` 探测 + `submitAnswer` |
| 推理类（官方消息） | 新闻被动 | 全员（经济动作） | 卖矿套利（§4.4） |
| 长上下文类（民间传闻） | 新闻被动 | 开拓者 | 推断后 `summonTreasure` |

### 5.2 自进化类：技能库是核心资产

**任务生命周期（⚠️ 待验证细节）：**
```
acceptTask(回合 R) → 任务点冷却 30 回合
    ↓ 期间离开任务点 1 格 / 超时 / 阵亡 → 任务作废
提交正确答案 → 任务完成，实际完成回合 = 提交回合
```
**完成判定的时间是唯一的加分杠杆**：`5 × std / (完成 − 接取)`，最快是"接取下回合即提交"（=150 分奖励，std=30 时）。因此：

**节奏定式：**
1. **接取后第 2 回合先提交一个"最优猜测"**（哪怕不完整）。
   - 若答案错误：只报 `errorCode 2`，**不计队伍异常**，任务继续，我们保留了时间线；
   - 若答案正确：直接吃满时间奖励；
   - 若中途被迫中断（超时/离开）：按通过率结算，仍有保底分与金币。
   > ⚠️ 需验证："部分正确提交"是否会直接终止任务（若是则先提交猜测会锁死低分，须改策略）。
2. **同族任务的 SOP 复用**：`自进化类1` 与 `自进化类2` 是**固定题型族**（如"查北京天气/上海天气/广州天气"）。首题用沙盒探索出 SOP，之后**绕过探索直接作答**（本地模板/规则代码，不用 LLM），把实际回合压到 2–3。
3. **技能库持久化到磁盘**（按"题型指纹"索引），跨对局复用——第二场比赛开局就带着第一场学到的全部 SOP。
4. **任务点交替**：两个任务点各 30 回合冷却，开拓者在 A 点交付后立即去 B 点；两者都在冷却时才去做宝藏/采购/回防。
5. **任务点总数有上限**，用尽后开拓者转为备用火力手（见 §8）。

**沙盒命令编排（1 条/回合、≤15 秒、输出 ≤64KB）：**
- 用 heredoc 一次性下发多条 shell/python：`python3 - <<'EOF' ... EOF`，在 15 秒内做尽可能多的探测，把结论压成短输出。
- 输出务必精简（超过 64KB 会被截断），结果下回合从 `lastCmdResult` 读取，注意解析 `[exitCode:N]` / `[TIMEOUT]` / `[JUDGER_ERROR]` 前缀。
- 沙盒是"我们的第二台电脑"：可写文件、跑脚本、做数据比对——**把探索过程脚本化并在沙盒里留存**，为后续同名任务复用。

### 5.3 长上下文类：宝藏（高价值、一次性）

**情报积累模型：**
- 每日 `folkLegends` 追加一条情报（DAY1…DAYN），需推断三要素：**地点 / 开启时间 / 献祭物品集合**。
- 示例："西部有一石门，门需三钥" → 方位 + 结构 + 物品数量（3 件）。
- 物品集合必须**不多不少**（结果码 3 = 物品错误，且**物品照样被消耗**）。

**执行规则：**
1. 维护"情报台账"：按天累积原文 + 结构化假设（候选地点集合、候选物品集合、候选时间窗口）。
2. 用 LLM 做一次集中推理（每日 1 次配额，在情报足够时用），输出**候选地点清单 + 置信度**；用规则交叉验证（地点是否与已知要素相关：矿点/任务点/西南角/石门…）。
3. **只在置信度足够高时购买物品并出动**：物品 15 金/件，浪费一次 = 白扔 45–90 金 + 一次失败的开启。
4. 提交前做三项自检：targetPos 在开拓者周围 1 格内 ✓、`item` 与背包实际持有完全一致 ✓、时间窗口匹配 ✓。
5. 若是"同回合双方都成功则双方都获奖"，则**抢在对手之前**是关键；赛后回放要核对对手是在哪一天开的（`lastSummonTreasureResult` 与对方基地/角色的活动轨迹）。

**❗关键待验证：** 宝藏是否跨半场重置？若是，则第一半场推断出的**地点**可直接用于第二半场抢开（第一半场已消耗 → 除非重置否则第二半场无宝藏）。

### 5.4 LLM 配额分配（3 次/天，任务期间不限）

| 场景 | 用不用 | 说明 |
|---|---|---|
| 自进化任务求解 | 用（不限次） | 无成本，放心用；但每次调用 ≥1 回合延迟，SOP 复用优先 |
| 官方消息解析 | 规则优先，LLM 兜底 | 结构化抽取，规则可覆盖大部分 |
| 民间传闻宝藏推断 | 每天 1 次 | 情报累积够多时集中推理 |
| 战斗/经济决策 | **绝不用** | 必须纯代码、毫秒级 |
| 沙盒探索循环 | 可用 | 任务期间不限次；仍要保 5 秒响应 |

## 6. 防御线

### 6.1 武器选型

三座武器槽、两名操作员（开拓者做任务时）→ **默认只建 2 座，聚焦升级**。

| 武器 | L1 | L2 | L3 | 定位 |
|---|---|---|---|---|
| 加特林 | 10/回合，射程 3 | 20，射程 5 | 30，射程 7 | 持续单体输出，但射程短、需 90° 锥形约束 |
| 电磁狙击炮 | 10，射程 6 | 20，射程 8 | 30，射程 10 | 持续单体，射程长，能量穿透（总伤恒定 30，**不会溢出**） |
| 火箭发射台 | 20/3回合，射程 10 | 40/3回合，射程 15 | 60/3回合，**全图** | AoE 溅射 + 全图打击，**战略武器** |

**击杀阈值表（回合数，单体）✅：**

| 目标 | 加特林 L1/L2/L3 | 电磁 L1/L2/L3 | 火箭 L1/L2/L3（每 3 回合一轮） |
|---|---|---|---|
| 小(40) | 4 / 2 / 2 | 4 / 2 / 2 | 2 / **1** / **1** 轮 |
| 中(60) | 6 / 3 / 2 | 6 / 3 / 2 | 3 / 2 / **1** 轮 |
| 大(500) | 50 / 25 / 17 | 50 / 25 / 17 | 25 / 13 / 9 轮 |
| BOSS(800) | 80 / 40 / 27 | 80 / 40 / 27 | 40 / 20 / 14 轮 |

**推荐组合：`火箭发射台 ×1（主升级）+ 电磁狙击炮 ×1`**
- 第一把武器优先升到 **L3 火箭**（25 建 + 100 + 150 = 275 金）：全图射程带来三重收益——① 覆盖任意来袭集群；② 可先手打击远处来敌；③ **可越图打击敌方基地/围墙（❗待验证，若成立则是最强的破局手段）**。
- 第二把走电磁/加特林到 L3（250 金）：**稳定的单体持续输出**，弥补火箭 3 回合冷却的爆发空窗。
- 若实测波次以"密集小中机器人"为主，则改为双火箭（溅射收益极高）。

> ⚠️ 选型需在拿到"每日波次曲线"（数量/种类/HP）后重算一次，见 §11 实验 1。

### 6.2 站位与围墙

**基本形制：内层武器、外层围墙、操作员在墙内紧贴武器。**

```
        ▓▓▓▓▓▓▓▓▓▓▓▓    ← 黄区围墙（闭合环，1~2 层）
        ▓          ▓
        ▓   ████   ▓    █ = 蓝区武器/基地（我方单位全部在环内）
        ▓   ████   ▓        操作员站在武器相邻格
        ▓          ▓
        ▓▓▓▓▓▓▓▓▓▓▓▓
```
- **闭合优于留口**：机器人只攻击"阻挡其移动的单位"，闭合环强制它们先拆墙，为我方武器争取输出时间。
- **多层优于单层**：每层墙 = 独立 1000 血，且每层都可 10 金回满 → 边际性价比极高。
- **❗必须验证"我方弹道是否被自己的墙阻挡"**：若阻挡，则需要在武器射界方向留出射孔/缺口（加特林/电磁是直线弹道，火箭不受阻挡）。这是布局方案能否成立的前提。
- 白天围墙可以留缺口方便工人进出，**入夜前（within ≈ 65）封口**（1 回合 1 面墙）。

### 6.3 夜间火力分配算法（每回合、纯代码）

```
for weapon in manned_weapons:
    enemies = robots within chebyshev_range(weapon.pos, weapon.range)
    if 无目标: 该角色转为修复/待机
    candidates = []
    for r in enemies:
        killable = (r.hp <= damage_of_one_shot(weapon, r))   # 本轮可击杀
        threat   = r.dps * proximity_weight(r, base)          # 越靠近基地越危险
        score    = threat + (killable ? kill_bonus + 击杀积分 : 0)
        candidates.append((score, r))
    选择得分最高者；同分时优先"本轮可击杀"、再优先"高 DPS 目标(BOSS>大>中>小)"
```

**要点：**
- **集火**：未打死的伤害在天亮时全部清零，所以宁可把 3 发子弹打在同一只残血机器人上。
- **加特林 90° 锥形**：所有目标相对加特林的方向夹角 ≤90°，否则**整次攻击非法**。安全兜底：3 个落点填同一个坐标（夹角 0° 永远合法）。
- **落点数组长度必须等于武器等级数**（L3 传 3 个），不足时用重复坐标补齐。
- **火箭多导弹**：同时评估"3 发叠同一格（60 中心伤害）"与"3 发分散到相邻格（覆盖 3×3+，溅射 10/格）"，取期望总伤最高者；密集小中群优先分散。
- **电磁**：总伤恒定，优先打"本轮能被 30 打死"的残血目标；无残血时打 BOSS/大型（避免能量浪费在小目标上）。

**应急道具（占用该角色本回合动作）：**
| 场景 | 道具 | 效果 |
|---|---|---|
| 3 只以上小/中机器人挤在一起 | `Bomb` | 3×3 各 100 伤，直接清场 |
| BOSS/大型贴脸且墙快破 | `DizzyWeapon` | 3×3 眩晕 5 回合（= 少挨 5 回合 + 我方多打 5 回合） |
| 工人血量 < 60 | `Medicine` | 10 金回满，**不要省** |
| 围墙血量 < 200 且有机器人在拆 | `WallFixer` | 10 金回满 |
| 基地血量 < 40% 且仍在挨打 | `StationUpgradeVoucher` | 回满 + 上限提升（一次性，效果最强） |

### 6.4 防御充足性判据（决定是否"召回开拓者"）

```
今夜威胁总量 ≈ Σ(机器人DPS) × 预计存活回合数
我方吸收能力 ≈ Σ(围墙血量 + 可修复量) + 基地当前血量 + 我方击杀总量
若 威胁 > 吸收能力 × 0.8  →  触发升级预案：
    ① 召回开拓者操作第 3 座武器（放弃当前任务）
    ② 购入/使用 Bomb、DizzyWeapon
    ③ 使用基地升级券回血
    ④ 动用召唤令无意义（那是打对手的）
```
> 早触发优于晚触发：基地一旦跌破 0 就没有第二次机会，而任务可以明天再做。

## 7. 建造蓝图与"可建造区探测"

### 7.1 ❗可建造区不在接口里

`mapInfo.zones` **只包含矿点/小贩/武器商店/任务点**，没有蓝区（可建武器）与黄区（可建围墙）。必须自行获取：

**方案：构造式探测（利用"执行失败不计异常"）**
1. 以**己方基地左上角坐标**为锚点（基地 2×2），建立"相对偏移 → 可建类型"的本地知识表。
2. 逐回合发起 `build`，用 `lastRoundRoleActionResults[workerId]` 的 true/false 判定该格是否合法。
3. 探测成本：围墙探测只需 1 石头（且**成功即留下真墙、失败即失败**，几乎零浪费）；武器探测 25 金/次，**只在确定蓝区后一两次内完成**。
4. **跨半场/跨对局复用**：地图同一张、基地与可建造区的相对布局大概率固定 → 第一半场学到的偏移表，第二半场直接使用，仅按 `teamOur.type` 做镜像变换。

### 7.2 已知的地图要素（示例局 `request.txt`）

| 要素 | 坐标 | 距挑战者基地(10,24) |
|---|---|---|
| 挑战者任务点1 | (14,14) | ≈10 |
| 挑战者任务点2 | (17,17) 双格 | ≈10 |
| 小贩 | (20,16) | ≈10 |
| 武器商店 | (25,20) | ≈15 |
| 守卫者基地 | (30,10) | ≈24 |
| 矿点 | 6 个（石×2 铁×2 铜×2）随机刷 | — |

**推论：**
- 卖矿（10 格）与买货（15 格）与采矿点（随机）构成**三角往返**，商店那一趟最贵 → **一次出行同时完成 卖+买**，且尽量由"顺路"的工人执行。
- 任务点紧邻小贩/商店（(14,14) 到 (20,16) 仅 6 格）→ **开拓者在任务冷却期可顺路做献祭品采购**。
- 防御纵深方向 = 基地朝地图中心（挑战者基地在左上，来敌大概率自右侧/下方来）→ 围墙应**朝地图中心一侧加厚**。

## 8. 日程模板（以回合为准，天 d 的回合区间 = [130(d−1)+1, 130d]）

```
within = (round - 1) % 130 + 1     # 1..130
phase  = "白天" if within <= 70 else "夜晚"
```

| within | 白天事项 | 夜晚事项 |
|---|---|---|
| 1 | 解析世界新闻 → 更新物价模型与宝藏情报；本轮决策预算（采/卖/建） | — |
| 2–10 | 施工窗口：建/升级武器、补墙、封口前的准备工作 | — |
| 10–55 | 采集（就近不同矿）→ 攒够批量 → 出发（卖→买→回基地升级） | — |
| 55–65 | **回防倒计时**：全员向武器站位移动（离基地越远越早出发） | — |
| 66–70 | 围墙封口；修复残墙；使用基地升级券（如需要）；确认站位合法性 | — |
| 71–130 | — | 每回合：分配火力 → 执行；残墙修复；血量危险时用道具 |
| 130 夜末 | — | 记录今夜波次数据（数量/类型/初始 HP/路径）用于外推 |

**关键节拍规则：**
- `within ≥ 55` 后，任何"采集/采购"行动视为**超时风险**，直接放弃回防。
- 工人阵亡 → 次日 `within 20` 才复活，等于丢掉上午经济与一次采购 —— **宁可少采 10 矿，也不要让工人死在夜里**。
- 开拓者：只要当前有未完成任务，**优先在任务点附近活动**（离开 1 格即作废）；无任务时才回防操控第 3 座武器。

**阶段目标：**

| 天 | 防御目标 | 经济目标 | 任务目标 |
|---|---|---|---|
| 1 | 2 座武器落地（-50 金），围墙 4–6 面 | 摸清"矿→金"实际速率与波次强度 | 摸清题型族，跑通 accept→submit 全链路 |
| 2 | 主武器 L2 | 完成首次"卖+买"合并出行 | 技能库落盘第 1 条 |
| 3 | **主武器 L3** | 现金储备 ≥150 | 技能库 ≥2 条；宝藏情报 ≥2 天 |
| 4–5 | 副武器 L3；围墙 2 层 | 按物价窗口套利 | 任务流水线稳定（交付 ≤3 回合） |
| 6–8 | 基地升 L2（当成回血用）+ 第 3 座武器（开拓者有空时） | 献祭物品预算就位 | 宝藏抢开窗口 |
| 9–10 | 全线维修保命 | 清库存 | 任务点可能耗尽 → 转宝藏/防御 |

## 9. 对手博弈

### 9.1 情报通道（免费且全程可用）

| 通道 | 可读信息 | 用途 |
|---|---|---|
| `teamEnemy.roles` 中的基地 | 血量、等级 | 判断对手承压程度、是否进入"可击杀窗口" |
| `teamEnemy.roles` 中的围墙 | 位置、血量、等级 | 评估对手防御投入与布局质量（**没围墙 = 弱**） |
| `robot.roles`（全图可见） | 每只机器人的位置、血量、`targetTeam` | **逐回合比对对手方机器人血量差 → 反推对手防御 DPS** |
| 对手基地血量曲线 | 逐回合变化 | 直接反映对手是否顶得住 |

> 这三条通道合起来，可以在不开视野的情况下**相当准确地评估对手的防御强度曲线**，是所有破局决策的输入。

### 9.2 破局手段（仅在有利时使用）

| 手段 | 成本 | 前提 | 收益 |
|---|---|---|---|
| 火箭 L3 轰击敌方基地 | 275 金（武器总投入） | ❗需验证建筑是否为合法攻击目标 | 60 伤/3 回合 = 20/回合 → 一夜 ≈1200 伤，数夜可摧毁敌方 L1 基地 |
| 火箭 L3 轰击敌方围墙 | 同上 | 同上 | 在其波次到来时开洞，形成"机器人海"灌入 |
| 机器人召唤令 | 小 20 / 中 30 / 大 100 / BOSS 200（每日上限 10 张） | 对手防御已接近临界 | 直接击溃对手基地 = **半场判负对手（3 分）** |

**决策规则（明确的触发条件，避免凭感觉）：**
```
若 对手基地血量 < 800 且 今夜对手波次威胁 > 我们估算的对手吸收能力 × 0.8
   → 追加 1~2 张 BOSS 召唤令（200~400 金），赌一次半场直接拿下
否则
   → 不买召唤令（同等金币投入我方武器升级的长期收益更高）
```
理由：半场胜负只有"先死基地"和"比分"两条路，而 **3 分的半场权重远大于比分差**；但召唤令是纯赌博，只有"对手已在临界点"时才是正期望。

### 9.3 不要做的事

- ❌ **不要为了刷击杀分而用全图火箭去打对手的波次**：一整夜 ≈25 分，却可能帮对手守住基地（把 3 分的半场胜势送出去）。
- ❌ 不要靠近对手可建造区（其武器能打到我们，我们的角色只有 200–220 血）。
- ❌ 不要在对手视野内暴露工人行进路线（对手可能用角色卡位/阻挡我们的建造格）。

## 10. 鲁棒性工程约束（红线 A）

| 约束 | 要求 |
|---|---|
| 响应时延 | 收到请求后 **<5 秒**必须返回；**绝不在请求处理线程里调用 LLM、沙盒或任何网络** |
| 默认指令 | 每个角色每回合都必须有一条**绝对合法**的兜底指令（如 `move` 到安全格 / `collect` 到最近矿）；构造失败时返回"空指令集合"而非异常 |
| JSON 合法性 | 严格按接口文档字段拼装；`targetPos` 数组长度、`num`、`item` 等必填项缺失 = **异常**（唯一会累计 5 次出局的情形之一） |
| 异步状态机 | `prompt → llmResp`、`executeCmd → lastCmdResult` 均为**跨回合异步**，用状态机登记"待回填任务"，下回合解析 |
| 结果回读 | 每回合读 `lastRoundRoleActionResults` 修正世界模型（失败的动作不重试同样参数，探测类失败写入负知识库） |
| 错误监控 | 监控 `errors[]`：`errorCode 5`（LLM 超限）→ 暂停 prompt 提交；`errorCode 2`（答案错误）→ 更新技能库、继续迭代 |
| 日志与复盘 | 每回合落盘完整 request/response + 决策理由（便于赛后重建"对手在干什么"） |

**降级链路（任一模块故障时）：**
```
正常策略 → 简化策略（只采最近矿/只打最近敌人） → 兜底空指令
```

### 12.3 关键公式与阈值

```
日/夜判定：within = (round-1) % 130 + 1；白天 = within ≤ 70
回防截止：within ≥ 55 停止一切非回防行动
武器单发伤害：加特林 10×弹数；电磁 能量穿透 min(剩余能量, 目标HP)；火箭 中心20 + 8邻10（多弹重叠叠加）
物理伤害需求（单体击杀回合）见 §6.1 表
防御触发阈值：今夜威胁总量 > 吸收能力 × 0.8 → 触发升级预案
破局触发阈值：对手基地血量 < 800 且对手波次威胁 > 其吸收能力 × 0.8 → 追加 BOSS 召唤令
```
