## 1. 一句话概括

在一个 41×32 的格点地图上，两队各守一座 2×2 基地。白天（70 回合）采集矿石换金币、造武器/围墙、开拓者做任务；夜晚（60 回合）机器人浪潮沿固定方向攻向基地，玩家操控角色手动驱动武器工事开火。存活 10 天（1300 回合）或一方基地先被摧毁即分胜负。

## 2. 时间与回合

| 项 | 值 | 来源 |
| --- | --- | --- |
| 一"天" | 130 回合 = 白天 70 + 黑夜 60 | 【明示】4.2 |
| 总上限 | 1300 回合 = 10 天 | 【明示】4.2 |
| 回合编号 | 从 1 开始，第 d 天白天 = `(d-1)*130+1 .. (d-1)*130+70`，黑夜 = `(d-1)*130+71 .. d*130` | 【推断】由"130 回合/天、10 天/场"推出 |
| 世界新闻 | 每个白天的第 1 回合发布 | 【明示】4.8 |

- 每回合**同时调度双方所有角色**，每个角色至多 1 条指令。【明示】4.2 / 接口文档 2.3 注
- 动作结算顺序：**武器攻击 > 机器人移动**；所有被攻击造成的伤害在**本回合结束后统一结算**。【明示】4.4
- 消耗品（眩晕法宝、范围炸弹）结算优先级 **>** 机器人移动。【明示】4.6.3
- 校验：样例 `roundNo=85` → `(85-1)//130 = 0` → 第 1 天，`85 > 70` → 第 1 天黑夜，场上有机器人 ✔（自洽）

## 3. 地图与坐标

- 41(X) × 32(Y)，原点 `(0,0)` 在**左下角**，X 向右、Y 向上。【明示】4.1
- 距离一律用**切比雪夫距离** `max(|dx|,|dy|)`。【明示】4.5.4
- 移动：8 方向、每回合 1 格；**两个障碍物相邻时，其对角线位置不构成阻挡**（可对角穿过）。【明示】4.5.4

### 3.1 阻挡移动的元素

己方/敌方建筑（基地、武器工事、围墙）、己方/敌方角色、机器人、中立单位（小贩、武器商店）、**4 个任务点**、矿区。【明示】4.1

> 注意：**任务点、小贩、武器商店、矿区都挡路**，等于地图上的固定障碍物；建筑被拆除后原地变可通行空地。

### 3.2 视野

- 己方所有单位（含建筑）视野距离 **4**（切比雪夫），全局共享视野。【明示】4.3
- 敌方**基地、围墙全图永久可见**，不受视野限制。【明示】4.3 / 接口文档 1.4
- **机器人全图可见**。【明示】
- 敌方角色/武器只有进入己方视野才在 `teamEnemy.roles` 里出现；**出现即消失是正常的，不能当作"被摧毁"**。【推断】接口文档 1.4 注

### 3.3 阵营与位置

- 挑战者（challenger）基地在**左上**，防守者（defender）基地在**右下**；上下半场换边，代码两种身份都要能跑。【明示】三、游戏概述
- 基地是 **2×2**，`pos` 给的是**左上角**坐标。【明示】接口文档 1.3.1 注
- 基地位置、机器人刷新点**固定**；矿区/任务点/小贩/武器商店**每局随机**。【明示】pic/大致地图信息.png

### 3.4 可建造区（关键）

任务书正文只给了颜色描述，`build_map.png` 给了几何关系：

```
中间黄 2×2 ：基地
绿色 4×4 外圈（不含基地） ：可建造武器，12 格
蓝色 6×6 外圈（不含 4×4）：可建造围墙，20 格
```

设我方基地左上角为 `(bx, by)`（基地占 `[bx,bx+1]×[by,by+1]`）：

| 区域 | 单元格集合 | 格数 |
| --- | --- | --- |
| 武器区 | `[bx-1, bx+2] × [by-1, by+2]` 去掉基地 2×2 | 12 |
| 围墙区 | `[bx-2, bx+3] × [by-2, by+3]` 去掉武器区、基地 | 20 |

- 【推断】这个"以基地为中心逐圈外扩"的规则是我从示意图推的，任务书正文没给坐标公式。**接口里 `mapInfo.zones` 只有矿/小贩/武器商店/任务点，不含可建造区**，所以可建造区只能按上式从基地坐标算。
- 【明示】矿区不会刷在可建造区里。
- 【矛盾】**样例 `request.txt` 里我方两座围墙在 `(5,20)`、`(5,21)`，与基地 `(10,24)` 按上式推出的围墙区 `x∈[8,13], y∈[21,26]` 不符**；但样例里其它 4 处建筑（我方 3 座武器 + 敌方 1 座围墙）都能被上式解释。判断：`request.txt` 是**手写文档样例**（里面 `errors` 的 description 直接写 `"xxx"`、武器 `attackRange` 与任务书表格也不符），**不可作为真值**。
- 【待验证】首次上线时，用 `build` + 下回合 `lastRoundRoleActionResults` 探测边界，确认公式（尤其"圈"是否严格对称、基地 pos 是左上还是别的角）。

## 5. 动作全集与权限（4.4 + 接口文档 2.3）

| 动作码 | 说明 | 关键参数 | 可用角色 | 限制 |
| --- | --- | --- | --- | --- |
| `move` | 移动 1 格 | `targetPos`(1) | 全部 | 碰撞见 6.3 |
| `attack` | 操控武器开火 | `targetPos`(1~n)、`controllerId` | 全部 | **仅黑夜**；操控者须在武器周围 1 格内；1 人只能操 1 座 |
| `sell` | 卖矿换金 | `name`、`num` | 全部 | 需在小贩周围 1 格 |
| `buy` | 商店购物 | `name`、`num` | 全部 | 需在武器商店周围 1 格 |
| `build` | 造武器/围墙 | `name`、`targetPos`(1) | **仅工人** | **仅白天**、目标须在自身 1 格内、须在可建造区、围墙需背包有石头 |
| `remove` | 拆围墙 | `targetPos`(1) | **仅工人** | 目标须在自身 1 格内 |
| `collect` | 采矿 | `targetPos`(1) | **仅工人** | 需在矿区周围 1 格 |
| `acceptTask` | 领任务 | — | **仅开拓者** | 需在**己方**任务点周围 1 格 |
| `submitAnswer` | 交答案 | `taskAnswer` | **仅开拓者** | — |
| `summonTreasure` | 献祭开宝藏 | `targetPos`(1)、`item[]` | **仅开拓者** | 需在自身 1 格内、`item` 须在背包 |
| `use` | 用消耗品/升级券 | `name`、有时 `targetPos` | 全部 | 见 7.3 |
| `drop` | 丢弃 | `name` | 全部 | — |

**必须记住的两条工程约束：**

1. **角色权限**：`build` / `remove` / `collect` 只能发给工人，`acceptTask` / `submitAnswer` / `summonTreasure` 只能发给开拓者。把工人的动作发给开拓者属于**非法指令**。
2. **指令字段完整性**：`move`/`attack` 缺 `targetPos`、`use` 眩晕法宝/范围炸弹缺 `targetPos`、动作码非法 → 属于**"指令错误"**，**计入队伍异常次数**（见第 11 节）。

> 区分：**非法指令**（字段缺失/动作码无法识别）= 异常，累计 5 次就出局；
> **指令执行失败**（指令合法但规则上没生效，如移动被撞、攻击落点无目标）= 只标记该条无效，**不计异常**（`lastRoundRoleActionResults[id]=false`）。

## 6. 战斗细节

### 6.1 攻击的前提

- **白天不能攻击**（`attack` 非法）。夜晚才开火。
- 角色**本身没有攻击力**，只是"炮手"：需要站在武器周围 1 格内，用 `controllerId` 指定自己，指令挂在**武器 ID** 上。
  - 样例见 `response.txt`：key=`10020`(武器)，value=`{action:attack, controllerId:"10010", targetPos:[...]}`。
- 一个角色同一时刻只能操控一座武器 ⇒ **3 座武器要同时开火就需要 3 个角色分别站在各自武器旁**。
- 攻击路径 = 两个坐标中心之间的直线。

### 6.2 三种武器的差异（【明示】4.5.4）

| | 加特林 gatling | 电磁狙击炮 railgun | 火箭发射台 rocket |
| --- | --- | --- | --- |
| 目标数 | 可多个（= 等级数） | **固定 1 个** | 可多个（= 等级数） |
| 多目标约束 | 所有目标须落在同一 **90° 锥**内（两两方向夹角 ≤ 90°，否则**整次攻击非法**） | — | — |
| 弹道 | 每颗子弹沿自身落点弹道飞行，**命中该弹道上最近的一台机器人即消耗** | **穿透**：沿弹道路径上每只存活机器人受 `min(剩余能量, 当前血量)` 伤害，能量按伤害量扣减，耗尽或到终点即止 | **导弹不会被阻挡**（指哪打哪） |
| 单发伤害 | 10 / 颗 | 10 / 20 / 30（= 能量值） | 中心 **20**，周围 8 格溅射 **10**（= 中心一半） |
| 冷却 | 无 | 无 | **发射后 3 回合空窗** |
| 叠加 | — | — | 多枚导弹落点重叠时**伤害叠加** |

- `targetPos` 的数量约束："加特林/火箭可传多个目标位置，**目标位置数与当前武器等级数相同**"。【明示】接口文档 2.2
  - 【推断】L1 传 1 个、L2 传 2 个、L3 传 3 个；所谓"目标位置数"应是**上限**，传少了大概也能打（需实测是否算失败）。
  - 【存疑】"与等级数相同"若是硬性要求，则 L2/L3 必须凑够目标数，否则整个动作失败——这会影响夜间调度逻辑（要预留兜底目标）。

### 6.3 移动碰撞（4.5.4）

触发条件：
1. **目标点受阻**：目标位置有障碍物，或被**本回合未移动**的其他角色/机器人占据；
2. **目标点争夺**：与其他角色/机器人预期移动到同一格；
3. **位置互换**：两名角色预期互移到对方当前格。

后果：

| 对撞对象 | 结果 |
| --- | --- |
| 角色（己方/敌方） | **双方都中断**，停在原位 |
| 障碍物 | **仅自己中断**，停在原位 |
| 机器人 | **双方都中断**，停在原位 |

> 自己的两个工人之间也会互相撞，编队移动要留间隔或用错开的目标格。

## 7. 经济与商店

### 7.1 采矿与卖矿

- 矿区 3 种：石矿→石头、铁矿→铁、铜矿→铜。【明示】4.1
- 每矿 **10 次采集后消失**，**下回合随机刷新**到地图其它位置（不进可建造区）。【明示】
- 【明示】"一个回合内矿石剩余量不足多个工人平分时，**每个工人都会获取一个矿石**" ⇒ **两个工人可以同时挖同一个矿，各拿 1 个**，采空当回合仍人人有份。这是白天效率的关键。
- 卖价随世界新闻波动，`vendorShopList` 每回合都会给当前价。样例：stone=1 / iron=3 / copper=5。【明示 + 样例】

### 7.2 金币产出与消耗（样例价）

- 采集速率：1 个/工人/回合；矿点 10 发。两个工人贴着一个铜矿轮流挖。
- 主要开销：

| 花销 | 价格 |
| --- | --- |
| 武器（L1） | 25 |
| 武器升级券1（L1→L2） | 100 |
| 武器升级券2（L2→L3） | 150 |
| 围墙升级券1 / 2 | 20 / 30 |
| 基地升级券1 / 2 | 100 / 150 |
| 围墙修复包 WallFixer | 10 |
| 生命药剂 Medicine | 10 |
| 眩晕法宝 DizzyWeapon | 100 |
| 范围炸弹 Bomb | 100 |
| 小/中/大/BOSS 机器人召唤令 | 20 / 30 / 100 / 200 |
| 任务用品（6 选 N，随地图刷） | 15 / 个 |

### 7.3 消耗品与升级券细则

- **升级券**（武器/围墙/基地）：需在**目标建筑周围 1 格内**使用并指定 `targetPos`。
  - 已满级再用**不生效、券不消失**；其它非法使用也**失败但不消耗**该券。【明示】
  - ⇒ 券只在**成功时**被扣，可以放心尝试。
- **WallFixer**：需站在待修复围墙 1 格内，目标围墙回满血。
- **Medicine**：使用者自己回满血。
- **DizzyWeapon**：`targetPos` 为中心的 **3×3** 内机器人**眩晕 5 回合**；无使用距离限制；**只对机器人有效**。
- **Bomb**：`targetPos` 为中心 **3×3** 内机器人 **100 伤害**；无距离限制；只对机器人有效。
- **机器人召唤令**：效果是**给对方下个夜晚加机器人**（是攻击手段，不是防御手段）；**每天最多用 10 张**。【明示】4.6.3
  - 【推断】"给对方添乱"能拖慢/打爆对面基地 → 影响半场胜负；但也会给对面送 `score2` 击杀分。是否值得买需按局势权衡。
- 所有商店商品**不支持退回/售卖**。

## 9. 任务体系（第五章）

三类任务、两种获取方式：

| 任务类型 | 通道 | 交互 | 谁能做 |
| --- | --- | --- | --- |
| 推理类 | 世界新闻（官方消息） | 被动，影响卖价 | 全队（影响经济） |
| 长上下文类 | 世界新闻（民间传闻） | 被动，推断宝藏地点/时间/祭品 | **开拓者** `summonTreasure` |
| 自进化类 | **任务点** | 主动 `acceptTask` → `executeCmd` 探索 → `submitAnswer` | **开拓者** |

### 9.1 自进化类任务的生命周期（关键）

- 在**己方**任务点 1 格内 `acceptTask` 领取；敌方任务点无效。【明示】4.6.2
- 任务点 2 占 **2 格**，站任一格都能领；任务点 1 占 1 格。
- **任务结束的 4 种情况**（任一发生即结束，无论是否完成，任务都消失）：
  1. 任务被完成；
  2. 从领任务起计数**超过 `timeoutRounds`**；
  3. **离开己方任务点周围 1 格内**；
  4. 领取任务的开拓者**死亡**。
- ⇒ **开拓者一旦领了任务，就必须钉在任务点旁边**，不能跑动。这是排班上的硬约束。
- 任务结束后任务点进入 **30 回合刷新冷却**（`coldDownRounds`）。
- 任务结束**无论完成与否**都给积分和金币；**金币 = 金币奖励 × 通过率**。【明示】第五章
- 积分：
  - 完整完成：`任务积分奖励 + 5 × timeoutRounds / (完成回合 - 接取回合)`（**越快分越高**）。
  - 部分完成：`任务积分奖励 × 通过率`，`通过率 = 答对字段数 / 全量字段数`。
  - 超时结束：**以之前提交过的通过率最高的答案**计算积分与金币。【明示】接口文档 1.3.2

### 9.2 沙盒与 LLM（接口文档）

- `executeCmd`：沙盒里执行 shell/python，**仅任务期间可用**，**每回合限时 15 秒**；沙盒无外网；沙盒故障/超时**不计队伍异常**。
- `prompt`：提交给 LLM 的内容，写在 response 里；结果在**下一回合**的 request `llmResp` 里返回（异步、1 回合延迟）。
- **LLM 配额：每队每个游戏日 3 次**，每天第 1 回合重置；**超额 → errorCode 5**。但**任务执行期间（接取到结束）不受限制、也不计数**。
- ⇒ 策略含义：把 LLM 预算压在"任务窗口内"，日常不要空烧。

### 9.3 宝藏（长上下文类）

- 全图**只有一个**宝藏，开启成功后**再开没有奖励**。
- 位置/条件/开启时间都要从每天的民间传闻里推断。
- 同一回合双方都满足条件且都正确 `summonTreasure`，**双方都拿奖励**（不是零和）。
- `lastSummonTreasureResult`：`0` 未探测 / `1` 成功 / `2` 无宝藏或未到时间 / `3` 献祭物品错误（多、少、错都报这个，无顺序要求）/ `4` 宝藏已空。
- ⚠️ `summonTreasure` **只要动作合法就消耗祭品**，即使开不出来。【明示】接口文档 2.3 注

### 9.4 官方消息（推理类）

- 影响**卖价**（也可能会影响采集，如"铁矿停工 2 天"）。示例：塌方新闻 ⇒ 当天正常，明天+后天铁矿**不可采**且回收**价格上涨**，大后天恢复。
- ⇒ 需要**解析新闻文本**，做出"今天该挖什么/什么时候卖"的决策。价格信号更直接地体现在每回合的 `vendorShopList`。

## 10. 积分与胜负

```
总积分 = score1(任务) + score2(击杀) + score3(生存)
```

- `score1`：任务完成 `任务积分奖励 + 5 × 标准回合数/(实际完成回合-接取回合)`；部分完成 `任务积分奖励 × 通过率`。
- `score2` = Σ(机器人击杀数 × 积分值)，即 1/2/4/10。【明示】4.7.2
- `score3` = Σ_{day=1..10} `10 × day × 存活系数`，存活系数 = 1（基地未被摧毁）/ 0（基地被摧毁当天及之后）。⇒ **第 10 天存活一天值 100 分**。

胜负：
1. **结束判定**：某方异常响应达 5 次；或 1300 回合跑完；或**双方基地均被摧毁**。
2. 同半场内：基地**同回合**被毁且积分相同 → 平局；不同回合先后被毁 → **先被毁者判负**；半场结束双方基地都还在 → 比积分。
3. 两半场：各赢一场 → 两半场得分总和比大小；胜 1 局得 3 分，平 1 分，负 0 分。

⇒ 战略主线：**活到最后 > 打爆对面基地 > 刷任务/击杀分**。"先死即负"意味着**防御优先级高于一切进攻行为**。

## 11. 接口与异常（工程约束，接口文档 + 第八章）

### 11.1 通信

- 判题器通过 **HTTP** 访问选手程序：`bash run.sh <port>`，监听 `0.0.0.0:<port>`。
- 请求体 = 地图状态（第 1 节 schema）；响应体 = `{roleCommandMap, prompt, executeCmd}`。
- 【项目既有认知，非本文档结论】平台约定入口文件名为 `main3.py`，改名会导致进程不启动——落到代码时按此约定。

### 11.2 异常（累计 5 次 = 该队本局不再被调度）

1. **请求响应超时**：建连 > 10s，或发送请求后 **5s 内未响应**。
2. **响应格式错误**：不符合接口文档规范。
3. **指令错误**：动作码无法识别 / 指令字段缺失（如 `move`、`attack` 缺 `targetPos`；`use` Bomb/DizzyWeapon 缺 `targetPos`）。

- **不计异常**：移动碰撞、攻击落点无目标等"指令合法但执行未生效"的情形；沙盒故障与 `executeCmd` 超时也不计入。
- 代码异常退出后**不再被拉起**。

⇒ 工程红线：**每回合必须在 5 秒内返回合法 JSON**；宁可少发动作，也不发非法动作。所有出站指令要做**角色权限 + 必填字段 + 白天/黑夜可用性**三重校验。

### 11.3 每回合必读的关键反馈

| 字段 | 用途 |
| --- | --- |
| `roundNo` | 判断昼夜、天数 |
| `lastRoundRoleActionResults` | 上回合每个角色动作是否合法 → **用它做失败重试/边界探测** |
| `vendorShopList` / `weaponShopList` | 当期价格（新闻会改卖价） |
| `worldNews` | 官方消息（价格/可采性）+ 民间传闻（宝藏线索） |
| `teamOur.roles[].health/level/cooldown` | 建筑血量、等级、火箭冷却 |
| `robot.roles` | 全图机器人（位置、血量、眩晕状态、targetTeam） |
| `phaseTask` / `llmResp` / `lastSummonTreasureResult` / `lastCmdResult` | 任务链路的状态回执 |
| `errors[]` | errorCode：0 未知 / 1 任务超时 / 2 答案错误 / 3 网络 / 4 指令错误 / 5 LLM 额度超限 |

## 12. 由规则直接推出的策略约束（供设计稿使用）

1. **开局**：0 武器 0 墙 75 金 ⇒ 第 1 天白天先造满 **3 座武器**（正好 75 金），再让工人挖石头砌墙。
2. **白天（70 回合）**：工人 = 采集 + 建造 + 卖矿 + 买券；开拓者 = 任务点蹲守。锄头要有分工。
3. **夜晚（60 回合）**：3 个角色必须**分别站到 3 座武器旁**才能同时开火（1 人只能操 1 座）；**白天不能攻击**，所以白天要把角色提前摆到炮位。
4. **围墙是唯一"可牺牲"的阻挡物**：机器人打挡路的东西，墙给基地争取时间；石头=1 金/个，性价比极高。
5. **升级券只在成功时消耗**，可以无风险试；武器 L1→L2 才 100 金但攻击距离/伤害/目标数都涨，性价比要按局势算。
6. **火箭发射台 L3 射程全图 + 20×3 + 溅射**：理论上可以打着对面基地/机器人刷新点，是唯一能越过前排的输出。
7. **开拓者领任务=原地不动**，且任务窗口内 LLM 不限量 ⇒ 任务可以"排队做"，但会锁死开拓者。
8. **不要给对面送 `score2`**：机器人召唤令是双刃剑，慎用（除非能直接压垮对面基地）。
9. **异常 5 次即出局**：每回合的生成本身要 try/except 兜底，最坏情况返回 `{}`（空 `roleCommandMap`）也远好过崩掉或超时。

## 14. 与 `docs/request.txt` 样例数据的差异记录

`request.txt` 是**文档手写样例**，多处与正文规则不符，**不可当真值**，仅用于确认字段结构：

- `gatling.attackRange=4`、`railgun.attackRange=7`、`rocket.attackRange=2147483647`（正文表格为 3/6/10）。
- 我方两座围墙 `(5,20)/(5,21)` 落在按基地 `(10,24)` 推出的围墙区之外。
- `errors[0].description = "xxx"`，明显是占位符。
- `teamOur.goldNum=20`、`totalScore=280`、`roundNo=85` 等只是示例状态，**开局并非如此**（开局：75 金、0 武器、0 墙）。
- 样例中出现了 `phaseTask=""`、`lastSummonTreasureResult=0`、`llmResp=""` 等空值形态，可作为解析时的默认值参考。
