# 用世界新闻处理推理与长上下文任务

依据：任务书 v1.0 §4.6.3、§5.1–5.2；接口 v1.0 §1.1、§2；用户补充 [Issue #29](https://github.com/guihousun/Competition_HW/issues/29)。
这是策略解释说明，不是新增官方规则。

推理类消息影响采矿可用性和交易时机。程序把公开消息按来源保存，由 LLM 给出带原文引文的事件，
再由代码检查日期、冲突和证据。第 2 天说“明天停工两天”，若确实观察到该日发布，
对应第 3–4 天停工、第 5 天恢复；第一次在第 4 天看到旧消息不意味着第 5 天才停工。
“通常两天左右”只能作为估计，恢复时间还应结合后续消息。实际买卖价格始终取本轮商店清单。

长上下文传闻需要跨天累积。地点、材料和开放条件分开记录，保留来源、否定与矛盾；
无关日的见闻不会清除旧线索。模型可以分段查看已收到的原文，每次新的 LLM 调用仍计入普通每日 3 次额度。
程序在固定 2000 字的原文前缀预算中，将短消息未用完的空间分配给长消息；这不是摘要，也不代表未展示部分已读。
备料、移动与献祭由现有策略执行，模型回执本身不是成功记录。

解释上下文附带任务书中的六种用品名称和外观，以及当前 `weaponShopList` 中的任务商品候选。
例如银白色、冰凉、暗处发光的细沙可以与 `StarSand` 的官方描述比较；这不意味着所有地图必买它，
也不意味着这个组合一定是宝藏答案。保留官方拼写 `AcientTablet`，未知用品不能凭参考表编造效果。

本次修复补充“第五日白昼”与“第五天白昼”的同义日期识别。仍需谨慎区分开放起点和完整开放窗口：
只知道何时开始，不自动假定何时结束。“北三公里、东三公里”还需要确认公里与格子的对应关系；
官方坐标轴 x 向东、y 向北并不能证明一公里就是一格。“西部”与后文位置的关系也不能凭空解释。
Issue #29 的两套日程作为不同示例保留，不能把其中缺失的第 4 天线索拼到另一局。

公司复测时，请保留：`worldNews` 原文/回合、模型回复、开拓者位置/背包、商店清单、
最终 `summonTreasure` 的位置与 item，以及下一轮 `lastSummonTreasureResult`。
结果码 1 才是成功；2 是无宝藏或未开放，3 是材料错误，4 是已空。合法失败也会消耗材料，不能反复盲试。
本地测试使用脚本构造模型回复，仅验证记忆、校验和实际动作链路，不代表真实模型解题成功或内网 PASS。
