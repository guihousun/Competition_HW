## 能够独立修复的缺陷

防御日志新增了一些字典结构，例如开拓者避险状态。任务日志器却统一按炮台列表遍历，
对字典的字符串键调用 `.pop()` 引发异常。日志外层为了不影响比赛响应吞掉异常，
导致整轮任务事件丢失，部分去重状态却已更新。这不等于动作没有执行。

同样的代码存在于实际反馈版本及修复前的当前版本。本次仅针对字段形状修正签名计算，
保留炮台冷却的既有去重，字典状态原样保留。独立测试先复现失败，再验证修复。
这解释了一个真实的日志缺口来源；没有原始输入，仍不能把 pk-609125 的所有日志缺失都归因于它。
尤其不能从“没打印 acceptTask”断定“没执行 acceptTask”。

## 暂不修改模拟器的结论

| 报告条目 | 当前判断 |
|---|---|
| `complete=1, invalid=5` 与只有两个日志 episode | 日志存在可复现缺陷；还需回放计数定义和原始输入，不能把计数直接当作接题次数 |
| replay.score=226 / totalPointB=256 | 差额30，与第3天基地被毁时前两天生存分10+20一致；仅为待确认解释 |
| 数字 roleType=31/32 | 回放编码与HTTP字符串枚举不同；在未知映射前，不改参赛协议或模拟器类型 |
| 初始3塔 | 报告自己的R0类型表只有基地/两工人/开拓者，后文塔数量需核对具体帧；阵容计划不是初始实体证据 |
| 总LLM交互13（6+5+3） | 分项和为14，需明确“请求/回复/回合”的统计单位 |
| 初始75、最终10，因此支出65 | 这是净减少；有任务奖励等收入时，不能据此求总支出 |
| 非任务增分138 | 需区分击杀、生存、任务部分结算等；不能自行新增“采集/摧毁建筑得分”规则 |

规则依据：任务书第六章生存积分为 `sum(10*day*存活系数)`，基地被毁当天及之后系数为0；
总分与回放字段是否采取相同结算时点，还需原始结果确认。数值巧合不等于系统差异已经消除。
