# 机器人攻击基地修复

类别：官方实现修复 / UI工具。依据 R02（任务书 §4.1，基地 2×2）与 R05
（§4.7.3，机器人攻击阻挡移动的角色/建筑）。基线为本地 codex/gap-llm 提交 0623fc1。

根因：建筑阻挡检测仅检查 mapInfo.zones，基地却主要存在 teamOur.roles，地点类型也可能是
challengerBase/defenderBase。即使发现基地的非锚点格，按单一 pos 查找扣血对象仍会失败。
这会使机器人停在基地附近却无法扣血。只有带 wall 地点的围墙测试，无法覆盖实际生成地图。

修复：从角色记录查建筑身份、血量与完整占地；以建筑 ID 扣血；无角色可追逐时寻找当前目标队伍
的建筑；事件增加建筑种类，前端显示“攻击基地”，而不是“攻击角色 undefined”。

独立验收：基地锚点 (10,5)，机器人从左/右/上/下的相邻格攻击，一级基地每次 1500→1495。
无地点记录和不同基地地点名都应相同。5 血围墙被打掉后，机器人继续接近并攻击基地；致命伤为 0，
而非负血。输入快照保持不变。修复前新测试的 11 个子用例失败。

不调整机器人 HP、伤害、射程、数量与刷怪点，也不新增“永远优先打基地”的规则。
现有优先追逐行动角色的选敌算法仍是本地约定；这可能让机器人先打角色或沿路围墙。
固定刷怪点与完整双队终局缺口仍在，本地测试不是官方认证。旧录像不会被重新结算。
