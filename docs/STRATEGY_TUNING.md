# 当前策略与微调入口

唯一可编辑配置是仓库根目录 `strategy.json`。采用 JSON 是为了让公司 Python 3.11 环境无需安装 PyYAML；JSON 也是 YAML 1.2 的子集，但本项目加载器只接受 JSON 语法。不要加注释、尾逗号或创建另一份 YAML 配置。

## 当前采用的方案

- 三座火炮（默认 `rocket / rocket / rocket`），优先寻找一个工人不用移动就能覆盖三座炮的共同操控位；每人每轮仍只能操作一座炮，利用冷却轮换。白天通过基地后侧开口安排入位；实际地图找不到可达的共同操控位时采用安全回退，不把非法站位当作已完成一人三炮。
- 前三天允许其他角色在安全且能及时回防时发展经济或做任务。
- 第四天起**夜间**全员参加防守；白天继续采矿、买卖、任务与建设，不是第四天起全天停工。
- 从第一天就允许朝三炮 `333` 升级，有钱且路线允许便采购，不再人为等待第二天才能升二级、第三天才能升三级。相同条件下先补齐全部二级，再升级三级；争取前四天全部三级，第四天后未完成仍继续补齐。配置中的 `333` 是允许投资的目标，不是承诺第一天完成；金币、商店和路线条件仍会限制进度。三座一级武器全部升到三级按官方列价共需 750 金币，采购以实际观测报价为准。
- 城墙升级依次考虑最前沿**正中央两堵**、前沿两侧另两堵、前沿两端的两堵拐角墙、其他墙；已经三级的墙退出候选。普通墙损耗不会抢走炮台升级预算；前六墙低于紧急阈值时整个前六墙组可提前升级，组内仍按中央→两侧→拐角排序，基地濒危的救援优先级更高。
- 最后方整排墙（包括后侧两个角）退出计划防线，不再新建、回填或追加升级与常规维修投资；不是取消所有侧墙。已有后墙保留，不会为了新布局自动整排拆除，只有符合原受限交通恢复规则时才可能拆除某堵非前六墙。后排由己方基地和迎敌方向动态计算，这属于资源分配策略，不把后排改成官方禁建区。
- 后期为城墙准备维修物品，低血量时修复，达到恢复阈值后释放维修角色；夜间清场后允许为白天准备。
- 白天回防采用动态路径预算：优先计算当前角色返回炮位/安全内侧的公开最短路，再扣除入夜前余量。默认前3天保留4轮，第4天起保留6轮，基地或前六墙受损保留8轮；路径未知时才回退 `return_day_index=55`。近处矿点可以晚些工作，远处或绕路目标仍会提前返回。

布局必须由当前己方基地和合法建造区求出，不能把蓝方坐标当成红方坐标。共同位和黄昏通道会为炮手预留，闲置队友先让路；采购工返回其他安全位置。白天绕行使用公开合法路径，夜间不为换炮绕到墙外。上述内容是团队策略，不改变官方价格、伤害、射程、动作额度、视野、昼夜长度或计分。

## 参数表

| 字段 | 默认 | 含义与调整影响 |
|---|---:|---|
| `name` | `user_phase_v1` | 本次参数方案名；微调时改成能辨识的名称。 |
| `enabled` | `true` | 本方案总开关；关闭用于对照旧策略，不表示机器人停止行动。 |
| `defense.full_defense_from_day` | `4` | 全员夜防起始日，范围 1–10；不限制白天职业活动。 |
| `defense.single_operator_three_rockets` | `true` | 尽量让一个操控者轮换三座火箭炮。关闭可对照原炮手分配机制。 |
| `defense.tower_loadout` | 三个 `rocket` | 三座武器类型；单人三炮策略开启时必须全部为 `rocket`。 |
| `upgrades.day_targets` | `[[3,3,3],[3,3,3],[3,3,3]]` | 第 1、2、3 天允许投资的三炮目标等级；默认不设置等日期再升级的门槛。按当前存活武器 `(y, x, id)` 升序对应；若要测试保守计划，应整段改成如 `[[1,1,1],[1,2,1],[2,2,2]]`，不能单独调低第二天而让目标下降。 |
| `upgrades.late_weapon_target` | `[3,3,3]` | 第四天及以后的目标。未完成的三级升级继续保留预算，紧急维修或基地救援可优先。 |
| `maintenance.from_day` | `4` | 启用后期维修准备的起始日；白天可备货，不独占所有工人。 |
| `maintenance.stock_target` | `2` | 维修物品储备目标，0–10；目标不是强制购买或无限预算。 |
| `maintenance.entry_fraction` | `0.55` | 城墙血量比例低到该值时考虑维修。提高会更早离开普通岗位。 |
| `maintenance.exit_fraction` | `0.85` | 修到该比例后退出维修，避免每轮往返切换。 |
| `maintenance.emergency_fraction` | `0.25` | 城墙紧急血量阈值。 |
| `maintenance.base_emergency_fraction` | `0.40` | 基地紧急血量阈值。 |
| `economy.dynamic_return` | `true` | 按当前公开路径和动作后的返岗成本计算白天截止；关闭后才使用固定回防门槛。 |
| `economy.return_margin_early` | `4` | 第1–3天入夜前安全余量。 |
| `economy.return_margin_late` | `6` | 第4天及以后入夜前安全余量。 |
| `economy.return_margin_damaged` | `8` | 基地或前六墙观察到损伤时的最小回防余量。 |
| `economy.return_day_index` | `55` | 动态路径不可判定时的保守回退门槛，以白天内 0–69 轮为刻度。 |
| `economy.upgrade_return_margin` | `3` | 升级采购往返所留的安全余量轮数。 |
| `economy.stone_batch` | `10` | 单次石头采集批量目标，1–100；不是修改背包容量。 |
| `economy.metal_batch` | `10` | 单次金银铜采集批量目标，1–100；需遵守实际矿量与容量。 |
| `economy.ore_max_distance` | `8` | 采矿候选距离上限，1–40；扩大可能增加赶路损耗。 |
| `nightwork.allow_after_clear` | `true` | 夜间已确认清场后允许工作；不能把当前无目标误当作未来绝无刷怪。 |
| `nightwork.quiet_rounds` | `3` | 清场观测建立基线后，连续多少次完整回合转换没有可见威胁/己方HP下降或单位消失才放行，范围1–20。重复请求与预览不增加计数。 |
| `navigation.enabled` | `true` | 启用队伍让路与持续停滞恢复；总开关 `enabled=false` 也会关闭该恢复策略。 |
| `navigation.stall_rounds` | `3` | 连续停滞达到多少轮后考虑恢复，范围 2–8；不能用同轮预测充当实际移动成功。 |
| `navigation.allow_wall_removal` | `true` | 允许在满足安全及连通条件时拆除己方非前六墙作为通路；关闭后仍可让路和绕行。 |
| `navigation.max_openings` | `2` | 恢复策略允许保留的拆墙通路数量上限，范围 0–6；0 禁用新增拆墙通路。 |
| `llm.task_prompt_prefix` | 任务背景前缀 | 可自行调整任务 Agent 的背景提醒；不能要求模型绕过官方格式、动作额度或沙盒权限。 |
| `llm.answer_instruction` | 答案输出提醒 | 可调整表达提示；任务题真实格式仍以题目和平台判题为准。 |
| `llm.include_recent_history` | `4` | 提供给任务 Agent 的最近操作摘要条数，范围 0–12；越大越有上下文但占用提示词空间。 |

### 夜间清场阶段

例如第113轮首次确认所有可见机器人清空，随后113→114、114→115、115→116三次完整观测无新威胁、己方HP下降或存活单位消失，第116轮即可恢复工作。白天不会被该窗口限制；第4夜起的全员防守也有这个清场例外。漏轮、回退、换局、新夜和观测缺失重新建立基线；出现机器人或公开HP损失时当轮撤销工作资格并回防。

放行后不永久占用三炮共同操控位，不保留已经没必要的维修返岗等待。工人优先继续已发出的采购承诺、使用已有修复物品/升级券，再做可达且有收益的采矿、卖矿和采购；缺墙时可提前备石头。开拓者可继续或领取公开任务、进行有依据的宝藏行程。夜间不会分配建墙/建炮，真实昼夜与每角色动作额度不变。采购和采矿规划可利用次日白天的时间预算，但新威胁会立即中断，预算不代表未来安全保证。

`decision_report.cleared_night`记录阶段、连续轮数、阻断原因和角色行动/等待原因，同步到`PlannerState.tasks.supervisor.cleared_night`供本地页面读取。当前官方接口没有逐次受击回执，只能比较完整己方角色、墙、武器和基地的公开HP及存活变化；**同轮回血可能抵消伤害**，因此该字段表示“未观察到HP下降”，不是“已证明没有受攻击”。`lastRoundRoleActionResults`只表示己方动作是否合法，不能当成受击信号。目标为我方或不明确的存活机器人在任何位置均阻断；明确攻对方且远离全部我方单位/建筑的机器人不会让已清场的我方一直待命。工作路线避开所有机器人周围4格（官方射程3格加一格移动余量，属于保守策略）；对方机器人靠近我方4格范围时当轮撤销工作资格。每轮重新规划，不能从本轮安全推断未来路线安全。

升级目标必须在 1–3 级内，按槽位随日期不下降；维修阈值必须满足 `emergency_fraction <= entry_fraction < exit_fraction`。未知字段、漏字段、非法类型和重复 JSON 键均会报错，不会悄悄忽略。

“前六墙”由当前己方基地和迎敌方向计算：最前面一排的中间四格，加上该排两个端角；中间四格中正对2×2基地宽度的两格属于最高优先级中央墙。左右阵营镜像，纵向迎敌时整体旋转；中心位置先按几何确定再过滤水面，不会因少一格陆地把侧墙错误提升成中央墙。与迎敌方向相反的完整六格边是后排，包含后侧两角。水面或地图外位置不会补成新的建造格。前六墙保护不以墙是否已经造好为条件，关闭导航或允许拆墙开关也不解除其保护。沿用的墙圈与迎敌方向仍属于 `DEVELOPMENT_RULES.md` D01 的本地几何假设，不能当作官方地图已对齐。

炮塔被毁或重建后，当前武器排序可能变化，三个等级数字不是永久绑定到某个武器 ID。等级上限限制新增升级采购；已携带的合法升级券仍允许使用，不会为了守住目标数字丢弃已有资源。

## 怎么修改和确认生效

1. 修改根目录 `strategy.json`，每次只调整一组相关参数，保留原文件。升级到带 `navigation` 的版本时先拉取完整新配置，再迁回自己的参数；旧配置缺少该节会明确报错，不能只拷贝旧文件覆盖。
2. 运行 `python tools/validate_strategy.py`。必须显示 `valid: true`；输出包含实际解析后的全部参数、文件路径和 SHA256。
3. 本地重启服务。服务启动时读取并缓存配置，运行中改文件不会热更新。可用 `COMPETITION_HW_STRATEGY_FILE` 指向另一份本机 JSON 做对照；显式指定的路径不存在会失败。
4. 公司平台需要重新构建并上传 `CoreGeek.tar.gz`，仅修改电脑上仓库的 JSON 不会改变已经上传的包。包内根目录包含同一份 `strategy.json`。
5. 记录包内源码 SHA、策略名称与策略文件 SHA256。配置加载身份中 `loaded: true, source: file` 表示读取了文件；`source: fallback/no_file` 表示文件缺失而使用内置默认，不应误当作已读取个人微调配置。

### LLM 和模拟器的可调边界

网页 `/strategy.html` 的“从运行服务读取的完整配置”通过 `/debug/strategy` 展示当前生效值、说明和分类。现在也可以直接在页面编辑 JSON 并点击“校验并保存策略”；服务端会拒绝缺字段、未知字段、错误类型和越界值，并原子写入根目录 `strategy.json`。保存后必须重启服务，策略模块才会全部重新加载。LLM 提示词只改变任务 Agent 如何整理题文、工具回执和近期摘要；它不会增加官方 LLM 次数、改变 `prompt`/`executeCmd`/`submitAnswer` 合同，也不能把本地答案当成官方成功。

模拟器参数不放进正式策略配置，以免参赛程序依赖本地扩展。调试接口支持显式选择 `seed`、`side`、`pressure`、`profile` 和 `map_layout`，例如 `/debug/scenario?seed=2029&side=defender&pressure=2&profile=observed-seven-days&map_layout=attack-map-observed-v1`。这些参数只改变本地压力实验；官方规则常量、动作字段、武器射程/价格、昼夜长度和计分不开放为策略调参项。

在仓库根目录完成修改与验证后，可用以下 PowerShell 命令制作自己的参数包。先提交配置，再从确定的提交构建；不能直接拿旧压缩包上传：

```powershell
python tools/validate_strategy.py
git add -- strategy.json
git commit -m "Tune user phase strategy parameters"
$strategySource = git rev-parse HEAD
git status --short
python tools/build_competition.py --repo . --ref $strategySource --output "dist/strategy-$strategySource/CoreGeek.tar.gz"
```

构建前工作树应干净；存在其他未提交文件时先核实和妥善保存，不要为打包盲目删除或全量暂存。上传此次输出目录中的 `CoreGeek.tar.gz`，同目录的 `.sha256` 和 `submission-manifest.json` 用于核对。输出路径包含源码 SHA，防止把不同参数版本的包混在一起。上述命令构建本地文件，不会自动向 GitHub 推送或替换平台已部署包。

对照测试同时看存活轮数、基地被攻破次数、真实游戏积分、实际升级完成回合、维修消耗、角色死亡和非法动作。赛事胜负、对战双方身份与游戏积分分开核实，不能只挑高分一场来决定参数。地图与怪物模拟假设没有因此成为官方认证。
