## 2. 三类边界

| 类别 | 是否允许修改 | 例子 |
|---|---|---|
| 官方明确的规则 | 不允许团队自行改定义；实现可以修正以符合规则 | 射程、冷却、坐标、动作字段、75 金币、超时 |
| 策略和工程选择 | 可优化，但动作与权限必须满足官方规则 | 造哪种炮、何时回防、A*、角色分工、任务算法、网页 |
| 本地实验假设 | 可配置、必须标注、不得作为官方结论 | 种子、波次数量公式、AI选敌、资源采样分布 |

**泛化是适应变化的输入，不是修改比赛规则。** 不同地图允许资源/任务/合法出生布局变化，
不能将任意尺寸地图、无限金币、无冷却或全图敌方视野混入官方符合性报告。
可以做这些压力实验，但必须单独标为非官方实验。

## 3. 不可自行改变的官方规则

以下为实施索引，细项仍以所引原文为准。未开发的功能也受这些规则约束。

### R01 — 运行与接口

依据：接口文档开头、§1、§2；任务书§八。

- 选手以 HTTP server 启动，端口由系统传入，监听 `0.0.0.0`；启动示例为 `bash run.sh port`。
- 保持官方字段名、大小写、类型及枚举；角色 ID 由判题器分配，响应使用收到的 ID。
- 敌我以当前请求的 `teamOur` / `teamEnemy` 为准，己方阵营读取 `teamOur.type`（`challenger` / `defender`）；我方既可能红方，也可能蓝方。不得按颜色、出生方位或角色 ID 前缀判定己方。任务点归属与机器人 `targetTeam` 均与当前己方阵营比较（接口§1.3、§1.5；用户澄清2026-09-14）。
- 输出 `roleCommandMap`；`prompt` 和 `executeCmd` 按功能使用。不得要求判题器提供本地新增字段。
- `controllerId` 为字符串，`targetPos` 是坐标数组，不可改成单个对象。
- 每角色每轮至多一条指令；攻击以武器 ID 为键，操控者每轮只能操控一座武器且不能另做一个动作。
- 动作全集是 `move/attack/sell/buy/build/remove/acceptTask/submitAnswer/summonTreasure/use/drop/collect`。
  当前审计只覆盖四种动作，并不意味着其余官方动作被禁止。
- 建立连接超过 10 秒、请求发出后 5 秒未响应属于超时；单队累计 5 次异常后停止调度，异常退出不重启。
- 字段缺失/未知动作等协议异常与碰撞、空落点等执行失败分开，不得把所有失败计成异常或全部吞成成功。

### R02 — 地图、视野与调度

依据：任务书§4.1–4.3、§4.5.4；接口§1.2–1.5。

- 地图 41×32，左下原点，x 向右、y 向上。基地 2×2，传入 pos 为左上角。
- 基地位置由系统指定。蓝色区域只造武器，黄色区域只造墙；“区域形状尚未核验”不等于任意空地可建造。
- 切比雪夫距离；角色八方向每轮移动一格，不能擅自限制成四方向或欧氏距离。
- 对角线上相邻的两障碍不额外阻挡斜向移动；单位、建筑、中立点、矿点等障碍按原文处理。
- 目标占用、同目标争抢、互换位置触发相应碰撞；不能用顺序移动伪装为官方同时结算。
- 己方视野距离 4、全队共享；敌方基地/墙全局可见，其他敌方单位受视野限制；机器人全图可见。
- 白天 70 轮、夜晚 60 轮，共 10 天/1300 轮；双方同时调度，无先后手。
- 武器攻击先于机器人移动，伤害回合末统一结算；眩晕法宝/范围炸弹等按原文先于机器人移动。

### R03 — 角色、建筑与资源

依据：任务书§4.1、§4.4、§4.5。

- 初始 75 金币、1 基地、1 开拓者、2 工人；初始没有武器和围墙。
- 开拓者 HP 200、背包40；工人 HP220、背包100；死亡后第二天白天开始20轮后可在基地复活，背包保留。
- 基地等级1/2/3血量1500/3000/4500；武器与墙血量1000/1500/2000。
- 武器三种类型合计同时最多3座，不是每种各3座。每座25金币，新造等级1；同位置已有武器会被覆盖。
- 墙耗石头1，拆墙不退材料；仅工人白天建造，工人可拆墙。
- 仅工人采矿，周围一格内，每轮一个矿石，遵守背包容量。
- 每矿采10次耗尽，下轮在建造区域之外随机刷新；同轮余量不足平分时，各采集工人仍各得一个。

依据：任务书§4.5.1、§4.5.4；接口§2.2。

### R06 — 交易、升级与物品

依据：任务书§4.4、§4.6；接口§1.1、§2。

- 小贩旁一格内卖矿；商店旁一格内购买；数量字段 `num` 默认1，可批量。金币/容量不足则失败。
- 矿价可受新闻影响，应读取当前收购清单，不能锁死成样例价格；任务用品列表也不是固定不变。
- 升级券1/2：武器100/150、墙20/30、基地100/150金币；限定对应等级提升，最高3级，成功后建筑满血。
- 升级券与修墙包需在目标建筑旁一格并指定目标；失败升级不消耗券。
- 修墙包/生命药剂10金币；眩晕法宝/范围炸弹100；召唤令小/中/大/BOSS为20/30/100/200。
- 眩晕5轮；炸弹3×3范围100伤害，仅作用双方机器人；使用距离无限制。召唤令每日最多10张，增加对方下一夜机器人。
- 商店物品不可退卖；任务物品的名称与拼写以当前官方接口为准，不自行“纠正” `AcientTablet` 等枚举。

### R07 — 任务、LLM 与沙盒

依据：任务书§4.6.2、§4.8、§五；接口§1.1、§1.3.2、§1.7、§2。

- 任务点分阵营，各队2个，任务点2占两格；仅开拓者在己方有效任务点范围内领取。
- 完成、超时、离开范围或开拓者死亡结束任务；结束后30轮刷新，任务总数有上限。
- 超时按之前最高通过率答案结算；部分奖励按通过率，不能以最后一次答案或全对/全错替代。
- 普通情况下每天最多3次LLM调用，首轮重置；自进化任务执行期间不受该额度限制且不计入日限。
- `executeCmd` 仅在任务期间可用，最多15秒；沙盒独立且无外网。不得在本机无约束执行替代官方沙盒后宣称合规。
- 保持 `lastCmdResult` 退出码、超时、判题错误和截断的接口语义，超过64KB的输出按文档处理。
- 宝藏仅开拓者召唤，需满足地点、时间和献祭物品；合法尝试消耗物品，即便未成功。
  非法动作不消耗；同轮双方都成功可各获奖励。物品集合必须不多不少，无顺序要求。

### R08 — 计分、终局与胜负

依据：任务书§六–八。

- 总分为任务分+击杀分+生存分。完整任务奖励含 `5×标准回合数/(完成回合−接取回合)`；
  部分完成为奖励×通过率；生存分为每天 `10×天数×基地存活系数`。
- 终局：双方异常数均达5、1300轮完成或双方基地均毁；本地“己方基地毁即停止”不是完整比赛终局。
- 上下半场换边；先后毁基地、同轮毁基地、双方存活等情形须依原文分别判断，不用“谁杀怪多谁赢”替代。
- 一局胜/平/负积3/1/0分；跨半场比较按原文处理。单队模拟得分不得冠名官方胜率。

## 5. 后续修改流程（团队工程规范）

1. 标注变更类别与受影响规则编号，例如“策略优化 / R03、R04；把三火箭改为混合配置”。
2. 只改实现与策略，不改官方原文；官方新版本更新单独提交来源差异，不混在调参中。
3. 规则修复给出独立可手算的输入/预期结果，先保留失败案例再修复。不能靠放宽审计通过测试。
4. 正式观测与模拟器私有状态分离；调试页面不直接改变比赛策略权限，假设只在本地配置中出现。
5. 验证分四层：协议结构、单条规则、模拟多图留出集、官方平台回放。报告只声明实际达到的层级。
6. 报告保存种子、阵营、压力、规则基线、代码提交或源码哈希、误差和未覆盖项；执行失败与异常分列。
7. `reports/VALIDATION.md` 是历史本地证据，不是官方认证；后续实现变化需新报告，不挪用旧结果。

本次只建立开发规范，不宣称已修复上述缺口。实现现状见 [DEMO.md](DEMO.md)。
